📑 목차

    네트워크

    사이트 연결 거부 오류(연결을 거부했습니다) 원인과 점검 순서

    크롬에서 '연결을 거부했습니다(ERR_CONNECTION_REFUSED)'가 뜨며 특정 사이트가 열리지 않는 경우

    크롬에 '사이트에 연결할 수 없음 — OOO에서 연결을 거부했습니다'와 ERR_CONNECTION_REFUSED가 뜨는 것은, 사이트 주소는 찾았지만 그 목적지에서 접속을 받지 않고 거절했다는 뜻입니다. 인터넷이 아예 끊긴 상황과는 다릅니다.

    이 오류에서 가장 먼저 가려야 할 것은 '접속이 정말 그 사이트로 가고 있는가'입니다. PC의 hosts 파일이나 프록시 설정이 접속 방향을 바꿔 놓았다면, 사이트도 인터넷도 정상인데 이 PC에서만 거부됩니다.

    특히 회사·매장·학교에서 관리하는 PC는 hosts 파일로 일부 사이트를 일부러 막아 두는 경우가 있습니다. 이때는 고장이 아니라 설정이므로, 고치기 전에 의도된 설정인지 먼저 확인하세요.

    이 가이드가 필요한 상황

    • 크롬에 '연결을 거부했습니다'와 ERR_CONNECTION_REFUSED가 표시된다.
    • 인터넷은 연결되어 있는데 특정 사이트(예: 구글)만 열리지 않는다.
    • 다른 기기나 휴대폰 데이터에서는 같은 사이트가 정상적으로 열린다.

    먼저 확인할 항목

    1. 오류 문구로 원인 방향 나누기 — 크롬 오류 이름마다 원인이 있는 위치가 다릅니다. 이 단계를 건너뛰면 DNS 문제를 방화벽 문제로 착각하는 식으로 엉뚱한 곳을 건드리게 됩니다. ① 크롬 화면 아래쪽 작은 글씨의 ERR_로 시작하는 문구를 확인하세요. ② ERR_CONNECTION_REFUSED는 주소는 찾았지만 접속이 거절된 경우이므로 이 가이드를 계속 따라가세요. ③ ERR_NAME_NOT_RESOLVED는 주소 자체를 못 찾는 DNS 문제, ERR_CONNECTION_TIMED_OUT은 응답이 없는 경로·방화벽 문제로 원인이 다릅니다.
    2. 다른 사이트·다른 기기로 교차 확인 — 이 PC만의 문제인지, 사이트나 네트워크 전체의 문제인지 가려야 hosts·프록시를 의심할 근거가 생깁니다. ① 같은 PC에서 naver.com처럼 평소 잘 열리던 다른 사이트를 열어 보세요. ② 휴대폰 데이터나 다른 PC에서 같은 사이트를 열어 보세요. ③ 다른 기기에서는 열리고 이 PC에서만 거부된다면 PC 안의 hosts·프록시·보안 프로그램을 확인할 차례입니다.
    3. ping과 nslookup 결과 비교(hosts 파일 의심) — nslookup은 DNS 서버에 직접 물어보고 hosts 파일을 보지 않습니다. 반대로 ping과 브라우저는 hosts 파일을 먼저 봅니다. 그래서 두 결과가 다르면 hosts 파일이 접속을 바꿔 놓았다는 증거가 됩니다. ① Windows 로고 키를 누르고 cmd를 입력해 명령 프롬프트를 실행하세요. ② nslookup 사이트주소를 실행해 나온 IP를 확인하세요(실제 서비스 IP가 나오면 DNS 자체는 정상입니다). ③ 이어서 ping -n 1 사이트주소를 실행해 맨 윗줄 대괄호 안에 표시되는 IP를 보세요(ping 응답이 막혀 있어도 IP는 표시됩니다). ④ ping이 127.0.0.1로 나오는데 nslookup은 다른 IP를 준다면 hosts 파일이 원인입니다.
    4. hosts 파일 확인과 정리 — hosts 파일에 도메인이 127.0.0.1로 적혀 있으면 그 도메인으로 가는 접속이 모두 PC 자신에게 돌아오고, PC 안에는 그 접속을 받는 프로그램이 없으니 거부됩니다. ① 시작 메뉴에서 메모장을 찾아 우클릭 → 관리자 권한으로 실행하세요. ② 파일 → 열기에서 C:\Windows\System32\drivers\etc 폴더로 이동하고, 파일 형식을 '모든 파일'로 바꿔 hosts를 여세요. ③ #로 시작하지 않는 줄 중 '127.0.0.1 사이트주소' 형태의 줄을 찾으세요. ④ 의도된 차단이 아님을 확인했다면, 먼저 hosts 파일을 복사해 백업해 둔 뒤 해당 줄만 지우거나 줄 맨 앞에 #을 붙이고 저장하세요. ⑤ 명령 프롬프트에서 ipconfig /flushdns를 실행하고 크롬을 다시 열어 확인하세요.
    5. 프록시 설정 확인 — 프록시 설정이 이미 없어진 주소를 가리키면 사이트와 상관없이 접속이 거부됩니다. 삭제한 프로그램의 설정이 남았거나 악성 프로그램이 바꿔 놓은 경우가 흔합니다. ① 설정 → 네트워크 및 인터넷 → 프록시를 여세요. ② '설정 스크립트 사용'과 '프록시 서버 사용'이 켜져 있는지, 켜져 있다면 주소가 무엇인지 보세요. 기억에 없는 주소(특히 127.0.0.1)라면 의심할 만합니다. ③ 회사·매장 PC가 아니라면 두 항목을 끄고 크롬을 다시 열어 보세요. ④ 참고로 명령 프롬프트의 netsh winhttp show proxy는 윈도우 서비스용 프록시를 보여 주므로, 크롬이 따르는 위 설정 화면과는 별개입니다.
    6. curl로 실제 접속 경로 확인 — curl.exe는 크롬이 따르는 윈도우 프록시 설정을 쓰지 않고 접속하면서, 어느 IP로 접속을 시도하는지 그대로 보여 줍니다. 프록시 문제와 hosts·방화벽 문제를 가르는 데 도움이 됩니다. ① 명령 프롬프트에서 curl.exe -I -v https://사이트주소 를 실행하세요. ② 'Trying' 뒤에 나오는 IP를 보세요. 127.0.0.1이면 hosts 파일 문제입니다. ③ 실제 서비스 IP로 시도했는데도 연결에 실패하면 방화벽·네트워크 정책이 거절하는 것이므로 네트워크 관리자 확인이 필요합니다. ④ curl은 성공하는데 크롬만 거부된다면 크롬이 따르는 프록시 설정이 원인일 가능성이 큽니다.

    원인을 더 정확히 나누는 방법

    ERR_CONNECTION_REFUSED·TIMED_OUT·NAME_NOT_RESOLVED의 차이

    REFUSED는 접속을 시도하자마자 '받지 않겠다'는 답이 돌아온 경우, TIMED_OUT은 한참 기다려도 아무 답이 없는 경우, NAME_NOT_RESOLVED는 사이트 주소 자체를 IP로 바꾸지 못한 경우입니다. REFUSED가 뜬다는 것은 최소한 주소를 찾고 연결을 시도하는 단계까지는 갔다는 뜻이라, DNS 서버를 바꾸는 것보다 hosts·프록시·방화벽 쪽을 먼저 보는 편이 맞습니다.

    nslookup은 정상인데 ping은 127.0.0.1일 때

    nslookup은 DNS 서버만 조회하고, 브라우저와 ping은 윈도우의 이름 해석 순서에 따라 hosts 파일을 DNS보다 먼저 확인합니다. 그래서 hosts에 해당 도메인이 있으면 DNS는 정상이어도 이 PC에서만 다른 곳으로 연결됩니다. 두 명령의 결과를 나란히 비교하는 것이 가장 빠른 구분법입니다.

    회사·매장 관리형 PC의 hosts 파일

    관리되는 PC의 hosts 파일에는 결제·내부 시스템 접속용 고정 주소와 차단 목록이 함께 들어 있는 경우가 있습니다. 파일을 통째로 비우거나 정리하면 업무 프로그램이나 결제가 멈출 수 있으니, 필요한 줄만 관리자 확인 후 수정하세요. 관리 프로그램이 파일을 자동으로 되돌리는 경우도 있습니다.

    프록시가 원인인지 가르는 법

    hosts는 정상이고(ping이 실제 IP) 프록시가 켜져 있으며 curl은 되는데 크롬만 거부된다면 프록시를 의심하세요. 다만 프록시를 거쳐야만 외부로 나갈 수 있는 망에서는 curl도 실패할 수 있으므로, 그런 환경이라면 프록시를 끄지 말고 올바른 프록시 주소를 IT 담당자에게 확인하세요.

    확인 결과에 따른 다음 단계

    • ping이 127.0.0.1로 나올 때 — hosts 파일이 원인입니다. 의도된 차단인지 확인한 뒤 해당 줄만 정리하고 ipconfig /flushdns를 실행하세요.
    • hosts는 정상이고 알 수 없는 프록시가 켜져 있을 때 — 프록시를 끄고 다시 확인하세요. 회사 PC라면 IT 담당자에게 올바른 프록시 주소를 확인하세요.
    • 실제 IP로 시도하는데 curl도 거절될 때 — PC 설정이 아니라 방화벽·네트워크 정책일 가능성이 큽니다. 같은 네트워크의 다른 PC와 비교해 보고 관리자에게 문의하세요.
    • hosts 줄을 지워도 다시 생길 때 — 관리 프로그램이 정책에 따라 되돌리는 것이거나 악성 프로그램일 수 있습니다. 관리되는 PC라면 담당자에게 정책을 확인하고, 개인 PC라면 백신으로 검사하세요.

    피해야 할 실수

    • nslookup 결과가 정상이라는 이유로 hosts 파일까지 정상이라고 판단하는 것(nslookup은 hosts를 보지 않음)
    • 관리되는 PC의 hosts 파일을 통째로 비우거나 정리해 업무용 주소까지 지우는 것
    • 원인을 확인하지 않고 방화벽을 끄거나 크롬부터 재설치하는 것

    자주 묻는 질문

    • ERR_CONNECTION_REFUSED와 ERR_CONNECTION_TIMED_OUT은 뭐가 다른가요? REFUSED는 접속 시도에 곧바로 거절 응답이 온 경우이고, TIMED_OUT은 한참 기다려도 응답이 없는 경우입니다. 거절은 hosts·프록시·방화벽 규칙처럼 분명한 설정에서, 무응답은 경로 단절이나 패킷을 버리는 방화벽에서 흔히 나옵니다.
    • 크롬에서는 안 되는데 엣지에서는 열려요. hosts 파일과 윈도우 프록시 설정은 두 브라우저가 함께 쓰므로, 한쪽만 안 된다면 크롬 확장 프로그램이나 크롬 자체 설정을 먼저 보세요. 시크릿 창에서 열어 보면 확장 프로그램의 영향을 구분할 수 있습니다.
    • hosts 파일을 수정해도 되나요? 수정 자체는 안전하게 할 수 있지만, 먼저 파일을 복사해 백업하고 필요한 줄만 고치세요. 특히 회사·매장 PC는 업무용 주소가 들어 있을 수 있어 관리자 확인이 먼저입니다.
    • hosts의 줄을 지웠는데 다시 생겨요. 보안·관리 프로그램이 정책에 따라 파일을 복원하거나 악성 프로그램이 다시 쓰는 경우입니다. 관리되는 PC라면 담당자에게 정책을 확인하고, 개인 PC라면 백신으로 검사하세요.
