에러 코드 상세

0x800F0983 · CBS 매니페스트 손상 오류

누적 업데이트 설치 중 CBS 매니페스트 손상으로 설치가 롤백될 때 나타나는 코드입니다.

이 코드를 어떻게 해석해야 하나요?

누적 업데이트 설치 도중 구성 요소 기반 서비스(CBS) 매니페스트가 손상되었거나 일치하지 않을 때 나타나는 코드로, 설치가 진행되다 특정 지점에서 롤백되는 증상으로 이어집니다. 2026년 8월 패치 이후 신고가 늘었습니다.

먼저 기록할 내용: 0x800F0983가 발생한 시각, 직전에 실행한 작업, 최근 설치한 드라이버·업데이트, 재부팅 뒤 같은 코드가 반복되는지를 적어 두세요.

가능성 높은 원인

  • 구성 요소 저장소(WinSxS)의 매니페스트 정보가 손상되었거나 이전 업데이트와 충돌하는 경우
  • 이전 업데이트가 중간에 실패하거나 강제 종료되어 잔여 파일이 남아있는 경우
  • 디스크 오류로 업데이트 패키지 파일 일부가 손상된 경우
  • 타사 최적화 프로그램이 시스템 파일을 임의로 수정하거나 삭제한 경우
  • 장기간 업데이트를 미뤄 여러 버전 차이가 누적된 경우

첫 점검 항목

  1. DISM /Online /Cleanup-Image /ScanHealth로 손상 여부 확인 — 되돌리기 쉬운 항목부터 확인해 위험 없이 범위를 줄입니다.
  2. DISM /Online /Cleanup-Image /RestoreHealth로 복구한 뒤 sfc /scannow 실행 — 첫 확인 결과와 비교해 손상 여부를 좁힙니다.
  3. Windows Update 서비스 중지 후 SoftwareDistribution·catroot2 폴더 초기화 — 이전 단계에서 해결되지 않을 때 캐시 문제를 배제합니다.
  4. 업데이트 어시스턴트나 미디어 생성 도구로 수동 설치 시도 — 복구로도 해결되지 않을 때 다음 단계로 진행합니다.
  5. CBS 로그(%windir%\\Logs\\CBS\\CBS.log) 확인 — 앞선 점검으로도 해결되지 않을 때 구체적으로 손상된 구성 요소를 특정합니다.

확인 결과에 따른 다음 단계

  • ScanHealth·RestoreHealth 복구로 해결될 때 — 재발 여부만 지켜보면 됩니다.
  • 캐시 폴더 초기화로 해결될 때 — 재발 여부만 지켜보면 됩니다.
  • 수동 설치로도 해결되지 않을 때 — CBS.log에서 손상된 구성 요소를 특정한 뒤 다음 단계를 판단하세요.

데이터와 시스템을 보호하는 주의사항

레지스트리 정리 도구를 쓰거나 시스템 폴더 권한을 바꾸기 전에, 저장 공간과 네트워크, 서비스 상태부터 점검하는 것이 우선입니다.

앞 단계로 해결되지 않을 때

오류가 반복된다면 Windows Update 기록과 DISM·SFC 실행 결과를 남겨두고, 사용 중인 설치 미디어 버전이 현재 Windows와 일치하는지 확인하세요.

복구, 초기화, 드라이버 제거처럼 되돌리기 어려운 작업 전에는 중요한 파일을 다른 물리 저장장치나 신뢰할 수 있는 백업 위치에 보관하세요.

자주 묻는 질문

  • 업데이트를 계속 재시도해도 괜찮은가요? 이 문제(0x800F0983)로 반복 실패한다면 무한정 재시도하기보다 DISM 복구와 업데이트 캐시 초기화를 먼저 하는 것이 시간을 아낄 수 있습니다.
  • 2026년 8월 패치와 관련이 있나요? 네, 2026년 8월 누적 업데이트(KB5121003 계열) 설치 이후 이 오류 신고가 늘었습니다. 구성 요소 저장소 손상이 주요 원인으로 지목되고 있습니다.
  • CBS.log는 어디서 확인하나요? %windir%\Logs\CBS\CBS.log 경로에서 텍스트 편집기로 열 수 있습니다. 오류가 발생한 시각 근처를 검색하면 어떤 구성 요소가 손상됐는지 구체적으로 확인할 수 있습니다.
