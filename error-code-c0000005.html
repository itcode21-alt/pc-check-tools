에러 코드 상세

0xc0000005 · 액세스 위반 오류

프로그램이 접근 권한이 없는 메모리 영역에 접근을 시도했을 때 나타나는 오류입니다. 프로그램 버그, 손상된 파일, 메모리 문제, 보안 소프트웨어 충돌 등 다양한 원인이 있습니다.

이 코드를 어떻게 해석해야 하나요?

업데이트 과정에서 나오는 이런 코드는 네트워크, 캐시, 구성 요소 저장소, 디스크 공간, 서비스 상태 중 어디서 작업이 끊겼는지 보여줍니다. 언제 반복되는지, 이벤트 로그의 세부 코드는 무엇인지 함께 확인하면 원인을 좁힐 수 있습니다.

먼저 기록할 내용: 0xc0000005가 발생한 시각, 직전에 실행한 작업, 최근 설치한 드라이버·업데이트, 재부팅 뒤 같은 코드가 반복되는지를 적어 두세요.

가능성 높은 원인

  • 프로그램 자체의 메모리 접근 버그
  • 램 모듈이 불안정하거나 손상된 경우
  • 보안 소프트웨어가 프로그램의 메모리 접근을 잘못 차단하는 경우
  • 프로그램 설치 파일이나 실행 파일이 손상된 경우
  • 다른 프로그램과의 DLL 충돌

첫 점검 항목

  1. 메모리 진단 도구로 램 상태를 점검하세요.
  2. 먼저 차단·격리 기록과 허용 목록을 확인하세요. 꼭 필요할 때만 보호 기능을 짧게 중지해 비교하고, 테스트 직후 다시 켜세요.
  3. 프로그램을 완전히 제거한 뒤 최신 버전으로 재설치하세요.
  4. 다른 프로그램을 모두 종료한 상태에서 다시 실행해 DLL 충돌 여부를 확인하세요.
  5. 윈도우와 해당 프로그램을 모두 최신 버전으로 업데이트하세요.

확인 결과에 따른 다음 단계

  • 메모리 진단에서 오류가 발견될 때 — 램 모듈을 하나씩 장착해가며 어떤 모듈이 문제인지 확인하세요.
  • 재설치로 해결될 때 — 재발 여부만 지켜보면 됩니다.
  • 특정 프로그램에서만 반복될 때 — 그 프로그램의 버그일 가능성이 크므로 제조사에 문의하거나 업데이트를 기다리세요.

데이터와 시스템을 보호하는 주의사항

시스템 폴더 권한을 손대거나 레지스트리 정리 프로그램을 실행하기보다는, 디스크 여유 공간과 네트워크 연결, 관련 서비스 상태를 먼저 확인하세요.

앞 단계로 해결되지 않을 때

같은 코드가 반복되면 Windows Update 기록과 DISM·SFC 결과를 저장하고 설치 미디어의 버전이 현재 Windows와 맞는지 확인하세요.

시스템 복구나 초기화, 드라이버 삭제처럼 원상복구가 힘든 작업을 시작하기 전에, 중요한 파일은 미리 외장 저장장치나 별도 위치에 백업해 두세요.

관련 증상 가이드 확인하기

같은 증상과 연결된 다른 오류 코드

  • 오류 1603 · 설치 중 치명적 오류가 발생했습니다 (오류 1603)
  • 오류 1618 · 다른 설치가 진행 중입니다 (오류 1618)
  • 오류 2503 · 이 설치 패키지를 열 수 없습니다 (오류 2503)
  • 오류 2502 · 이 설치 패키지를 열 수 없습니다 (오류 2502)

공식 참고자료

Microsoft Learn: Access Violation C0000005

자주 묻는 질문

  • 앱이 실행되지 않으면 무조건 재설치해야 하나요? 이 문제(0xc0000005)는 재설치보다 런타임 구성 요소(비주얼 C++ 등) 문제인 경우가 많아, 재설치 전에 필수 구성 요소부터 점검하는 것이 좋습니다.
  • 바이러스 때문에 실행이 차단된 걸 수도 있나요? 백신이 오탐으로 실행 파일을 격리했을 수 있으므로, 백신의 격리소·검역소 목록을 확인하는 것도 방법입니다.
  • DLL 충돌은 어떻게 확인하나요? 다른 프로그램을 모두 종료한 상태에서 재현되는지 비교하거나, Process Explorer 같은 도구로 로드된 DLL 목록을 확인해보세요.
