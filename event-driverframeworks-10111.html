DriverFrameworks-UserMode 10111 장치 오프라인 점검

사용자 모드 드라이버 충돌로 특정 장치가 오프라인 상태가 되었고 Windows가 장치를 다시 시작하려 했다는 기록입니다. 일반 탭의 장치 이름과 XML의 InstanceId·RestartCount를 이용하면 점검 대상을 구체적으로 찾을 수 있습니다.

10111은 사용자 모드 드라이버 충돌로 특정 장치가 오프라인이 되었고 Windows가 장치를 다시 시작하려 했다는 기록입니다. 일반 탭의 장치 이름과 XML의 InstanceId·RestartCount가 가장 중요한 단서입니다.

헤드셋·웹캠·키보드·마우스처럼 HID나 오디오 장치에서 자주 체감되지만, 장치 종류에 따라 원인이 달라집니다. 장치와 포트·케이블·드라이버를 차례로 분리해 확인하세요.

발생 조건

  • 특정 장치가 장치 관리자에서 사라짐
  • 헤드셋·웹캠·키보드·마우스·USB 장치가 끊김
  • 10110 직후 같은 장치가 반복해서 오프라인이 됨

가능성 높은 원인

  • 해당 장치의 UMDF 드라이버 또는 제조사 유틸리티 충돌
  • USB·블루투스 전원 관리와 절전 복귀 문제
  • 케이블·허브·포트 접촉 불량
  • 장치 펌웨어와 Windows 빌드의 호환성 문제

점검 순서

  1. 이벤트 XML의 FriendlyName·InstanceId·RestartCount를 기록해 장치를 특정 — 되돌리기 쉬운 항목부터 확인해 위험 없이 범위를 줄입니다.
  2. 10110과 발생 시각을 맞춰 UMDF 호스트 오류의 선후 관계 확인 — 첫 확인 결과와 비교해 원인 후보를 좁힙니다.
  3. 장치를 다른 포트·케이블·PC에 연결해 본체와 주변 환경을 분리 — 앞 단계에서 해결되지 않을 때 다음 원인을 검증합니다.
  4. 장치 제조사 드라이버·펌웨어와 칩셋 드라이버를 확인 — 앞 단계에서 해결되지 않을 때 다음 원인을 검증합니다.
  5. 전원 관리에서 장치 끄기 옵션을 비교하고 재현이 계속되면 장치 교체 테스트 — 앞 단계에서 해결되지 않을 때 다음 원인을 검증합니다.
주의사항

장치가 한 번 재연결되고 기능이 정상이라면 즉시 교체할 필요는 없습니다. RestartCount와 실제 끊김 반복을 함께 보세요.

InstanceId에는 장치 식별 정보가 포함될 수 있으므로 공유할 때는 일부를 가리고 전달하세요.

자주 묻는 질문

  • 10111과 10110은 어떻게 다른가요? 10110은 UMDF 호스트 프로세스 문제를, 10111은 그 결과 오프라인이 된 장치와 재시작 시도를 보여줍니다. 두 이벤트를 한 쌍으로 보면 장치를 찾기 쉽습니다.
  • 재부팅 후 장치가 다시 작동하면 무시해도 되나요? 단발성이라면 관찰할 수 있지만, RestartCount가 늘거나 같은 장치가 반복해서 끊기면 드라이버·펌웨어·전원 관리를 점검하세요.
