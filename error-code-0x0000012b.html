📑 목차

에러 코드 상세

0x0000012B · FAULTY_HARDWARE_CORRUPTED_PAGE

메모리에서 단일 비트 오류가 확인되었을 때 나타나며, RAM 이상을 강하게 시사합니다.

이 코드를 어떻게 해석해야 하나요?

오류 코드 자체가 고장난 부품을 확정 짓는 것은 아니며, 발생 시점과 함께 원인 후보를 좁히는 단서로 활용해야 합니다. 최근 변경 사항, 반복되는 조건, 안전 모드에서의 재현 여부를 함께 기록해두세요.

먼저 기록할 내용: 0x0000012B가 발생한 시각, 직전에 실행한 작업, 최근 설치한 드라이버·업데이트, 재부팅 뒤 같은 코드가 반복되는지를 적어 두세요.

이 코드가 가리키는 것

단일 비트 오류는 데이터의 비트 하나가 뒤집힌 상태를 말합니다. 서버용 ECC 메모리는 이런 오류를 스스로 정정하지만, 일반 PC의 메모리는 정정하지 못하고 이 코드로 이어집니다. 따라서 이 코드는 메모리 점검을 최우선으로 두는 것이 맞습니다. 드라이버 재설치로 해결되는 경우는 드뭅니다.

첫 점검 항목

  1. 메모리 한 개씩 교차 시험 — 메모리를 한 개만 장착해 며칠 사용하고, 재현되면 다른 한 개로 교체해 같은 시험을 반복합니다. 특정 한 개에서만 나오면 그 메모리가 원인입니다.
  2. MemTest86으로 정밀 검사 — Windows 메모리 진단은 짧은 검사라 단일 비트 오류를 놓칠 수 있습니다. MemTest86을 USB로 부팅해 최소 한 번의 전체 패스를 완주시키고, 가능하면 밤새 여러 회차 돌립니다.
  3. XMP·EXPO 해제 후 재검사 — 메모리 프로파일을 끄고 기본 속도에서 다시 검사합니다. 기본 속도에서 오류가 사라지면 메모리 불량이 아니라 설정 안정성 문제일 수 있습니다.
  4. 슬롯과 접점 상태 확인 — 메모리를 빼서 금색 접점에 이물이나 변색이 없는지 보고, 슬롯 걸쇠가 양쪽 모두 완전히 잠기도록 다시 장착합니다. 슬롯을 바꿔 꽂아 슬롯 불량 여부도 함께 구분하세요.

확인 결과에 따른 다음 단계

  • 메모리를 하나만 장착했을 때 재현되지 않을 때 — 문제가 있는 모듈을 특정해 교체하세요.
  • MemTest86에서 오류가 발견될 때 — 데이터를 먼저 백업한 뒤 해당 모듈을 교체하세요.
  • XMP·EXPO 해제 후 정상일 때 — 오버클럭을 다시 적용하지 말고 기본 속도를 유지하세요.

데이터와 시스템을 보호하는 주의사항

원인이 확인되지 않은 상태에서 초기화, 레지스트리 수정, 시스템 파일 수동 교체를 먼저 진행하지 마세요.

앞 단계로 해결되지 않을 때

반복되는 코드가 같다면 이벤트 로그와 장치 상태를 남겨두세요. 코드가 매번 다르다면 메모리·전원·온도 등 시스템 전체 안정성부터 확인하는 것이 순서입니다.

되돌리기 어려운 조치(복구, 초기화, 드라이버 제거 등)에 들어가기 전에는 반드시 중요 데이터를 다른 저장장치로 옮겨 두는 것이 안전합니다.

자주 묻는 질문

  • 블루스크린 코드가 한 번 떴는데 계속 지켜봐야 하나요? 이 문제(0x0000012B)가 한 번만 발생했다면 즉시 부품을 교체하기보다 재현 여부와 최근 변경 사항을 먼저 기록해두는 것으로 충분합니다. 반복된다면 그때 하드웨어 점검 범위를 넓히세요.
  • 덤프 파일은 어디서 확인하나요? C:\Windows\Minidump 폴더에 저장되며, BlueScreenView 같은 도구로 열어 정지 코드와 관련 드라이버를 확인할 수 있습니다.
  • ECC 메모리로 바꾸면 이 문제가 해결되나요? ECC는 서버·워크스테이션 메인보드에서만 지원되는 경우가 많아, 일반 데스크톱에서는 사용할 수 없는 경우가 대부분입니다.
