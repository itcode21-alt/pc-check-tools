에러 코드 상세

0x80070005 · Access Denied

관리자 권한이 필요한 작업을 일반 권한으로 시도했거나, 보안 소프트웨어가 접근을 차단했을 때 나타나는 권한 오류입니다.

이 코드를 어떻게 해석해야 하나요?

업데이트·설치 코드는 파일 누락, 구성 요소 저장소, 서비스, 권한, 여유 공간 중 작업이 중단된 지점을 나타냅니다. 실패 비율과 업데이트 기록의 세부 코드를 함께 봐야 합니다.

먼저 기록할 내용: 0x80070005가 발생한 시각, 직전에 실행한 작업, 최근 설치한 드라이버·업데이트, 재부팅 뒤 같은 코드가 반복되는지를 적어 두세요.

가능성 높은 원인

  • 관리자 권한 없이 시스템 파일이나 설정에 접근하려 한 경우
  • 보안 소프트웨어(백신, 방화벽)가 해당 프로그램의 접근을 차단한 경우
  • 폴더나 파일의 소유권이 다른 계정으로 되어 있는 경우
  • 그룹 정책으로 특정 기능에 대한 접근이 제한된 경우
  • 사용자 계정 컨트롤(UAC) 설정이 지나치게 엄격한 경우

첫 점검 항목

  1. 해당 프로그램이나 명령 프롬프트를 마우스 우클릭 후 '관리자 권한으로 실행'으로 다시 시도하세요.
  2. 먼저 차단·격리 기록과 허용 목록을 확인하세요. 꼭 필요할 때만 보호 기능을 짧게 중지해 같은 작업을 비교하고, 테스트 직후 다시 켜세요.
  3. 문제되는 폴더나 파일을 우클릭 > 속성 > 보안 탭에서 현재 계정의 권한을 확인하고 필요시 소유권을 가져오세요.
  4. 회사나 학교 PC라면 그룹 정책으로 제한된 기능인지 관리자에게 확인하세요.
  5. UAC 설정을 기본값으로 되돌린 뒤 다시 시도해 보세요.

확인 결과에 따른 다음 단계

  • 관리자 권한으로 재실행해 해결될 때 — 재발 여부만 지켜보면 됩니다.
  • 보안 소프트웨어 예외 등록으로 해결될 때 — 등록한 예외 항목을 잊지 말고 기록해 두세요.
  • 소유권 변경이나 그룹 정책 확인으로도 해결되지 않을 때 — 해당 드라이브의 NTFS 압축 설정을 점검하세요.

실제 사용자 사례

위 점검 순서로도 해결되지 않았을 때, 다른 원인으로 해결된 사례입니다.

드라이브 압축 해제로 해결한 사례

마이크로소프트 스토어 앱 설치가 이 오류로 계속 실패했던 사례가 있습니다. 관리자 권한, 폴더 권한 부여 등 일반적인 방법으로는 해결되지 않았는데, 앱을 설치하려던 보조 드라이브에 걸려 있던 NTFS 압축(디스크 공간 절약) 기능을 해제한 뒤 정상적으로 설치됐습니다.

포인트: C 드라이브가 아닌 다른 드라이브에 앱이나 프로그램을 설치할 때 이 오류가 난다면, 그 드라이브에 압축 기능이 켜져 있지 않은지 확인해보세요.

데이터와 시스템을 보호하는 주의사항

저장 공간·네트워크·서비스 상태를 확인하는 것이 시스템 폴더 권한 변경이나 레지스트리 정리 도구 사용보다 먼저입니다.

앞 단계로 해결되지 않을 때

반복해서 같은 오류가 난다면 Windows Update 이력과 DISM·SFC 결과를 저장하고, 설치 미디어 버전이 지금 쓰는 Windows와 맞는지부터 확인하세요.

작업이 잘못됐을 때 되돌릴 수 없는 경우가 많으니, 복구나 초기화, 드라이버 제거에 앞서 중요 파일을 다른 물리 저장장치에 먼저 복사해 두세요.

공식 참고자료

Microsoft Learn: System Error Codes — ERROR_ACCESS_DENIED

자주 묻는 질문

  • 프린터를 재설치하면 바로 해결되나요? 이 문제(0x80070005)는 드라이버보다 서비스나 권한 문제인 경우가 많아, 재설치 전에 스풀러 서비스 상태부터 확인하는 것이 순서상 더 빠릅니다.
  • 프린터 스풀러 서비스를 재시작하면 도움이 되나요? 네, services.msc에서 Print Spooler 서비스를 재시작하면 멈춰있던 인쇄 대기열이 정리되며 문제가 해결되는 경우가 많습니다.
  • 이 오류가 특정 프로그램에서만 반복되면 무엇을 의심해야 하나요? 해당 프로그램의 설치 폴더 권한이나 백신의 예외 목록을 먼저 확인하세요. 다른 프로그램은 정상 동작한다면 시스템 전체 문제가 아니라 해당 프로그램에 국한된 권한 설정 문제일 가능성이 높습니다.
