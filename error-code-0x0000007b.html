에러 코드 상세

0x0000007B · INACCESSIBLE_BOOT_DEVICE

시작 중에 Windows가 시스템 파티션(부팅 장치)에 접근하지 못했을 때 나오는 코드입니다. 문서는 부팅 장치 오류, 시스템 파티션 변경, BIOS 설정 변경, 호환되지 않는 디스크 하드웨어를 원인으로 듭니다.

하드웨어를 교체하거나 BIOS 설정을 바꾼 직후에 특히 자주 발생합니다.

Windows 11 26H2에서는 이 오류가 아래와 같은 검은 화면으로 나타납니다. 다른 중지 코드와 달리 이 사례에서는 "오류 정보를 수집하고 있습니다"라는 문장과 진행률(%)이 없고 하단의 "중지 코드"만 표시되었습니다. 부팅 초기에 시스템 디스크에 접근하지 못해 멈춘 경우라, 재부팅 뒤 이벤트 뷰어에 BugCheck 기록이나 덤프 파일이 남지 않을 수 있습니다. 아래는 테스트용 가상 머신에서 가상 디스크 컨트롤러 드라이버를 부팅 시 사용하지 않도록 바꿔 일부러 일으킨 화면입니다.

이 코드를 어떻게 해석해야 하나요?

항상 시스템을 시작하는 중에 발생하는 오류입니다. Microsoft Learn은 원인으로 부팅 장치(보통 하드 디스크)를 초기화하지 못한 경우, 파일 시스템이 부팅 장치의 데이터를 인식하지 못한 경우, 시스템 파티션을 다시 나누거나 BIOS 구성을 바꾸거나 디스크 컨트롤러를 설치한 경우, 호환되지 않는 디스크 하드웨어, 저장장치 고장을 듭니다. 부팅이 안 되는 경우와 부팅이 되는 경우로 나누어 최근 하드웨어 변경 되돌리기, 컨트롤러 모드(예: AHCI) 되돌리기, UEFI·펌웨어 업데이트, 안전 모드 부팅, 디스크 검사, 바이러스 검사를 안내합니다.

가능성 높은 원인

  • 부팅 장치(보통 하드 디스크) 드라이버가 장치를 초기화하지 못한 경우
  • 파일 시스템이 부팅 장치의 데이터를 인식하지 못한 경우
  • 시스템 파티션을 다시 나누거나 BIOS 구성을 바꾸거나 디스크 컨트롤러를 설치한 경우
  • 호환되지 않는 디스크 하드웨어, 또는 일부 디스크 컨트롤러가 요구하는 별도 드라이버가 없는 경우
  • 저장장치가 고장 나 Windows의 요청에 응답하지 못하는 경우

첫 점검 항목

  1. 공식 문서가 알려 주는 것: 최근에 추가한 하드웨어, 특히 하드 디스크나 컨트롤러를 빼고 오류가 사라지는지 보세요. 디스크 펌웨어가 Windows 버전과 호환되지 않을 수 있어 제조사에 업데이트를 문의하라고 안내합니다.
  2. 공식 문서가 알려 주는 것: UEFI(BIOS)에서 컨트롤러 모드를 레거시에서 AHCI로 바꾸는 등 최근 설정을 바꿨다면 되돌리세요.
  3. 공식 문서가 알려 주는 것: 저장장치 드라이버, 컨트롤러, 기타 저장장치 어댑터가 설치된 Windows 버전과 호환되는지 확인하고, 시스템 UEFI(BIOS)와 저장장치 컨트롤러 펌웨어 업데이트가 있는지 확인하세요.
  4. 공식 문서가 알려 주는 것: Windows가 부팅된다면 안전 모드로 부팅했다가 다시 정상 부팅해 보고, 디스크 검사(속성 → 도구 → 지금 확인)와 바이러스 검사(마스터 부트 레코드 포함)를 하세요.
  5. 문서 외 일반 점검: 저장장치와 메인보드를 잇는 케이블(또는 M.2 슬롯 장착 상태)을 다시 꽂아 보세요.
  6. 문서 외 일반 점검: 설치 미디어로 복구 환경에 들어가 bootrec /fixmbr, bootrec /fixboot로 부트 정보를 복구해 보세요. 이 명령은 실제 Windows에서 실행해 보지 못했습니다.

확인 결과에 따른 다음 단계

  • 최근 컨트롤러 모드나 BIOS 설정을 바꾼 뒤부터일 때 — 바꾸기 전 설정으로 되돌려 부팅되는지 확인하세요. 컨트롤러 모드를 AHCI로 바꾼 뒤 부팅이 안 되는 경우가 문서에도 언급됩니다.
  • 새 하드 디스크나 컨트롤러를 설치한 뒤부터일 때 — 추가한 장치를 빼고 부팅해 보세요. 빼서 해결되면 장치 펌웨어가 Windows와 호환되는지, IRQ나 I/O 포트 충돌이 있는지 제조사에 확인하세요.
  • 안전 모드로는 부팅될 때 — 안전 모드가 저장장치 핵심 드라이버를 불러 주므로, 안전 모드에 들어갔다가 정상 재시작해 저장장치 드라이버가 제대로 로드되는지 확인하세요.

해결 사례 예시

위 점검 순서로도 해결되지 않았을 때 다른 원인으로 해결될 수 있는 예시입니다. 실제 제보를 그대로 옮긴 것이 아니라 일반적인 사례를 바탕으로 구성한 참고용 예시이며, 환경에 따라 결과가 다를 수 있습니다.

윈도우10 → 11 업그레이드 우회로 해결한 사례

새로 조립한 PC에 윈도우 11을 USB로 직접 설치했을 때 계속 이 오류가 발생했던 사례가 있습니다. 드라이버 재설치, 복구 명령어, BIOS 설정 변경까지 다양한 시도를 했지만 해결되지 않았는데, 결국 윈도우 10을 먼저 설치한 뒤 온라인으로 윈도우 11까지 업그레이드하는 방식으로 우회해서 해결했습니다.

포인트: 정확한 원인은 명확하지 않지만, USB로 최신 윈도우를 바로 설치하는 과정에서 특정 하드웨어 조합에 문제가 생길 수 있습니다.

바이오스(CMOS) 초기화로 해결한 사례

오버클럭 설정을 건드린 직후 이 오류가 발생한 사례도 있었는데, CMOS 배터리를 잠시 분리했다가 다시 끼워 바이오스 설정을 초기화하는 것으로 해결됐습니다.

포인트: 최근 오버클럭이나 BIOS 설정을 변경한 직후 이 오류가 나타났다면, 원인이 저장장치 자체보다 불안정해진 시스템 설정에 있을 수 있습니다.

데이터와 시스템을 보호하는 주의사항

SMART 경고, 읽기 실패, Disk 7·129·153 반복이 있으면 복구 명령보다 중요한 파일 백업을 먼저 진행하세요.

앞 단계로 해결되지 않을 때

백업 후 케이블·포트·M.2 슬롯을 교차하고 제조사 진단과 펌웨어를 확인한 뒤 파일 시스템 검사를 계획하세요.

작업이 잘못됐을 때 되돌릴 수 없는 경우가 많으니, 복구나 초기화, 드라이버 제거에 앞서 중요 파일을 다른 물리 저장장치에 먼저 복사해 두세요.

Microsoft Learn: Bug Check 0x7B INACCESSIBLE_BOOT_DEVICE

자주 묻는 질문

  • 이 코드가 나오면 데이터가 지워지나요? 이 코드 자체가 데이터 삭제를 뜻하지는 않습니다. 다만 문서가 안내하는 해결 방법 중에는 설치 미디어를 쓴 새로 설치(clean install)도 있으니, 그 방법을 쓰기 전에 중요한 파일을 먼저 백업하세요.
  • 부팅 자체가 안 되는데 무엇부터 하나요? Microsoft Learn은 최근 하드웨어 변경 되돌리기, 컨트롤러 모드 되돌리기, 저장장치 호환성 확인, UEFI·펌웨어 업데이트, 다른 PC에서 만든 설치 USB로 부팅하는 순서를 안내합니다. 부팅 메뉴 키와 BIOS 진입 키는 제조사마다 다릅니다.

최종 검토일: 2026-11-20

아래는 Gigabyte 메인보드 BIOS의 Settings → IO Ports → SATA Configuration 화면 예시입니다. SATA Mode 항목을 열면 AHCI와 RAID 두 가지가 선택지로 나오며(이 예시는 AHCI가 선택된 상태), 현재 Windows가 어느 모드로 설치되어 있는지 모르면 이 값을 바꾸지 마세요. 메뉴 이름과 위치는 제조사와 BIOS 버전마다 다릅니다.
