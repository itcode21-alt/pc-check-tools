에러 코드 상세

TiWorker.exe 디스크 100% · Windows 모듈 설치 관리자(TiWorker.exe)로 인한 디스크 사용률 100%

Windows 업데이트를 설치하거나 정리하는 TiWorker.exe 프로세스가 백그라운드에서 디스크 압축·정리 작업을 하면서 디스크 사용률이 100%에 가깝게 오래 유지되는 증상입니다.

이 코드를 어떻게 해석해야 하나요?

오류 코드는 원인 후보를 좁히는 단서일 뿐, 고장 부품을 확정하는 근거는 아닙니다. 최근에 무엇이 바뀌었는지, 어떤 조건에서 반복되는지, 안전 모드에서도 재현되는지를 함께 기록해두세요.

먼저 기록할 내용: TiWorker.exe 디스크 100%가 발생한 시각, 직전에 실행한 작업, 최근 설치한 드라이버·업데이트, 재부팅 뒤 같은 코드가 반복되는지를 적어 두세요.

가능성 높은 원인

  • 대규모 누적 업데이트 설치 후 정리 작업이 진행 중인 경우
  • 백그라운드 업데이트 정리 작업이 예상보다 오래 걸리는 경우
  • 디스크(특히 HDD)의 처리 속도가 느린 경우
  • Windows Update 서비스가 백그라운드에서 정리 작업을 여러 번 재시도하며 반복하는 경우

첫 점검 항목

  1. 디스크 사용량·진행 확인 — 작업 관리자 세부 정보 탭에서 TiWorker.exe의 디스크 사용량과 CPU 점유율을 확인하세요.
  2. 자연 완료 대기 — 일반적으로 몇 시간 내 자연히 끝나므로, 강제 종료보다 완료를 기다리는 것이 안전합니다.
  3. 디스크 정리 도구 실행 — 디스크 정리 도구에서 "시스템 파일 정리"를 선택해 이전 업데이트 파일을 정리하세요.
  4. 컴포넌트 저장소 정리 — 관리자 권한 명령 프롬프트에서 Dism /Online /Cleanup-Image /StartComponentCleanup을 실행해 오래된 업데이트 파일을 직접 정리하세요.
  5. 반복 시 시스템 파일 점검 — 며칠 이상 반복된다면 sfc /scannow와 DISM /Online /Cleanup-Image /RestoreHealth로 시스템 파일 상태를 점검하세요.

확인 결과에 따른 다음 단계

  • 몇 시간 내 자연히 끝날 때 — 정상 동작이므로 별도 조치가 필요 없습니다.
  • 디스크 정리·컴포넌트 정리 후에도 며칠씩 반복될 때 — Windows Update 자체의 손상을 의심하고 sfc·DISM 점검으로 넘어가세요.
  • sfc·DISM에서도 문제를 찾지 못했는데 반복될 때 — 디스크(특히 HDD) 자체의 처리 속도 저하나 배드섹터 가능성을 SMART로 확인하세요.

데이터와 시스템을 보호하는 주의사항

정확한 원인을 파악하기 전에 초기화나 레지스트리 수정, 시스템 파일 수동 교체부터 시도하지 않는 것이 좋습니다.

앞 단계로 해결되지 않을 때

반복되는 코드가 같다면 이벤트 로그와 장치 상태를 남겨두세요. 코드가 매번 다르다면 메모리·전원·온도 등 시스템 전체 안정성부터 확인하는 것이 순서입니다.

되돌리기 어려운 조치(복구, 초기화, 드라이버 제거 등)에 들어가기 전에는 반드시 중요 데이터를 다른 저장장치로 옮겨 두는 것이 안전합니다.

자주 묻는 질문

  • 디스크 사용률이 100%면 디스크를 교체해야 하나요? 이 문제(TiWorker.exe 디스크 100%)는 디스크 고장보다 백그라운드 서비스가 원인인 경우가 많아, 교체 전에 해당 프로세스가 자연히 끝나는지 먼저 지켜보는 것이 좋습니다.
  • 업데이트 도중 강제 종료해도 되나요? 강제 종료는 업데이트 파일 손상으로 이어질 수 있어 권장하지 않습니다. 정말 하루 이상 지속될 때만 안전 모드에서 원인을 점검하세요.
