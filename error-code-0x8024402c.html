에러 코드 상세

0x8024402C · WU_E_PT_WINHTTP_NAME_NOT_RESOLVED 서버 연결 실패

윈도우 업데이트 클라이언트가 마이크로소프트 업데이트 서버의 주소를 확인(DNS)하지 못했을 때 나타나는 오류입니다. 네트워크 연결 자체보다 이름 확인이나 프록시 설정이 원인인 경우가 많습니다.

이 코드를 어떻게 해석해야 하나요?

업데이트 관련 오류 코드는 네트워크, 캐시, 구성 요소 저장소, 디스크 공간, 서비스 상태 중 어느 단계에서 작업이 멈췄는지를 나타냅니다. 실패가 반복되는 시점과 이벤트 로그의 세부 코드를 같이 살펴보면 원인을 좁히기 수월합니다.

먼저 기록할 내용: 0x8024402C가 발생한 시각, 직전에 실행한 작업, 최근 설치한 드라이버·업데이트, 재부팅 뒤 같은 코드가 반복되는지를 적어 두세요.

가능성 높은 원인

  • DNS 서버가 응답하지 않거나 잘못된 DNS 주소가 설정된 경우
  • VPN이나 프록시 설정이 업데이트 서버 접속을 가로막는 경우
  • 회사/학교 네트워크의 방화벽이 업데이트 관련 포트를 차단하는 경우
  • 네트워크 어댑터 드라이버가 불안정해 간헐적으로 연결이 끊기는 경우
  • hosts 파일에 업데이트 서버 도메인이 잘못 등록된 경우

첫 점검 항목

  1. 다른 웹사이트는 정상 접속되는지 확인해 전체 네트워크 문제인지 좁혀보세요.
  2. 명령 프롬프트에서 ipconfig /flushdns로 DNS 캐시를 지운 뒤 다시 시도하세요.
  3. VPN이나 프록시를 사용 중이라면 임시로 해제하고 업데이트를 재시도하세요.
  4. 네트워크 어댑터 속성에서 DNS 서버를 8.8.8.8 같은 공용 DNS로 임시 변경해 재현 여부를 확인하세요.
  5. 회사망이라면 네트워크 관리자에게 업데이트 서버 도메인이 차단됐는지 확인을 요청하세요.

확인 결과에 따른 다음 단계

  • DNS 캐시 초기화만으로 해결될 때 — 재발 여부만 지켜보면 됩니다.
  • 공용 DNS로 변경해 해결될 때 — 재발 여부만 지켜보면 됩니다.
  • VPN·프록시 해제로도 해결되지 않을 때 — 회사망 방화벽의 업데이트 서버 차단 여부를 관리자에게 확인하세요.

데이터와 시스템을 보호하는 주의사항

레지스트리 정리 도구를 쓰거나 시스템 폴더 권한을 바꾸기 전에, 저장 공간과 네트워크, 서비스 상태부터 점검하는 것이 우선입니다.

앞 단계로 해결되지 않을 때

오류가 반복된다면 Windows Update 기록과 DISM·SFC 실행 결과를 남겨두고, 사용 중인 설치 미디어 버전이 현재 Windows와 일치하는지 확인하세요.

되돌리기 어려운 조치(복구, 초기화, 드라이버 제거 등)에 들어가기 전에는 반드시 중요 데이터를 다른 저장장치로 옮겨 두는 것이 안전합니다.

관련 증상 가이드 확인하기

같은 증상과 연결된 다른 오류 코드

  • 0x800F081F · 원본 파일을 찾을 수 없음
  • 0x80070422 · 필요한 서비스가 비활성화됨
  • 0x80070070 · 디스크 공간 부족
  • 0xC1900101 · 업데이트 드라이버 호환성 실패

자주 묻는 질문

  • 업데이트를 계속 재시도해도 괜찮은가요? 이 문제(0x8024402C)로 반복 실패한다면 무한정 재시도하기보다 업데이트 구성 요소 정리와 디스크 공간 확인을 먼저 하는 것이 시간을 아낄 수 있습니다.
  • 업데이트를 미루면 보안에 문제가 되나요? 보안 업데이트가 누락되면 취약점 노출 위험이 커지므로, 오류를 바로 해결하지 못했다면 최소한 원인 진단이라도 진행하는 것이 좋습니다.
  • hosts 파일은 어떻게 확인하나요? 메모장을 관리자 권한으로 실행해 C:\Windows\System32\drivers\etc\hosts 파일을 열어보세요. update.microsoft.com 같은 업데이트 관련 도메인이 임의로 등록되어 있다면 해당 줄을 삭제하세요.
