# 게임 출시·패치 당일 대응 절차

게임 출시일과 대형 패치 직후에는 오류 검색이 짧은 기간에 몰린다(2026년 8월 말 검은사막 페이지에 구글 3개월 노출의 대부분이 13일 동안 몰린 사례). 이 문서는 그 시기에 맞춰 정확한 내용을 먼저 올리기 위한 절차다. 일정은 `docs/game-watch.json`에서 관리한다.

## 원칙
- **출시 전에 빈 페이지를 만들지 않는다.** 실제 오류 문구가 없는 페이지는 내용이 얇아 애드센스·색인에 불리하다.
- **공식 공지에 나온 문구만 본문에 쓴다.** 커뮤니티 보고만 있는 내용은 페이지에 올리지 않고 `docs/game-drafts/게임-날짜.md`에 초안으로 남긴다. 초안은 사람이 확인한 뒤 반영한다.
- 기존 게임 페이지가 있으면 그 페이지를 고친다. 새 페이지는 루틴의 새 페이지 조건(공식 출처, 7일 2개 이하, 본문 2,500자 이상)을 그대로 따른다.
- `game-*.html`은 직접 고친다. `scripts/generate-game-pages.mjs`는 다시 돌리지 않는다(직접 고친 내용이 덮어써진다).

## 시기별 할 일
| 시기 | 할 일 |
|---|---|
| 출시 30~8일 전 | 일정이 바뀌지 않았는지 dateSource나 공식 사이트로 확인하고 `game-watch.json`만 갱신 |
| 출시 7~1일 전 | 기존 페이지가 있으면 출시 뒤 낡을 표현(예: '얼리 액세스')을 찾아 최종 보고에 적음. 공식 사이트에 사전 다운로드·권장 사양·점검 일정 공지가 있으면 기존 페이지에 출처와 함께 반영 |
| 출시 당일~3일 뒤 | 공식 공지·알려진 문제 페이지를 열어 오류 문구, 원인, 공식 해결 방법을 확인하고 기존 페이지에 반영. 페이지가 없는 게임은 새 페이지 조건을 만족하면 만들고, 아니면 '새 페이지 제안'으로 보고 |
| 출시 4~14일 뒤 | 공식 공지에서 해결됨으로 바뀐 문제를 페이지에 반영하고 항목을 `done`으로 옮김 |

## 페이지에 넣을 내용(공식 확인된 것만)
1. 화면에 나오는 오류 문구나 번호 그대로(검색어와 일치하도록)
2. 서버·점검 문제인지 PC 문제인지 구분하는 기준과 공식 점검 공지 링크
3. 공식 해결 방법과 출처 링크, 확인한 날짜
4. PC 쪽 원인일 때 이어 볼 사이트 내 가이드 링크(그래픽 드라이버, 메모리, 네트워크 등)

## 일정 추가 기준
- 국내 PC 이용자가 많을 것으로 보이는 온라인 게임(국내 퍼블리셔 서비스, PC방 순위 진입, 기존 인기작의 정식 출시·대형 확장팩)
- 날짜가 공식 발표나 발행일이 확인된 기사로 뒷받침될 것. 매체마다 날짜가 다르면 `dateConfidence`에 그대로 적는다
- 콘솔 전용, 싱글 플레이 위주 게임은 넣지 않는다

## 감시 루틴이 매 실행에서 따르는 순서
1. `docs/game-watch.json`을 읽고 오늘 날짜(한국 시간) 기준으로 각 항목이 위 표의 어느 시기인지 정한다. 해당하는 항목이 하나도 없고 `recurring` 점검에서도 변화가 없으면 **아무것도 바꾸지 않고 종료**한다.
2. 한 번 실행에 게임 1개만 다룬다. 여러 개가 겹치면 `priority`가 높은 것, 그다음 날짜가 가까운 것 순서로 고른다.
3. 공식 사이트·공지를 WebFetch로 연다. 막히면(EGRESS_BLOCKED 등) 최종 보고에 '차단(도메인)'을 적고 페이지는 고치지 않는다. 뉴스 기사만으로 오류 해결 방법을 쓰지 않는다.
4. 반영할 때는 해당 `game-*.html`을 직접 고치고, 실제로 내용을 바꾼 페이지만 `최종 검토일`과 JSON-LD `dateModified`를 오늘 날짜로 바꾼다. 날짜를 바꿨으면 `node scripts/generate-rss.mjs`를 실행한다. `scripts/generate-sitemap.mjs`와 `scripts/generate-game-pages.mjs`는 실행하지 않는다.
5. `games-data.js`·`data.js`는 건드리지 않는다(건드리면 캐시 토큰과 파생 파일을 전부 다시 만들어야 한다). 꼭 필요하면 고치지 말고 최종 보고에 제안으로 적는다.
6. `game-watch.json`의 `status`, `updated`, 확인한 내용을 갱신한다. 끝난 항목은 `done`으로 옮긴다.
7. `git add -A` 뒤 아래 검사를 모두 통과시킨다. 우회 옵션과 `--no-verify`는 쓰지 않는다.
   ```
   node scripts/check-asset-versions.mjs --staged
   node scripts/check-links.mjs
   node scripts/check-rss-freshness.mjs --staged
   node scripts/check-policy-link-coverage.mjs
   node scripts/check-content-quality.mjs --staged
   ```
8. 한국어 커밋 메시지로 커밋하고, `git fetch origin main` 뒤 원격이 앞서 있으면 `git merge origin/main --no-edit`로 합친 다음 `git push origin main`(거부되면 `git push origin HEAD:main`). `git push --force`, `git reset --hard`는 쓰지 않는다.
9. 최종 보고(한국어)에 적을 것: 다룬 게임과 시기, 외부 조사 결과(성공/차단 도메인), 바꾼 파일, 사람이 확인해야 할 초안(`docs/game-drafts/`)이나 새 페이지 제안, 새로 추가한 일정.

## 새 일정 찾기(주 1회, 월요일 실행에서만)
- 게임트릭스 메인 TOP 10을 열어 `recurring.baseline`과 비교한다. 사이트에 페이지가 없는 게임이 들어왔으면 `events`에 추가한다.
- 앞으로 60일 안의 국내 PC 온라인 게임 출시·정식 출시·대형 확장팩 일정을 검색해, 발행일이 최근 2개월 이내이고 날짜가 명시된 자료가 있을 때만 `events`에 추가한다. 추가만 한 실행에서는 페이지를 고치지 않는다.
