블루스크린 코드 해석기

블루스크린에 나온 중지 코드나 이벤트 뷰어의 BugCheck 문구를 붙여넣으면 코드의 뜻, 흔한 원인, 먼저 확인할 순서를 알려 줍니다. 0x로 시작하는 코드, 영문 코드 이름, 한글 키워드 모두 입력할 수 있고 입력 내용은 이 브라우저 안에서만 처리됩니다.

자주 보는 코드

중지 코드는 어디서 확인하나요?

  • 파란 화면 아래쪽: '중지 코드' 옆에 CRITICAL_PROCESS_DIED 같은 영문 이름이 표시됩니다. 최근 윈도우는 QR 코드 아래에 작게 나옵니다. 사진을 찍어 두면 재부팅 후에도 확인할 수 있습니다.
  • 이벤트 뷰어: eventvwr.msc → Windows 로그 → 시스템에서 원본이 BugCheck인 이벤트 1001을 찾으세요. 'The bugcheck was: 0x…' 문구를 통째로 붙여넣어도 됩니다. 괄호 안의 숫자는 매개변수라서 코드로 읽지 않고 걸러냅니다.
  • 화면을 못 봤을 때: 블루스크린이 뜨자마자 재부팅된다면 시스템 속성 → 고급 → 시작 및 복구에서 '자동으로 다시 시작'을 끄면 화면이 유지됩니다.
  • 덤프 파일이 있다면 블루스크린 덤프 분석기가 코드뿐 아니라 원인 드라이버까지 좁혀 줍니다.

코드 해석 결과, 이렇게 활용하세요

  • 코드는 증상의 이름이지 원인의 확정이 아닙니다. 같은 코드도 드라이버, 램, 저장장치 등 서로 다른 원인으로 생길 수 있어서 결과의 '먼저 확인할 순서'를 위에서부터 하나씩 확인하세요.
  • 한 번만 나타나고 다시 안 생긴다면 일시적인 충돌일 수 있습니다. 같은 코드가 반복되면 최근에 바꾼 드라이버·업데이트·하드웨어를 되돌려 보는 것이 가장 먼저입니다.
  • 코드가 매번 달라지면 특정 드라이버보다 램·전원·저장장치 같은 하드웨어 불안정을 먼저 의심해 볼 만합니다.
  • 부팅 자체가 안 되는 경우는 BIOS·부팅 가이드와 블루스크린 총정리를 함께 보세요.

이 해석기는 이 사이트에 정리된 정지 코드 해설을 찾아 보여 주는 도구이며, 해설이 없는 코드는 마이크로소프트 공식 참조로 안내합니다. 기준 시점: 2026-11-15.

해설이 준비된 정지 코드 전체

    자주 묻는 질문

    • 블루스크린 코드를 알면 원인을 바로 알 수 있나요? 코드는 문제가 생긴 영역을 알려 주지만 원인을 하나로 정하지는 않습니다. 예를 들어 드라이버 관련 코드라도 어느 드라이버인지는 덤프 파일이나 이벤트 로그를 봐야 압니다. 이 해석기의 점검 순서를 따라 확인하고 반복되면 덤프 분석기로 넘어가세요.
    • 코드가 0x로 시작하지 않고 영어 이름만 보여요. 정상입니다. 최근 윈도우는 화면에 코드 이름(예: CRITICAL_PROCESS_DIED)만 보여 줍니다. 그 이름을 그대로 입력하면 해당 코드를 찾습니다. 대소문자나 밑줄 유무는 신경 쓰지 않아도 됩니다.
    • 블루스크린이 났는데 코드를 못 봤어요. 어떻게 확인하죠? 이벤트 뷰어의 시스템 로그에서 BugCheck 이벤트를 찾으면 코드가 남아 있습니다. 로그가 없다면 다음 발생에 대비해 '자동으로 다시 시작'을 끄고 화면 사진을 찍어 두세요. 부팅 초기에 멈추는 코드는 로그가 남지 않을 수도 있습니다.
    • 한 번 나고 다시 안 나면 그냥 둬도 되나요? 한 번뿐이라면 일시적인 드라이버 충돌이나 전원 문제일 수 있어 우선 윈도우 업데이트와 드라이버 상태를 점검하고 지켜보면 됩니다. 며칠 안에 반복되거나 같은 코드가 다시 나오면 램 검사, 저장장치 상태 확인 같은 하드웨어 점검으로 넘어가세요.
    • 이 사이트에 없는 코드는 어떻게 해야 하나요? 해설이 없는 코드는 마이크로소프트 버그 체크 코드 참조에서 이름과 매개변수의 의미를 볼 수 있고, 덤프 파일이 있으면 덤프 분석기를 쓰세요. 반복되는데 원인을 못 찾겠다면 카카오톡 채널로 증상을 보내 주셔도 됩니다.
