에러 코드 상세

0x80072F8F · 보안 연결 실패·시스템 시간 오류

Microsoft 문서는 시계 설정이 어긋났거나 신뢰되지 않는 SSL 인증서 때문에 SSL 협상이 실패해 Windows Update에 연결하지 못할 때의 오류로 설명합니다.

0x80072F8F는 Windows Update 연결 중 SSL 협상 문제를 가리킵니다. Microsoft 문서는 원인을 시계 불일치와 신뢰되지 않는 SSL 인증서(WSUS·Configuration Manager를 SSL로 쓰는 환경)로 설명합니다.

이 코드를 어떻게 해석해야 하나요?

Windows 업데이트나 Microsoft Store가 보안 연결을 맺을 때 인증서를 검증하지 못하면 나타나는 오류입니다. 시스템 날짜와 시간이 실제와 다르거나, 프록시나 백신이 HTTPS 통신을 가로채 인증서가 바뀐 경우가 많습니다. 날짜와 시간을 자동으로 맞춘 뒤 다시 시도하는 것이 가장 빠른 확인 방법입니다.

가능성 높은 원인

  • PC의 날짜·시간 또는 시간대가 실제 시간과 크게 다른 경우
  • 인터넷 시간 동기화가 실패했거나 Windows Time 서비스가 중지된 경우
  • 관리되는 PC의 WSUS·프록시가 자체 인증서를 사용하지만 클라이언트가 인증서 체인을 신뢰하지 못하는 경우
  • 오래된 Windows에서 루트 인증서·TLS 구성 요소가 갱신되지 않은 경우
  • 보안 프로그램이나 프록시가 Windows Update·Microsoft Store의 HTTPS 연결을 가로채는 경우

첫 점검 항목

  1. 공식 문서가 알려 주는 것: 시계 설정이 맞지 않으면 SSL 협상이 실패합니다. 설정 > 시간 및 언어 > 날짜 및 시간에서 시간 자동 설정과 시간대를 확인하고 지금 동기화를 실행하세요. WindowsUpdate.log(C:\Windows\Logs\WindowsUpdate)는 항상 로컬 시간으로 기록되므로 시계가 맞는지 로그로도 확인할 수 있습니다.
  2. 공식 문서가 알려 주는 것: WSUS나 Configuration Manager를 SSL로 운영하며 자체 발급·서명 인증서를 쓰는 환경에서는 클라이언트가 인증서 체인을 신뢰하지 않으면 검사가 실패합니다. 회사·학교 PC라면 관리자에게 서버 인증서가 신뢰할 수 있는 루트 인증 기관에 설치되어 있는지 확인해 달라고 하세요. 인증서를 임의로 설치하거나 삭제하지 마세요.
  3. 공식 문서가 알려 주는 것: WindowsUpdate.log에서 'Send request failed, hr:0x80072f8f'나 'WinHttp: SendRequestToServerForFileInformation failed with 0x80072f8f' 항목이 sls.update.microsoft.com 요청과 함께 반복되는지 확인하세요.
  4. 문서 외 일반 점검: 다른 HTTPS 웹사이트가 정상으로 열리는지 확인하고, VPN이나 프록시를 쓰면 잠시 해제하고 같은 작업을 다시 시도하세요.
  5. 문서 외 일반 점검: 관리자 명령 프롬프트에서 w32tm /query /status로 시간 동기화 상태를 확인하고 필요하면 w32tm /resync를 실행하세요. Azure 가상 머신은 Microsoft 문서가 인플레이스 업그레이드를 해결 방법으로 안내합니다.

데이터와 시스템을 보호하는 주의사항

시스템 폴더 권한 변경이나 레지스트리 정리 도구 사용보다 저장 공간, 네트워크, 서비스 상태를 먼저 확인하세요.

앞 단계로 해결되지 않을 때

같은 코드가 반복되면 Windows Update 기록과 DISM·SFC 결과를 저장하고 설치 미디어의 버전이 현재 Windows와 맞는지 확인하세요.

복구, 초기화, 드라이버 제거처럼 되돌리기 어려운 작업 전에는 중요한 파일을 다른 물리 저장장치나 신뢰할 수 있는 백업 위치에 보관하세요.

자주 묻는 질문

  • 0x80072F8F는 시간 설정 문제인가요? Microsoft 문서는 시계 불일치를 대표 원인 중 하나로 들지만, 신뢰되지 않는 SSL 인증서(WSUS·Configuration Manager 환경)도 원인으로 설명합니다. 시간을 맞춰도 반복되면 인증서 쪽을 확인하세요.
  • 인증서를 직접 설치하면 되나요? 권하지 않습니다. 관리되는 PC에서는 관리자가 서버 인증서의 신뢰 구성을 확인해야 하고, 출처를 모르는 인증서를 설치하면 보안 위험이 생깁니다.
