사용자가 요청한 단계까지만 진행한다. PR은 요청이 있을 때만 만들고, 병합은 병합하라고 했을 때만 한다.

## 1. PR 만들기 ("PR 만들어줘")
1. `CLAUDE.md`의 푸시 전 점검 명령을 돌려 모두 통과하는지 확인한다.
2. 작업 브랜치에 푸시한다(`git fetch` 뒤 푸시, 가격 봇이 브랜치에 커밋을 올리므로 `--force-with-lease`에는 최신 원격 커밋을 쓴다).
3. `.github/pull_request_template.md`가 있으면 그 구조를 따른다. 본문에는 변경 내용, 검증한 것, **검증하지 못한 한계**를 적는다.
4. 만든 PR 링크를 알려 주고, 지켜볼지 묻는다.

## 2. 지켜보기 ("PR 지켜봐줘")
- `subscribe_pr_activity`로 구독하고 CI 결과를 확인한다. 실패하면 원인을 찾아 고친다(스킵·재실행으로 넘기지 않는다).
- 충돌(`mergeable_state: dirty`)이 나면 main을 병합해 풀고, `CLAUDE.md`의 캐시 토큰 규칙대로 토큰과 파생 파일을 맞춘다.

## 3. 병합 ("머지해줘")
1. 병합 직전에 PR의 `mergeable_state`와 최신 커밋의 CI를 다시 확인한다. 충돌이면 먼저 해결한다.
2. `merge_method: merge`로 병합하고 병합 SHA를 알린다.

## 4. 배포 확인 ("배포 확인해줘")
- 반영에 2~3분 걸리므로 URL 확인은 Monitor 반복으로 기다린다.
- 확인할 것: 새·수정 페이지가 200인지, 새 캐시 토큰이 라이브 HTML에 있는지, 사이트맵·색인 항목, 링크로 연결한 곳.
- 결과와 라이브 링크를 알리고, 직접 실행해 보지 못한 부분(Windows 스크립트 등)은 그대로 밝힌다.
