에러 코드 상세

오류 1603 · 설치 중 치명적 오류가 발생했습니다 (오류 1603 · 0x80070643)

MSI(Windows Installer) 설치가 치명적 오류로 롤백됐다는 코드입니다. 0x80070643으로 표시되는 경우와 같은 오류이며, Microsoft 문서의 네 가지 원인과 Windows Update에서 나올 때의 복구 파티션 점검을 함께 봅니다.

오류 1603은 Windows Installer(MSI) 설치가 치명적 오류로 롤백됐다는 코드입니다. 같은 오류가 Windows Update나 .NET Framework 설치 화면에서는 0x80070643(0x643 = 1603)으로 표시되기도 해서, 이 페이지에서 함께 다룹니다.

쉽게 말하면

숫자만 다른 같은 오류입니다. 1603은 설치 프로그램이 보여 주는 형태이고, 0x80070643은 같은 번호를 16진수로 적은 형태입니다(0x643 = 1603). 어느 쪽으로 보이든 아래 순서로 점검합니다.

이 코드를 어떻게 해석해야 하나요?

오류 1603과 0x80070643은 같은 오류 번호입니다(0x643은 10진수로 1603). Windows Installer가 설치 도중 치명적 오류를 만나 설치를 되돌렸다는 결과이고, Microsoft의 MSI 오류 1603 문서는 원인을 네 가지로 정리합니다: 이미 설치된 앱, 암호화된 설치 폴더, 대체 드라이브, SYSTEM 계정 권한 부족. 그래서 이 순서로 하나씩 확인합니다. Windows Update에서 0x80070643이 나올 때는 복구 환경(WinRE) 업데이트가 복구 파티션 공간 부족으로 실패하는 경우가 있는데, Microsoft의 KB5028997 문서는 이 경우를 다루지만 오류 코드를 적어 두지는 않았습니다. 이벤트 ID 4502와 reagentc /info로 먼저 그 경우인지 확인하세요.

가능성 높은 원인

  • 이미 설치된 앱을 다시 설치하려는 경우 — Microsoft 문서가 첫 번째로 꼽는 원인으로, 업그레이드 뒤 바로가기만 사라져 설치되지 않은 것처럼 보이는 경우도 포함됩니다
  • 설치할 폴더가 암호화되어 있는 경우
  • 설치할 폴더가 들어 있는 드라이브가 대체 드라이브(SUBST로 만든 드라이브)로 접근되는 경우
  • 설치 폴더에 SYSTEM 계정의 모든 권한(Full Control)이 없는 경우 — Windows Installer 서비스가 SYSTEM 계정으로 설치하기 때문입니다
  • Windows Update 중 0x80070643이 나올 때: 복구 환경(WinRE) 업데이트가 복구 파티션 공간 부족으로 실패하는 경우 — Microsoft는 KB5028997에서 일부 PC의 복구 파티션이 이 업데이트를 마치기에 작을 수 있다고 안내합니다(이 문서에는 오류 코드가 적혀 있지 않고, 해당 업데이트가 0x80070643으로 실패한다는 보고는 Microsoft Q&A 커뮤니티 글에서 확인됩니다)
  • 공식 문서에는 없지만 일반적으로 확인하는 경우: 설치 파일 손상, 보안 프로그램의 파일 쓰기 차단, .NET Framework 구성 요소 손상

첫 점검 항목

  1. 설정의 앱 목록(Windows 10은 시스템 > 앱 및 기능)에서 같은 앱이 이미 설치되어 있는지 검색하세요. 있다면 제거한 뒤 다시 설치합니다. 이 방법으로 설치가 되면 이미 설치된 앱과의 충돌이 원인이었습니다.
  2. 설치 경로를 암호화되지 않은 폴더(기본 설치 경로 등)로 바꿔 다시 설치하세요. 이 방법으로 설치가 되면 암호화된 폴더가 원인이었습니다.
  3. SUBST 명령으로 만든 대체 드라이브가 아니라 실제 드라이브에 설치하세요. 이 방법으로 설치가 되면 대체 드라이브가 원인이었습니다.
  4. 설치할 드라이브를 우클릭해 속성 > 보안 탭을 열고 SYSTEM 계정이 목록에 있고 모든 권한이 '허용'인지 확인하세요. 권한 변경은 시스템 보안에 영향을 주므로, 바꿔야 한다면 Microsoft 문서의 절차를 그대로 따르세요.
  5. Windows Update에서 이 코드가 나왔다면 설정 > Windows Update > 업데이트 기록에서 실패한 업데이트의 KB 번호를 적어 두세요. 이벤트 뷰어의 Windows 로그 > 시스템에서 같은 시각에 이벤트 ID 4502(Windows Recovery Environment servicing failed)가 있는지 보고, 관리자 명령 프롬프트에서 reagentc /info를 실행해 복구 환경(WinRE) 상태를 확인하세요. 확인만 하는 명령입니다.
  6. 설치 중인 것이 .NET Framework라면 Microsoft의 .NET Framework Repair Tool을 실행하고 재부팅한 뒤 다시 설치해 보세요. 이 방법으로 설치가 되면 .NET 구성 요소가 원인이었습니다.
  7. 공식 문서 외 일반 점검: 설치 파일을 공식 홈페이지에서 다시 받고, 우클릭 '관리자 권한으로 실행'으로 시도하세요. 보안 프로그램은 확인용으로만 잠시 끄고 바로 다시 켭니다.

확인 결과에 따른 다음 단계

  • 같은 앱이 이미 설치되어 있을 때 — 설정의 앱 목록에서 제거한 뒤 다시 설치하세요. 바로가기만 사라진 것일 수 있어 먼저 앱 이름으로 검색해 보세요(Microsoft 문서의 첫 번째 방법).
  • 설치 경로가 암호화된 폴더이거나 대체 드라이브일 때 — 암호화되지 않은 일반 폴더, SUBST가 아닌 실제 드라이브에 설치하세요.
  • SYSTEM 계정에 모든 권한이 없을 때 — Microsoft 문서의 절차(드라이브 속성 > 보안 > SYSTEM에 모든 권한 허용)를 따르되, 권한 변경은 시스템 보안에 영향을 주므로 백업 뒤에 진행하세요. 문서: Microsoft Learn: MSI installation error 1603
  • Windows Update 중 이벤트 ID 4502가 함께 보일 때 — 복구 파티션 크기 조정은 diskpart로 파티션을 줄이고 복구 파티션을 삭제·재생성하는 작업이라 데이터 손실 위험이 있습니다. 전체 백업 뒤 Microsoft 문서의 절차를 그대로 따르거나 전문가에게 맡기세요. 문서: KB5028997: Instructions to manually resize your partition to install the WinRE update
  • .NET Framework 설치 중이었을 때 — Microsoft의 .NET Framework Repair Tool을 실행하고 재부팅한 뒤 다시 설치하세요(공식 문서 외 일반 점검).

점검 전 주의

권한 변경이나 파티션 조정이 필요한 조치는 전체 백업 없이 시도하지 마세요. 원인이 확인되기 전에는 시스템 폴더 권한이나 복구 파티션을 건드리지 않는 것이 안전합니다.

자주 묻는 질문

  • 오류 1603과 0x80070643은 다른 오류인가요? 같은 오류 번호입니다. 0x643은 10진수로 1603이고, 설치 프로그램은 '오류 1603'으로, Windows Update나 .NET 설치 화면은 '0x80070643' 형태로 보여 주는 경우가 있습니다. 어느 쪽이든 이 페이지의 점검 순서를 따르면 됩니다.
  • Windows Update에서 0x80070643이 나오는데 복구 파티션을 직접 늘려야 하나요? 먼저 이벤트 ID 4502(Windows Recovery Environment servicing failed)와 reagentc /info로 복구 환경 문제인지 확인하세요. 그 전에는 파티션을 건드리지 마세요. Microsoft의 KB5028997 절차는 디스크 파티션을 줄이고 복구 파티션을 삭제·재생성하는 방식이라 전체 백업이 필수입니다.
  • SYSTEM 계정 권한을 직접 바꿔도 되나요? Microsoft 문서가 안내하는 방법이지만 시스템 보안에 영향을 주므로, 앞의 세 가지(이미 설치됨, 암호화 폴더, 대체 드라이브)를 먼저 확인하세요. 바꿀 때는 문서의 절차 그대로, 백업 뒤에 진행하세요.
