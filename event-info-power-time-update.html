Kernel-Power 107·187·566·130·131, Time-Service, Winlogon, WindowsUpdateClient 정보 기록

이 묶음은 비정상 종료나 업데이트 실패를 판단할 때 보조 단서로 쓰는 정보 기록입니다. 단독으로는 문제를 뜻하지 않으며, 41·6008·20·25 같은 결과 기록과 시각을 맞춰 볼 때 가치가 생깁니다.

Kernel-Power 107·187·566은 전원 상태 전환과 정책 처리를 알리는 정보 기록입니다. 전원 공급 장치(PSU) 고장을 뜻하지 않으며, 비정상 종료를 판단할 때는 Kernel-Power 41·EventLog 6008과 사용자 작업 시각을 함께 봅니다.

Kernel-Power 130·131은 절전(S3) 진입·복귀에 펌웨어가 걸린 시간을 남깁니다. 오류가 아니라 시간 값이며, 복귀가 느리게 느껴질 때 다른 날과 비교하는 용도입니다.

이 페이지에서 설명하는 기록

원본·ID의미확인할 때
Kernel-Power 107Windows 전원 상태 전환·절전·재개 과정을 기록하는 정보 이벤트입니다. 비정상 종료를 판단할 때는 41·6008과 사용자 작업 시각을 함께 봅니다.Power-Troubleshooter·Kernel-Power 41·EventLog 6008과 시간순 비교
Kernel-Power 187Windows가 전원 관리·절전 정책과 관련된 상태를 기록한 정보 이벤트입니다. 하드웨어 고장보다는 전원 상태 전환의 맥락을 보여주는 보조 단서입니다.같은 시간의 41·107·6008·Power-Troubleshooter 대조
Kernel-Power 566Windows 전원 관리자 내부의 전원 상태 변경을 기록하는 정보 이벤트입니다. 발생 시각을 절전·재개·종료 기록과 맞추는 데 사용합니다.41·6008·1074와 시간순으로 비교
Kernel-Power 130절전(S3) 모드로 들어갈 때 펌웨어가 걸린 시간(SuspendStart·SuspendEnd)을 남기는 정보성 기록입니다.절전 진입이 유독 오래 걸린다면 SuspendStart와 SuspendEnd 값의 차이를 다른 날과 비교
Kernel-Power 131절전(S3)에서 깨어날 때 펌웨어가 복귀하는 데 걸린 시간(ResumeCount·FullResume·AverageResume)을 남기는 정보성 기록입니다.복귀가 느리다는 체감이 있으면 FullResume 값을 다른 날과 비교
Time-Service 35Windows 시간 서비스가 시간 원본(예: time.windows.com)과 시스템 시간을 동기화하기 시작했음을 기록합니다.시간이 어긋나면 동기화 원본과 네트워크 연결 확인
Time-Service 37Windows 시간 서비스가 동기화·상태 갱신을 수행한 기록입니다. 시계가 실제로 틀리거나 인증서·로그인 오류가 있을 때만 네트워크와 시간 서버를 점검합니다.w32tm /query /status로 마지막 동기화 상태 확인
Winlogon 7001Winlogon 세션의 로그온·로그오프 상태를 기록하는 정보 이벤트입니다. 로그인 지연이나 사용자 프로필 문제가 있을 때 관련 서비스와 같은 시각으로 해석합니다.이벤트의 사용자·세션·상태를 기록
Winlogon 7002Winlogon 사용자 세션이 종료되거나 상태를 전환한 기록입니다. 정상적인 로그오프·잠금에서도 발생할 수 있으며, 세션이 비정상적으로 끊길 때만 주변 이벤트를 확인합니다.사용자·세션 ID와 발생 시각 기록
WindowsUpdateClient 19Windows Update가 업데이트 검색·확인·처리 과정의 상태를 기록한 정보 이벤트입니다. 설치 실패 여부는 오류 코드와 20·25·31 등 후속 이벤트를 함께 확인해야 합니다.이벤트의 UpdateTitle·KB·ResultCode 확인
WindowsUpdateClient 43Windows Update 작업의 다운로드·설치 상태를 기록하는 정보 이벤트입니다. 실제 실패는 설명의 결과 코드와 Windows Update 오류 메시지를 기준으로 판단합니다.KB 번호·결과 코드·재부팅 필요 여부 기록
WindowsUpdateClient 44Windows Update가 업데이트 설치 또는 재부팅 후 상태를 갱신한 기록입니다. 설치 결과와 KB 번호가 실제 문제를 판단하는 핵심 정보입니다.이벤트의 UpdateTitle·KB·ResultCode 확인

걱정해야 하는 때

  • 재부팅·블루스크린이 실제로 있었다면 Kernel-Power 41, EventLog 6008과 시간순으로 비교합니다. 정보 기록만 반복되면 전원 부품을 교체하지 않습니다.
  • 절전 복귀가 느리면 Kernel-Power 131의 FullResume 값을 다른 날과 비교하고, 복귀 뒤 화면·네트워크가 돌아오지 않으면 그래픽·네트워크 드라이버와 Kernel-Power 172를 함께 확인합니다.
  • 시계가 실제로 틀릴 때만 w32tm /query /status로 마지막 동기화 상태를 확인합니다. Time-Service 기록만으로 메인보드 배터리나 RTC 고장을 판단하지 마세요.
  • Winlogon 7001·7002는 Service Control Manager의 7001과 원본이 다릅니다. 로그인 지연이나 예상하지 못한 로그오프가 있을 때만 주변 이벤트와 비교합니다.
  • WindowsUpdateClient 19·43·44는 결과 코드(ResultCode)가 없는 정보 기록이면 실패가 아닙니다. 실제 실패는 설정의 Windows Update 기록과 WindowsUpdateClient 20·25·31 같은 후속 기록으로 판단합니다.
  • WHEA-Logger 19와 WindowsUpdateClient 19는 번호만 같습니다. 원본을 먼저 확인하세요.
주의사항

정보 수준 기록 하나만으로 부품 고장이나 보안 사고를 판단하지 마세요. 같은 시각의 오류·경고 기록과 실제 증상(끊김, 재부팅, 느려짐)이 함께 있을 때만 단서로 씁니다.

자주 묻는 질문

  • Kernel-Power 107·187·566이 많이 보이는데 파워가 문제인가요? 아닙니다. 정상적인 전원 상태 전환·정책 처리 기록입니다. 비정상 종료 증거(41·6008)가 없고 실제 증상이 없다면 조치하지 않아도 됩니다.
  • WindowsUpdateClient 44가 있으면 업데이트가 실패한 건가요? 아닙니다. 44는 업데이트 설치 또는 재부팅 후 상태를 갱신한 기록입니다. 결과 코드가 없는 정보 기록을 실패로 해석하지 마세요.
  • 절전 복귀 기록(131)의 시간이 길면 부품 고장인가요? 값만으로는 단정할 수 없습니다. 체감 복귀 지연이 있을 때 다른 날 값과 비교하고, 그래픽·네트워크 드라이버와 전원 계획을 함께 확인하세요.
