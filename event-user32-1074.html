홈진단가이드게임문의

EVENT ID 1074

User32 이벤트 1074 계획된 종료·재시작 확인

사용자나 특정 프로세스가 Windows 종료·재시작을 요청했을 때 남는 계획된 종료 기록입니다. 갑작스러운 전원 차단인지는 이 이벤트의 요청 주체와 이유를 함께 봐야 합니다.

1074는 Windows가 종료나 재시작 요청을 받았을 때 남기는 정보 기록입니다. Kernel-Power 41처럼 갑작스러운 전원 차단을 뜻하는 이벤트가 아니므로, 먼저 요청한 프로세스와 사용자를 확인해야 합니다.

Windows Update나 설치 프로그램이 재시작을 요청한 경우에는 정상적인 기록일 수 있습니다. 반대로 예상하지 못한 프로세스가 반복해서 요청한다면 최근 설치 항목과 보안 로그를 함께 비교하세요.

발생 조건

  • Windows Update 뒤 자동 재시작
  • 시작 메뉴·shutdown 명령으로 종료
  • 관리 도구나 설치 프로그램이 재부팅 요청

가능성 높은 원인

  • 사용자 직접 종료
  • Windows Update 또는 설치 프로그램
  • WMI·관리 도구가 보낸 종료 요청

계획된 종료와 예기치 않은 종료의 차이

1074는 누군가 또는 무언가가 요청해서 Windows가 종료·재시작을 시작했다는 기록입니다. Kernel-Power 41이나 EventLog 6008과는 반대 성격입니다 — 저것들은 계획 없이 갑자기 꺼진 기록이고, 1074는 정상적으로 종료 절차를 시작했다는 기록입니다. 다만 시작만 기록되므로, 그 뒤 실제로 정상 종료됐는지는 별도로 확인해야 합니다.

점검 순서

  1. Description의 프로세스·사용자·Reason Code 기록 — 이벤트 설명에서 종료를 요청한 프로세스(예: svchost.exe), 요청한 사용자 계정, Reason Code를 적어 둡니다. 이 세 값이 무엇이 왜 종료를 요청했는지 알려줍니다.
  2. 같은 시각의 Windows Update·설치 이벤트 비교 — 프로세스가 TrustedInstaller나 업데이트 관련 서비스라면 Windows Update가 재시작을 요청한 정상 동작입니다. 이벤트 뷰어의 Windows 로그 → 설정에서 같은 시각의 업데이트 설치 기록을 대조하세요.
  3. 1074 뒤 실제 재부팅이 이어졌는지 6008·41과 시간 비교 — 1074는 종료를 요청한 기록일 뿐 실제로 정상 종료됐는지는 확인해 주지 않습니다. 직후 시각에 EventLog 6008이나 Kernel-Power 41이 남아 있다면, 종료 요청은 있었지만 실제로는 비정상적으로 꺼졌다는 뜻이므로 전원·드라이버 쪽을 별도로 점검해야 합니다.
주의사항

1074는 계획된 종료 요청 기록입니다. 이 이벤트만으로 원치 않는 종료나 악성 동작을 확정하지 마세요.

자주 묻는 질문

  • 1074가 있으면 PC 고장인가요? 아닙니다. 사용자의 종료·재시작이나 Windows Update 같은 계획된 동작도 1074를 남깁니다. 프로세스 이름과 발생 시각을 실제 작업과 비교해야 합니다.
  • 1074와 Kernel-Power 41을 같이 봐야 하나요? 네. 1074는 종료 요청 주체를, 41은 정상 종료되지 않은 결과를 보여줍니다. 두 기록의 시각을 비교하면 계획된 재시작과 갑작스러운 전원 차단을 구분하는 데 도움이 됩니다.
