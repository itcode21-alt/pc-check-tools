에러 코드 상세

0x000000F4 · CRITICAL_OBJECT_TERMINATION

핵심 시스템 프로세스나 스레드 객체가 예기치 않게 종료되었을 때 나타나는 코드로, 저장장치 문제와 함께 발생하는 경우가 많습니다.

이 코드를 어떻게 해석해야 하나요?

오류 코드는 고장 부품을 확정하는 판정이 아니라 발생 시점과 함께 원인 범위를 좁히는 단서입니다. 최근 변경, 반복 조건, 안전 모드 재현 여부를 함께 기록하세요.

먼저 기록할 내용: 0x000000F4가 발생한 시각, 직전에 실행한 작업, 최근 설치한 드라이버·업데이트, 재부팅 뒤 같은 코드가 반복되는지를 적어 두세요.

가능성 높은 원인

  • 부팅 디스크의 연결 불량이나 물리적 결함
  • 부팅 관련 시스템 파일의 손상
  • 저장장치 드라이버 문제
  • 전원 공급 불안정으로 인한 저장장치 접근 실패
  • 최근 시스템 설정 변경으로 인한 충돌

첫 점검 항목

  1. 저장장치 물리 연결 확인 — 저장장치 연결 상태를 물리적으로 확인하세요.
  2. 복구 환경에서 시스템 파일 복구 — 시동 복구를 먼저 시도하고, 안 되면 복구 환경 명령 프롬프트에서 sfc /scannow /offbootdir=C:\ /offwindir=C:\Windows를 실행하세요.
  3. 저장장치 진단 도구로 상태 점검 — 제조사 진단 유틸리티로 SMART 상태를 확인하세요.
  4. 최근 변경 사항 되돌리기 — 최근 설치한 드라이버나 변경한 시스템 설정이 있다면 되돌려 보세요.
  5. 전원 공급 점검 — 파워 서플라이 용량과 케이블 연결 상태를 점검하세요.

확인 결과에 따른 다음 단계

  • 저장장치 진단에서 이상이 없고 시동 복구로 해결될 때 — 재발 여부만 지켜보면 됩니다.
  • 진단 도구에서 배드섹터나 경고가 뜰 때 — 복구 명령보다 데이터 백업을 최우선으로 하고 디스크 교체를 검토하세요.
  • 시동 복구·sfc로도 해결되지 않을 때 — 최근 설치한 저장장치 컨트롤러 드라이버를 이전 버전으로 롤백해보세요.

데이터와 시스템을 보호하는 주의사항

원인이 분명하지 않은데 초기화·레지스트리 수정·시스템 파일 교체 같은 조치를 먼저 시도하면 오히려 문제가 커질 수 있습니다.

앞 단계로 해결되지 않을 때

같은 코드가 반복되면 이벤트 로그와 장치 상태를 보존하고, 코드가 계속 달라지면 메모리·전원·온도처럼 시스템 전체 안정성을 확인하세요.

복구, 초기화, 드라이버 제거처럼 되돌리기 어려운 작업 전에는 중요한 파일을 다른 물리 저장장치나 신뢰할 수 있는 백업 위치에 보관하세요.

관련 증상 가이드 확인하기

같은 증상과 연결된 다른 오류 코드

  • 0x80070002 · 파일을 찾을 수 없음
  • 0x80070057 · 매개 변수가 올바르지 않음
  • 0x800F0922 · Windows 업데이트 실패
  • 0x80004005 · Unspecified error

자주 묻는 질문

  • 복구 화면에서 초기화를 바로 눌러도 되나요? 이 문제(0x000000F4)가 반복된다면 초기화 전에 먼저 안전 모드 진입과 최근 변경 사항 확인을 시도해보세요. 초기화는 되돌리기 어려우니 마지막 단계로 남겨두는 것이 좋습니다.
  • 외장 하드를 연결한 상태에서도 복구를 시도해도 되나요? 외장 장치가 부팅 순서에 영향을 줄 수 있으므로, 복구 시도 전에는 분리하는 것이 좋습니다.
  • 이 코드가 램 때문일 수도 있나요? 저장장치가 원인의 대부분이지만, Windows 메모리 진단 도구로 램 상태도 함께 확인해야 저장장치와 램 양쪽을 배제하고 원인을 좁힐 수 있습니다.
