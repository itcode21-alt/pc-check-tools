📑 목차

에러 코드 상세

셸 확장 충돌 (작업표시줄 멈춤) · 셸 확장 프로그램 충돌로 작업표시줄과 시작 메뉴가 멈춤

우클릭 메뉴를 추가하는 압축 프로그램, 클라우드 동기화 도구, 시작 메뉴 커스터마이징 도구 등이 탐색기 셸과 충돌하면 작업표시줄이나 시작 메뉴만 멈추는 증상으로 나타납니다.

이 코드를 어떻게 해석해야 하나요?

오류 코드는 고장 부품을 확정하는 판정이 아니라 발생 시점과 함께 원인 범위를 좁히는 단서입니다. 최근 변경, 반복 조건, 안전 모드 재현 여부를 함께 기록하세요.

먼저 기록할 내용: 셸 확장 충돌 (작업표시줄 멈춤)가 발생한 시각, 직전에 실행한 작업, 최근 설치한 드라이버·업데이트, 재부팅 뒤 같은 코드가 반복되는지를 적어 두세요.

가능성 높은 원인

  • 최근 설치한 셸 확장(우클릭 메뉴 추가 프로그램)이 충돌하는 경우
  • 시작 메뉴/작업표시줄을 변경하는 서드파티 도구와의 충돌
  • 탐색기 캐시나 아이콘 캐시가 손상된 경우

첫 점검 항목

  1. 탐색기 재시작으로 즉시 확인 — 작업 관리자(Ctrl+Shift+Esc)에서 "Windows 탐색기"를 찾아 다시 시작하세요. 이것만으로 풀리면 캐시나 일시적 충돌일 가능성이 큽니다.
  2. 최근 설치 프로그램 제거 — 압축 프로그램, 클라우드 동기화, 시작 메뉴 꾸미기 도구를 최근 설치·업데이트 순으로 하나씩 제거하며 재현 여부를 확인하세요.
  3. 아이콘 캐시 삭제 — 탐색기를 모두 닫은 뒤 %localappdata%\IconCache.db 파일과 %localappdata%\Microsoft\Windows\Explorer 폴더의 캐시 파일(thumbcache_*.db)을 삭제하고 재부팅하세요.
  4. ShellExView로 원인 셸 확장 특정 — NirSoft의 무료 ShellExView를 실행해 Microsoft 항목은 그대로 두고, 최근 설치한 프로그램의 확장만 하나씩 비활성화(빨간 표시)한 뒤 탐색기를 재시작해 원인을 좁히세요.
  5. 깨끗한 부팅으로 교차 확인 — 위 방법으로도 반복되면 클린 부팅으로 비Microsoft 시작 앱을 모두 끈 상태에서 재현되는지 확인하세요.

확인 결과에 따른 다음 단계

  • 탐색기 재시작만으로 매번 풀릴 때 — 근본 원인(특정 셸 확장)을 찾기 전까지는 임시 조치로 반복 사용해도 무방하지만, ShellExView로 원인 프로그램을 특정해두면 재발을 줄일 수 있습니다.
  • 특정 프로그램 제거 후 재발하지 않을 때 — 그 프로그램의 최신 버전이나 우클릭 메뉴 기능을 끌 수 있는 설정이 있는지 제조사 홈페이지에서 확인한 뒤 재설치하세요.
  • ShellExView로 특정 확장을 비활성화해도 계속될 때 — 탐색기 자체보다 시작 메뉴·작업표시줄 관련 시스템 파일 손상 가능성이 있으므로 sfc /scannow를 실행하세요.

실제 사용자 사례

위 점검 순서로도 해결되지 않았을 때, 다른 원인으로 해결된 사례입니다.

클라우드 동기화 도구 재설치로 해결한 사례

특정 클라우드 저장소 프로그램을 설치한 뒤부터 파일 탐색기에서 우클릭할 때마다 몇 초씩 멈추던 사례가 있습니다. ShellExView로 확인하니 그 프로그램의 셸 확장이 응답 없음 상태로 표시됐고, 프로그램을 완전히 제거한 뒤 최신 버전으로 재설치하자 재발하지 않았습니다.

포인트: 특정 프로그램 설치 이후부터 증상이 시작됐다면, 재설치보다 먼저 완전 제거 후 최신 버전으로 새로 설치하는 편이 셸 확장 잔여 문제를 줄이는 데 더 효과적입니다.

데이터와 시스템을 보호하는 주의사항

아직 원인을 특정하지 못했다면 초기화나 레지스트리 편집, 시스템 파일 교체 같은 조치는 뒤로 미루세요.

앞 단계로 해결되지 않을 때

반복되는 코드가 같다면 이벤트 로그와 장치 상태를 남겨두세요. 코드가 매번 다르다면 메모리·전원·온도 등 시스템 전체 안정성부터 확인하는 것이 순서입니다.

되돌리기 어려운 조치(복구, 초기화, 드라이버 제거 등)에 들어가기 전에는 반드시 중요 데이터를 다른 저장장치로 옮겨 두는 것이 안전합니다.
