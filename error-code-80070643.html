에러 코드 상세

오류 0x80070643 · 설치 중 오류가 발생했습니다 (0x80070643)

주로 .NET Framework나 특정 재배포 패키지 설치 도중 나타나는 오류로, 구성 요소 손상이나 이전 설치 실패의 잔여 상태가 원인인 경우가 많습니다.

이 코드를 어떻게 해석해야 하나요?

이런 업데이트 오류 코드는 네트워크·캐시·구성 요소 저장소·디스크 공간·서비스 상태 가운데 어느 지점에서 문제가 생겼는지 알려주는 단서입니다. 반복되는 시점과 이벤트 로그의 세부 코드를 함께 확인하세요.

먼저 기록할 내용: 오류 0x80070643가 발생한 시각, 직전에 실행한 작업, 최근 설치한 드라이버·업데이트, 재부팅 뒤 같은 코드가 반복되는지를 적어 두세요.

가능성 높은 원인

  • .NET Framework 구성 요소가 손상된 경우
  • 이전 설치나 업데이트가 실패한 채로 남아있는 경우
  • 관련 윈도우 업데이트가 누락된 경우
  • 레지스트리에 손상된 설치 기록이 남아있는 경우
  • 디스크 오류로 설치 파일 일부가 손상된 경우

첫 점검 항목

  1. .NET Framework 복구 도구(마이크로소프트 공식 .NET Framework Repair Tool)를 실행해 보세요.
  2. Windows Update에서 관련 누락된 업데이트가 있는지 확인하고 설치하세요.
  3. 제어판의 Windows 기능 켜기/끄기에서 .NET Framework를 껐다가 다시 켜 보세요.
  4. sfc /scannow로 시스템 파일 손상 여부를 점검하세요.
  5. 설치 로그 파일을 확인해 구체적으로 어떤 구성 요소에서 실패했는지 확인하세요.

확인 결과에 따른 다음 단계

  • .NET 복구 도구로 해결될 때 — 재발 여부만 지켜보면 됩니다.
  • Windows 기능 껐다 켜기로 해결될 때 — 재발 여부만 지켜보면 됩니다.
  • sfc /scannow로도 해결되지 않을 때 — 설치 로그에서 구체적으로 실패한 구성 요소를 확인해 수동으로 설치하세요.

데이터와 시스템을 보호하는 주의사항

레지스트리 정리 도구나 시스템 폴더 권한 변경은 마지막 수단으로 남겨두고, 저장 공간과 네트워크, 서비스 상태부터 확인해보세요.

앞 단계로 해결되지 않을 때

반복해서 같은 오류가 난다면 Windows Update 이력과 DISM·SFC 결과를 저장하고, 설치 미디어 버전이 지금 쓰는 Windows와 맞는지부터 확인하세요.

시스템 복구나 초기화, 드라이버 삭제처럼 원상복구가 힘든 작업을 시작하기 전에, 중요한 파일은 미리 외장 저장장치나 별도 위치에 백업해 두세요.

관련 증상 가이드 확인하기

  • 오류 1618 · 다른 설치가 진행 중입니다 (오류 1618)
  • 오류 2503 · 이 설치 패키지를 열 수 없습니다 (오류 2503)
  • 오류 2502 · 이 설치 패키지를 열 수 없습니다 (오류 2502)

자주 묻는 질문

  • 설치 오류가 나면 프로그램을 다시 받으면 되나요? 이 문제(오류 0x80070643)는 설치 파일보다 Windows Installer 서비스나 잔여 파일이 원인인 경우가 많아, 재다운로드 전에 서비스 상태와 이전 설치 흔적부터 정리해보세요.
  • 이전 버전을 지우지 않고 업데이트 설치하면 안 되나요? 일부 프로그램은 가능하지만, 오류가 반복된다면 이전 버전을 완전히 제거한 뒤 재설치하는 것이 안전합니다.
  • .NET Framework 여러 버전을 동시에 설치해도 되나요? .NET Framework는 여러 버전이 공존하도록 설계되어 있어 동시 설치가 문제되지 않습니다.
