에러 코드 상세

0x000000C5 · DRIVER_CORRUPTED_EXPOOL

드라이버가 커널 메모리 풀을 손상시킨 상태를 가리키므로 최근 설치한 드라이버와 커널 수준 프로그램을 먼저 확인하세요.

커널 드라이버가 시스템 메모리 풀을 손상시키거나 높은 IRQL에서 잘못된 메모리에 접근했을 때 나타나는 블루스크린입니다. 오류 이름처럼 드라이버 가능성이 매우 높지만, 불안정한 메모리가 드라이버 동작을 깨뜨리는 경우도 함께 고려해야 합니다.

이 코드를 어떻게 해석해야 하나요?

오류 코드 자체가 고장난 부품을 확정 짓는 것은 아니며, 발생 시점과 함께 원인 후보를 좁히는 단서로 활용해야 합니다. 최근 변경 사항, 반복되는 조건, 안전 모드에서의 재현 여부를 함께 기록해두세요.

먼저 기록할 내용: 0x000000C5가 발생한 시각, 직전에 실행한 작업, 최근 설치한 드라이버·업데이트, 재부팅 뒤 같은 코드가 반복되는지를 적어 두세요.

가능성 높은 원인

  • 그래픽·네트워크·저장장치 드라이버의 메모리 관리 결함
  • VPN, 백신, 튜닝 도구, 가상화 프로그램의 커널 드라이버 충돌
  • 최근 업데이트된 드라이버가 현재 Windows 빌드와 맞지 않는 경우
  • 램 불안정으로 드라이버가 잘못된 메모리를 참조하는 경우
  • 손상된 드라이버 설치나 제거되지 않은 이전 버전의 잔여 파일

첫 점검 항목

  1. 덤프 파일에서 !analyze 결과와 반복해서 언급되는 .sys 드라이버 이름을 먼저 기록하세요.
  2. 최근 설치·업데이트한 드라이버와 커널 수준 프로그램을 하나씩 롤백하거나 제조사 공식 버전으로 재설치하세요.
  3. 안전 모드에서 증상이 재현되는지 비교해 타사 드라이버 개입 여부를 좁히세요.
  4. 드라이버 변경으로도 해결되지 않으면 XMP/EXPO를 끄고 메모리 진단을 진행하세요.
  5. Driver Verifier는 원인 드라이버를 찾는 고급 도구이므로 복구 환경 진입 방법과 해제 방법을 확인한 뒤 필요한 경우에만 사용하세요.

확인 결과에 따른 다음 단계

  • 덤프에서 지목된 드라이버를 롤백해 해결될 때 — 재발 여부만 지켜보면 됩니다.
  • 안전 모드에서는 재현되지 않을 때 — 타사 드라이버가 원인이므로 최근 설치 순서대로 하나씩 제거하세요.
  • XMP 해제·메모리 진단으로도 해결되지 않을 때 — Driver Verifier 사용을 고려하세요.

데이터와 시스템을 보호하는 주의사항

아직 원인을 특정하지 못했다면 초기화나 레지스트리 편집, 시스템 파일 교체 같은 조치는 뒤로 미루세요.

앞 단계로 해결되지 않을 때

같은 코드가 반복되면 이벤트 로그와 장치 상태를 보존하고, 코드가 계속 달라지면 메모리·전원·온도처럼 시스템 전체 안정성을 확인하세요.

복구, 초기화, 드라이버 제거처럼 되돌리기 어려운 작업 전에는 중요한 파일을 다른 물리 저장장치나 신뢰할 수 있는 백업 위치에 보관하세요.

자주 묻는 질문

  • 블루스크린 코드가 한 번 떴는데 계속 지켜봐야 하나요? 이 문제(0x000000C5)가 한 번만 발생했다면 즉시 부품을 교체하기보다 재현 여부와 최근 변경 사항을 먼저 기록해두는 것으로 충분합니다. 반복된다면 그때 하드웨어 점검 범위를 넓히세요.
  • 덤프 파일은 어디서 확인하나요? C:\Windows\Minidump 폴더에 저장되며, BlueScreenView 같은 도구로 열어 정지 코드와 관련 드라이버를 확인할 수 있습니다.
  • Driver Verifier를 켠 채로 계속 써도 되나요? 검사 중에는 시스템이 불안정해질 수 있으므로 원인 확인이 끝나면 반드시 꺼야 합니다.
