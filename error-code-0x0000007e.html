📑 목차

에러 코드 상세

0x0000007E · SYSTEM_THREAD_EXCEPTION_NOT_HANDLED

시스템 스레드에서 처리되지 않은 예외가 발생했을 때 나타나며, 주로 그래픽이나 칩셋 드라이버의 결함, 혹은 업데이트 직후 호환성 문제로 발생합니다.

이 코드를 어떻게 해석해야 하나요?

오류 코드 자체가 고장난 부품을 확정 짓는 것은 아니며, 발생 시점과 함께 원인 후보를 좁히는 단서로 활용해야 합니다. 최근 변경 사항, 반복되는 조건, 안전 모드에서의 재현 여부를 함께 기록해두세요.

먼저 기록할 내용: 0x0000007E가 발생한 시각, 직전에 실행한 작업, 최근 설치한 드라이버·업데이트, 재부팅 뒤 같은 코드가 반복되는지를 적어 두세요.

가능성 높은 원인

  • 그래픽이나 칩셋 드라이버가 최신 업데이트와 호환되지 않는 경우
  • 시스템 파일이 손상된 경우
  • 타사 프로그램이 시스템 스레드와 충돌하는 경우
  • 램이나 저장장치의 물리적 불안정
  • 오버클럭 설정으로 인한 시스템 불안정

첫 점검 항목

  1. 업데이트 직후부터 증상이 시작됐는지 확인하고, 그렇다면 관련 드라이버를 재설치하세요. <a href="graphics-driver-guide.html">그래픽 드라이버 재설치 방법 보기 →</a>
  2. 안전 모드에서 재현 여부를 확인해 드라이버 문제인지 구분하세요.
  3. sfc /scannow로 시스템 파일을 점검하세요.
  4. 최근 설치한 타사 프로그램을 제거한 뒤 재현 여부를 확인하세요.
  5. 오버클럭 설정이 있다면 기본값으로 되돌리세요.

확인 결과에 따른 다음 단계

  • 관련 드라이버 재설치로 해결될 때 — 재발 여부만 지켜보면 됩니다.
  • 안전 모드에서는 재현되지 않을 때 — 최근 설치한 프로그램 제거로 넘어가세요.
  • sfc /scannow로도 해결되지 않을 때 — 사례처럼 문제 드라이버 파일을 직접 확인하세요.

실제 사용자 사례

위 점검 순서로도 해결되지 않았을 때, 다른 원인으로 해결된 사례입니다.

문제 드라이버 파일 직접 삭제로 해결한 사례

AMD OverDrive 관련 드라이버(AODDRIVER2.sys)가 원인으로 지목됐지만, 설치 프로그램이 손상되어 제어판에서 일반적인 방법으로는 제거할 수 없었던 사례가 있습니다. 시스템 폴더에서 해당 드라이버 파일을 직접 찾아 삭제한 뒤 정상적으로 부팅됐습니다.

포인트: 원인 드라이버를 찾았는데도 제어판에서 제거가 안 된다면, 설치 프로그램 자체가 손상됐을 수 있습니다. 이 경우 드라이버 파일을 직접 삭제해야 할 수도 있지만, 시스템 파일을 직접 다루는 작업이라 신중하게 진행해야 합니다.

데이터와 시스템을 보호하는 주의사항

정확한 원인을 파악하기 전에 초기화나 레지스트리 수정, 시스템 파일 수동 교체부터 시도하지 않는 것이 좋습니다.

앞 단계로 해결되지 않을 때

코드가 매번 동일하게 반복된다면 이벤트 로그와 장치 상태를 기록해두고, 코드가 바뀐다면 메모리·전원·온도처럼 시스템 전체의 안정성을 먼저 살펴보세요.

되돌리기 어려운 조치(복구, 초기화, 드라이버 제거 등)에 들어가기 전에는 반드시 중요 데이터를 다른 저장장치로 옮겨 두는 것이 안전합니다.

관련 증상 가이드 확인하기

  • 0x00000050 · PAGE_FAULT_IN_NONPAGED_AREA

  • 0x000000D1 · DRIVER_IRQL_NOT_LESS_OR_EQUAL

자주 묻는 질문

  • 블루스크린 코드가 한 번 떴는데 계속 지켜봐야 하나요? 이 문제(0x0000007E)가 한 번만 발생했다면 즉시 부품을 교체하기보다 재현 여부와 최근 변경 사항을 먼저 기록해두는 것으로 충분합니다. 반복된다면 그때 하드웨어 점검 범위를 넓히세요.
  • 블루스크린 이후 데이터가 손상되나요? 대부분은 강제 재시작만 발생할 뿐 저장된 파일이 곧바로 손상되지는 않지만, 저장하지 않은 작업 내용은 사라질 수 있습니다.
  • 드라이버 파일을 직접 삭제해도 안전한가요? 위험도가 높은 작업이므로 복원 지점을 먼저 만들고, 정확한 파일명을 확인한 뒤 신중하게 진행해야 합니다.
