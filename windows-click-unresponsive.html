Windows 11 클릭 무반응

홈진단가이드게임문의
홈/가이드/Windows 11 클릭 무반응

목차

    WINDOWS 11

    마우스는 움직이는데 클릭이 되지 않을 때

    부팅 후 몇 분 동안은 정상인데 창·작업표시줄·바탕화면 클릭이 모두 반응하지 않는다면 입력 장치보다 Windows가 클릭 명령을 처리하는 경로를 먼저 확인하세요.

    이 증상은 마우스 포인터가 움직인다는 이유만으로 마우스 문제라고 단정하기 어렵습니다. 포인터 이동은 계속되지만 Explorer.exe, 작업표시줄, Desktop Window Manager(DWM), 특정 프로그램 또는 저장장치 응답이 멈추면 클릭만 무시되는 것처럼 보일 수 있습니다. 다른 마우스를 연결해도 같은 현상이 반복된다면 입력 장치 교체보다 멈춘 순간의 시스템 상태를 기록하는 편이 원인 파악에 도움이 됩니다.

    먼저 작업 관리자나 Ctrl+Alt+Delete 화면이 열리는지 구분하세요. 작업 관리자가 열리면 Windows 전체보다는 탐색기·특정 프로그램·디스크 병목을 좁혀볼 수 있습니다. 단축키도 전혀 반응하지 않으면 저장장치 I/O, 그래픽 드라이버, 메모리, 전원 안정성까지 함께 확인해야 합니다.

    핵심 판단

    재부팅 후 잠시 정상으로 돌아오는 것은 원인이 해결됐다는 뜻이 아닙니다. 다음에 다시 멈출 때의 시각, CPU·메모리·디스크 사용률, 이벤트 뷰어 기록을 남겨야 합니다.

    1. 멈춘 순간 바로 확인할 것

    1. Ctrl+Shift+Esc를 눌러 작업 관리자를 엽니다. 디스크 사용률과 응답 시간, 메모리·커밋 사용량, 응답 없음으로 표시된 앱을 기록하세요.
    2. 작업 관리자가 열리면 Windows 탐색기를 찾아 다시 시작합니다. 즉시 클릭이 돌아오면 셸 확장·클라우드 동기화·미리 보기·네트워크 드라이브를 우선 의심합니다.
    3. 화면 갱신이 멈춘 느낌이면 Win+Ctrl+Shift+B를 눌러 그래픽 드라이버를 재설정합니다. 화면이 깜빡인 뒤 회복되면 그래픽 드라이버·오버레이·GPU 온도와 전원을 확인합니다.
    4. Ctrl+Alt+Delete도 열리지 않으면 강제 종료 전에 가능한 한 작업을 저장하고, 재부팅 후 이벤트 발생 시각을 확인합니다.

    2. 원인별로 나누는 기준

    Windows 탐색기·작업표시줄만 멈추는 경우

    탐색기를 다시 시작했을 때 바로 회복된다면 파일 자체보다 셸 확장, 우클릭 메뉴, 썸네일, 클라우드 동기화, 끊긴 네트워크 드라이브가 원인일 수 있습니다. 최근 설치한 압축 프로그램이나 백업·동기화 도구를 하나씩 중지하고 재현 여부를 비교하세요.

    디스크가 100%이거나 응답 시간이 긴 경우

    작업 관리자에서 디스크 사용률이 높고 응답 시간이 수백~수천 ms로 치솟으면 클릭 처리에 필요한 프로필·셸 파일을 읽지 못해 전체 화면이 멈춘 것처럼 보일 수 있습니다. 이벤트 뷰어에서 Disk 7·51·129·154, Ntfs 55, storport·volsnap이 같은 시간에 반복되는지 확인하고, 반복 오류가 있다면 복구 명령보다 중요한 파일 백업과 SMART·제조사 진단을 먼저 진행하세요.

    화면은 보이지만 그래픽 드라이버가 멈추는 경우

    게임이나 영상 전환 뒤 화면만 멈추거나 Win+Ctrl+Shift+B로 회복된다면 Display 4101, nvlddmkm 153, LiveKernelEvent를 확인합니다. GPU 온도·핫스팟·보조전원·오버클럭을 점검하고 Discord, GeForce Experience, Xbox Game Bar 등 오버레이를 끈 상태와 비교하세요.

    메모리·프로그램이 점점 자원을 소모하는 경우

    부팅 직후에는 괜찮다가 몇 분 또는 몇 시간 뒤 멈춘다면 특정 프로그램의 메모리 누수나 커밋 부족도 후보입니다. 메모리 사용량만 보지 말고 커밋 사용량과 페이지 파일 상태를 함께 기록하세요. Application Hang 1002, Application Error 1000, Resource-Exhaustion-Detector 2004가 같은 프로그램과 함께 반복되는지 확인합니다.

    3. 이벤트 뷰어에서 시간대를 맞추는 방법

    1. 증상이 발생한 시각을 분 단위로 기록합니다.
    2. 이벤트 뷰어에서 Windows 로그 → 응용 프로그램과 Windows 로그 → 시스템을 각각 확인합니다.
    3. 응용 프로그램 로그에서는 Application Hang 1002의 응답 없음 프로그램과 Application Error 1000의 오류 모듈을 확인합니다.
    4. 시스템 로그에서는 Disk·Ntfs·Display·WHEA-Logger·Kernel-Power를 같은 시간대에 비교합니다.
    5. 오류 하나만으로 부품을 확정하지 말고, 같은 시간에 반복된 이벤트와 실제 증상을 함께 판단합니다.

    4. 안전한 해결 순서

    1. 중요 파일을 먼저 백업합니다. Disk 154나 읽기 지연이 있으면 외장 저장장치나 다른 PC에 복사하세요.
    2. 최근 설치한 셸 확장·클라우드·백신·게임 오버레이를 하나씩 끄고 재현 조건을 비교합니다.
    3. 그래픽·칩셋·저장장치 드라이버를 PC·메인보드·GPU 제조사 버전 기준으로 업데이트하거나 문제가 업데이트 직후 시작됐다면 롤백합니다.
    4. 안전 모드 또는 클린 부팅에서 같은 시간이 지난 뒤에도 클릭이 멈추는지 확인합니다. 안전 모드에서 정상이라면 외부 서비스·드라이버 가능성이 올라갑니다.
    5. 여러 프로그램에서 무작위로 멈추고 WHEA·메모리 오류까지 나타나면 RAM 기본 설정, MemTest86, 저장장치 SMART, 발열을 순서대로 확인합니다.

    피해야 할 실수

    • 다른 마우스를 계속 교체하면서 Windows 셸·디스크 상태를 확인하지 않는 것
    • Disk 오류가 있는데 SFC·DISM이나 재설치를 먼저 반복하는 것
    • Kernel-Power 41만 보고 곧바로 파워서플라이를 교체하는 것
    • 여러 드라이버와 시작 프로그램을 한꺼번에 변경해 원인 비교가 불가능해지는 것

    자주 묻는 질문

    • 마우스 포인터가 움직이면 그래픽카드는 정상인가요? 기본 출력이 유지된다는 단서일 뿐 그래픽 드라이버가 완전히 정상이라는 뜻은 아닙니다. Win+Ctrl+Shift+B 반응과 Display·nvlddmkm 이벤트를 함께 확인하세요.
    • 재부팅하면 해결되는데 그냥 사용해도 되나요? 재부팅은 셸·메모리·드라이버 상태를 초기화할 뿐 원인을 없애지 않을 수 있습니다. 반복된다면 발생 시각과 사용률을 기록하세요.
    • 가장 먼저 어떤 이벤트를 봐야 하나요? Application Hang 1002로 응답 없음 대상을 확인하고, 같은 시간의 Disk 154·Display 4101·nvlddmkm 153·WHEA 이벤트를 비교하는 것이 좋습니다.
