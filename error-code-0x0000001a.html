에러 코드 상세

0x0000001A · MEMORY_MANAGEMENT

메모리 관리자가 심각한 오류를 발견했을 때 나오는 코드입니다. 문서는 첫 번째 매개변수 값에 따라 하드웨어 오류, 드라이버의 잘못된 메모리 사용, 페이지 테이블 손상 같은 원인을 나눕니다.

램 자체의 불량뿐 아니라 드라이버의 메모리 오용도 흔한 원인입니다.

이 코드를 어떻게 해석해야 하나요?

첫 번째 매개변수가 정확한 위반 유형입니다. 문서의 표에서 0x31(이미지 재배치 정보 손상)과 0x403(페이지 테이블과 PFN 불일치), 0x5003(작업 집합 여유 목록 손상)은 하드웨어 오류일 가능성이 크다고 하고, 0x1233(잠기지 않은 물리 페이지를 드라이버가 매핑)과 0x4477(드라이버가 할당되지 않은 주소에 쓰기)은 드라이버 코드의 문제로 설명합니다. 일반 사용자용 해결 절차는 짧게 Windows 메모리 진단 도구를 실행해 물리 메모리 문제를 확인하라는 안내만 있습니다. 나머지 점검은 문서 외 일반 점검입니다.

가능성 높은 원인

  • 램 같은 하드웨어 오류(문서가 하드웨어 오류일 가능성이 크다고 적은 위반 유형)
  • 드라이버가 잠기지 않은 물리 페이지를 매핑하거나 할당되지 않은 주소에 쓴 경우
  • 페이지 테이블 항목이나 커널 스레드 스택 같은 메모리 관리 구조가 손상된 경우
  • 페이지 파일에서 읽은 페이지가 CRC 검사에 실패한 경우(첫 매개변수 0x3F)

첫 점검 항목

  1. 공식 문서가 알려 주는 것: Windows 메모리 진단 도구를 실행해 물리 메모리에 문제가 있는지 확인하세요.
  2. 문서 외 일반 점검: 램을 한 개씩 꽂아 재부팅하며 특정 모듈이나 슬롯에서만 재현되는지 보세요. 실제 검사 방법과 결과 해석 보기 →
  3. 문서 외 일반 점검: BIOS에서 XMP나 오버클럭 설정을 기본값으로 되돌려 증상이 사라지는지 확인하세요.
  4. 문서 외 일반 점검: 최근 설치하거나 업데이트한 드라이버가 있다면 이전 버전으로 되돌려 재현 여부를 보세요.
  5. 문서 외 일반 점검: chkdsk로 페이지 파일이 있는 디스크에 오류가 없는지, sfc /scannow로 시스템 파일이 정상인지 점검하세요.

확인 결과에 따른 다음 단계

  • 메모리 진단에서 오류가 나왔을 때 — 램 모듈을 하나씩 꽂아 오류가 나는 모듈과 슬롯을 가려내세요. 모듈 분리는 문서 외 일반 조치입니다. 불량 모듈은 보증 기간 안에 교체를 신청하세요.
  • XMP나 오버클럭을 끄면 사라질 때 — 기본 클럭에서 안정적인지 며칠 지켜본 뒤 다시 켜려면 전압과 타이밍을 낮춰 시험하세요. 램이나 CPU의 메모리 컨트롤러가 그 설정을 견디지 못한 경우일 수 있습니다.
  • 최근 드라이버를 되돌리면 사라질 때 — 그 드라이버 업데이트는 보류하고 제조사가 수정 버전을 내는지 확인하세요. 문서는 일부 위반 유형을 드라이버 코드의 문제로 설명합니다.

해결 사례 예시

위 점검 순서로도 해결되지 않았을 때 다른 원인으로 해결될 수 있는 예시입니다. 실제 제보를 그대로 옮긴 것이 아니라 일반적인 사례를 바탕으로 구성한 참고용 예시이며, 환경에 따라 결과가 다를 수 있습니다.

램 오버클럭(XMP) 낮춰서 해결한 사례

새로 조립한 PC에서 게임 중 반복적으로 이 블루스크린이 발생했던 사례가 있습니다. 램 자체는 정상으로 테스트됐지만, XMP로 설정된 고클럭(3600MHz)이 실제로는 불안정했던 것이 원인이었고, 클럭을 3200~3400MHz로 낮춘 뒤 재현되지 않았습니다.

포인트: 메모리 진단 도구를 통과해도 XMP/오버클럭 설정 자체가 불안정의 원인일 수 있습니다. 기본 클럭에서 안정적이라면 XMP 프로파일을 의심해보세요.

SFC로 시스템 파일 복구해 해결한 사례

램과 디스크 모두 정상으로 진단됐는데도 이 블루스크린이 반복됐던 사례에서는, sfc /scannow 명령이 손상된 시스템 파일을 발견해 복구한 뒤로 더 이상 블루스크린이 발생하지 않았습니다.

포인트: 이름은 '메모리 관리' 오류지만 실제 원인이 하드웨어가 아니라 손상된 시스템 파일인 경우도 있습니다. 하드웨어 교체를 고려하기 전에 SFC 결과를 먼저 확인해보세요.

데이터와 시스템을 보호하는 주의사항

메모리 검사가 한 번 통과했다고 즉시 정상으로 단정하지 말고 XMP·EXPO 해제 상태와 모듈별 결과를 비교하세요.

앞 단계로 해결되지 않을 때

모듈을 한 개씩 기본 속도로 장착해 슬롯을 교차하고, 안전 모드와 클린 부팅에서 같은 작업이 재현되는지 확인하세요.

복구, 초기화, 드라이버 제거처럼 되돌리기 어려운 작업 전에는 중요한 파일을 다른 물리 저장장치나 신뢰할 수 있는 백업 위치에 보관하세요.

공식 참고자료

Microsoft Learn: Bug Check 0x1A MEMORY_MANAGEMENT

자주 묻는 질문

  • 블루스크린에 표시되는 첫 번째 값은 무엇인가요? 위반 유형입니다. Microsoft Learn은 0x31·0x403·0x5003을 하드웨어 오류일 가능성이 큰 유형으로, 0x1233·0x4477을 드라이버 문제로 설명합니다. 같은 값이 반복되는지 기록해 두면 원인 범위를 좁히는 데 도움이 됩니다.
  • 메모리 진단을 통과하면 램은 정상인가요? 한 번 통과했다고 램이 정상이라고 단정할 수는 없습니다. 이 항목은 문서 외 일반 안내입니다. XMP를 끈 상태에서도 증상이 반복되는지 함께 확인하세요.
