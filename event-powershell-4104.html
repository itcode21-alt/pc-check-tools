📑 목차

    EVENT ID 4104 · Microsoft-Windows-PowerShell

    대부분 정상 자동화지만 인코딩된 코드는 반드시 확인하세요 확인 필요

    PowerShell 이벤트 4104는 스크립트 블록 로깅 기능이 PowerShell이 컴파일해 실행한 스크립트 블록의 전체 내용을 Microsoft-Windows-PowerShell/Operational 로그에 기록한 것입니다.

    이 기능은 관리자·백업·설치 프로그램의 정상 자동화 스크립트도 그대로 기록하도록 설계되어 있어, 이벤트가 있다는 사실만으로 악성 행위를 의미하지 않습니다. 다만 Base64 인코딩이나 문자열 결합으로 숨겨진 코드, Invoke-Expression·DownloadString·FromBase64String 같은 문구가 포함된 스크립트는 보안 검토가 필요한 신호입니다.

    먼저 구분할 상황

    • 보안 프로그램이 PowerShell 관련 경고를 띄웠다면 경고에 표시된 시각의 4104 이벤트를 먼저 찾습니다.
    • 알 수 없는 예약 작업·시작 프로그램이 있다면 그 항목이 실행하는 PowerShell 명령을 4104 로그에서 대조합니다.
    • 일반적인 관리·설치 작업 뒤라면 대부분 정상 자동화 스크립트이며 급하게 조치할 필요는 낮습니다.

    안전한 점검 순서

    1. 이벤트 설명에서 ScriptBlockId를 확인하고, 같은 ID를 가진 여러 이벤트가 있다면 순서대로 모아 전체 스크립트를 재구성합니다.
    2. Base64 인코딩이나 문자열 결합으로 난독화된 부분이 있으면 디코딩해 실제로 어떤 명령을 실행하는지 확인합니다.
    3. 실행 계정과 부모 프로세스(예약 작업, 서비스, 문서 매크로, 브라우저 등)를 함께 확인합니다.
    4. 같은 시각의 Windows Defender 1116·1117, 프로세스 생성 이벤트(4688)와 대조해 탐지·차단 여부를 확인합니다.
    5. 정상 자동화로 확인되면 별도 조치 없이 넘어가고, 낯선 다운로드·인코딩된 명령이 확인되면 네트워크 연결을 차단하고 전체 검사를 실행합니다.

    하면 안 되는 실수

    4104 이벤트가 많이 쌓여 있다고 스크립트 블록 로깅 자체를 끄지 마세요. 이는 보안 모니터링을 위해 켜져 있는 경우가 많으며, 로깅을 끄는 것은 실제 위협 탐지 능력을 낮추는 결과로 이어질 수 있습니다. 반대로 관리 스크립트가 매일 대량으로 기록된다고 해서 전부 악성으로 의심할 필요도 없습니다.

    즉시 점검이 필요한 경우

    디코딩한 스크립트에 원격 다운로드, 자격 증명 탈취, 방어 프로그램 비활성화 명령이 포함돼 있다면 네트워크 연결을 차단하고 오프라인 검사와 계정 비밀번호 변경을 우선 진행하세요.

    자주 묻는 질문

    • 4104 이벤트가 있으면 무조건 악성코드인가요? 아닙니다. 스크립트 블록 로깅은 PowerShell이 실행하는 모든 스크립트 블록을 기록하도록 설계된 기능이라, 백업·업데이트·설치 프로그램 같은 정상적인 자동화 스크립트도 대량으로 이 이벤트를 남깁니다. 인코딩·난독화 여부와 실제 실행 내용을 함께 봐야 합니다.
    • 긴 스크립트는 왜 여러 이벤트로 나뉘나요? 이벤트 하나에 담을 수 있는 크기 제한 때문에 긴 스크립트 블록은 여러 개의 4104 이벤트로 분할되어 기록됩니다. 같은 ScriptBlockId를 가진 이벤트를 순서대로 이어붙이면 원래의 전체 스크립트를 재구성할 수 있습니다.
    • 내 PC에서 스크립트 블록 로깅을 켜거나 끌 수 있나요? 그룹 정책 편집기의 관리 템플릿 → Windows 구성 요소 → Windows PowerShell에서 '스크립트 블록 로깅 켜기' 설정으로 사용 여부를 조정할 수 있습니다. 다만 보안 모니터링 목적으로 활성화된 경우가 많으므로 조직 PC라면 임의로 끄기 전에 관리자와 상의하세요.
