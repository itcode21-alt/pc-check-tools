📑 목차

에러 코드 상세

0x0000013A · KERNEL_MODE_HEAP_CORRUPTION

커널 모드 힙 관리자가 메모리 힙의 손상을 감지했을 때 나타나는 코드로, 드라이버의 메모리 오용이나 램 결함이 흔한 원인입니다.

이 코드를 어떻게 해석해야 하나요?

이 코드만으로 특정 부품의 고장을 단정할 수는 없습니다. 발생 시점과 재현 조건, 최근 변경 사항, 안전 모드 결과를 함께 기록하면 원인 범위를 좁히는 데 도움이 됩니다.

먼저 기록할 내용: 0x0000013A가 발생한 시각, 직전에 실행한 작업, 최근 설치한 드라이버·업데이트, 재부팅 뒤 같은 코드가 반복되는지를 적어 두세요.

이 코드가 가리키는 것

힙은 커널이 필요할 때마다 할당해 쓰는 메모리 영역입니다. 그 구조가 어긋났다는 것은 어떤 드라이버가 자기 몫을 넘겨 다른 영역을 건드렸을 가능성이 큽니다. 따라서 드라이버가 1순위이고, 메모리 불량이 2순위입니다.

첫 점검 항목

  1. 덤프에서 지목된 드라이버 확인 — C:\Windows\Minidump의 최신 덤프를 열어 원인 모듈로 나온 .sys 파일명을 확인합니다. 같은 파일이 반복해 나온다면 그 드라이버가 유력한 원인입니다.
  2. 최근 업데이트한 드라이버 되돌리기 — 덤프에서 특정 드라이버가 잡히지 않으면 최근에 바꾼 드라이버부터 되돌립니다. 장치 관리자의 드라이버 롤백을 우선 사용하고, 없으면 이전 버전을 직접 설치합니다.
  3. 드라이버 검사기로 원인 좁히기 — 원인이 좁혀지지 않으면 verifier(드라이버 검사기)로 서드파티 드라이버만 대상으로 검사를 걸어 둘 수 있습니다. 검사 중에는 부팅이 불안정해질 수 있으므로 복원 지점을 먼저 만들고, 확인이 끝나면 verifier /reset으로 반드시 해제하세요.
  4. 메모리 진단 실행 — 드라이버 쪽에서 원인이 나오지 않으면 mdsched.exe나 MemTest86으로 메모리를 검사합니다.

확인 결과에 따른 다음 단계

  • 덤프에서 특정 드라이버가 지목될 때 — 그 드라이버를 롤백하거나 최신 버전으로 업데이트하세요.
  • 드라이버 검사기로 원인이 좁혀질 때 — 확인이 끝나면 반드시 verifier /reset으로 해제하세요.
  • 메모리 진단에서 오류가 발견될 때 — 램 모듈을 하나씩 장착해가며 어떤 모듈이 문제인지 확인하세요.

데이터와 시스템을 보호하는 주의사항

원인이 확인되지 않은 상태에서 초기화, 레지스트리 수정, 시스템 파일 수동 교체를 먼저 진행하지 마세요.

앞 단계로 해결되지 않을 때

반복되는 코드가 같다면 이벤트 로그와 장치 상태를 남겨두세요. 코드가 매번 다르다면 메모리·전원·온도 등 시스템 전체 안정성부터 확인하는 것이 순서입니다.

되돌리기 어려운 조치(복구, 초기화, 드라이버 제거 등)에 들어가기 전에는 반드시 중요 데이터를 다른 저장장치로 옮겨 두는 것이 안전합니다.

자주 묻는 질문

  • 블루스크린 코드가 한 번 떴는데 계속 지켜봐야 하나요? 이 문제(0x0000013A)가 한 번만 발생했다면 즉시 부품을 교체하기보다 재현 여부와 최근 변경 사항을 먼저 기록해두는 것으로 충분합니다. 반복된다면 그때 하드웨어 점검 범위를 넓히세요.
  • 덤프 파일은 어디서 확인하나요? C:\Windows\Minidump 폴더에 저장되며, BlueScreenView 같은 도구로 열어 정지 코드와 관련 드라이버를 확인할 수 있습니다.
  • 드라이버 검사기(verifier)가 위험하다고 들었는데 안전한가요? 검사 중 부팅이 불안정해질 수 있으므로 복원 지점을 먼저 만들고, 확인이 끝나면 반드시 verifier /reset으로 해제해야 합니다.
