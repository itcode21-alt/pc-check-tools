📑 목차

에러 코드 상세

0x00000101 · CLOCK_WATCHDOG_TIMEOUT

여러 코어 중 하나가 정해진 시간 안에 클록 인터럽트에 응답하지 않았을 때 나타납니다.

이 코드를 어떻게 해석해야 하나요?

이 코드만으로 특정 부품의 고장을 단정할 수는 없습니다. 발생 시점과 재현 조건, 최근 변경 사항, 안전 모드 결과를 함께 기록하면 원인 범위를 좁히는 데 도움이 됩니다.

먼저 기록할 내용: 0x00000101가 발생한 시각, 직전에 실행한 작업, 최근 설치한 드라이버·업데이트, 재부팅 뒤 같은 코드가 반복되는지를 적어 두세요.

이 코드가 가리키는 것

이 코드는 CPU 안정성과 직접 연결됩니다. 보조 프로세서(코어)가 응답하지 못했다는 뜻이라, 오버클럭이나 전압 부족처럼 CPU가 설정대로 동작하지 못하는 상황에서 자주 나타납니다. 드라이버나 Windows 파일보다 BIOS 설정을 먼저 되돌리는 것이 순서입니다.

첫 점검 항목

  1. 오버클럭과 전압 설정을 기본값으로 — BIOS에서 Load Optimized Defaults를 적용해 CPU 배수·전압·메모리 프로파일을 한 번에 되돌립니다. 이 코드에서 가장 효과가 큰 단계이므로 다른 조치보다 먼저 진행하세요.
  2. 메모리 XMP·EXPO 해제 — 기본값으로 되돌린 뒤에도 재현되면 메모리 프로파일만 따로 꺼 봅니다. 메모리 설정이 CPU 메모리 컨트롤러 안정성에 영향을 주기 때문입니다.
  3. CPU 온도와 전원 상태 확인 — HWiNFO 등으로 부하 중 CPU 온도와 전압을 기록합니다. 온도가 한계에 가깝거나 전압이 크게 흔들리면 쿨러 장착 상태와 파워서플라이를 점검합니다.
  4. BIOS 업데이트 검토 — 특정 CPU 세대에서는 메인보드 BIOS 버전에 따라 안정성 차이가 있습니다. 제조사가 CPU 호환성·안정성 개선을 명시한 BIOS를 배포했다면 적용을 검토하세요.

확인 결과에 따른 다음 단계

  • BIOS 기본값 복원 후 해결될 때 — 재발 여부만 지켜보면 됩니다.
  • XMP·EXPO 해제 후 해결될 때 — 메모리 프로파일을 다시 켜지 말고 기본 속도로 유지하세요.
  • 온도·전압이 정상인데도 반복될 때 — BIOS 업데이트를 검토하거나 CPU 자체 결함 가능성을 확인하세요.

데이터와 시스템을 보호하는 주의사항

원인이 확인되지 않은 상태에서 초기화, 레지스트리 수정, 시스템 파일 수동 교체를 먼저 진행하지 마세요.

앞 단계로 해결되지 않을 때

같은 코드가 재발할 때는 이벤트 로그와 장치 상태 기록을 보관하고, 코드가 그때그때 달라진다면 메모리·전원·발열 같은 전반적인 안정성 문제를 의심해보세요.

시스템 복구나 초기화, 드라이버 삭제처럼 원상복구가 힘든 작업을 시작하기 전에, 중요한 파일은 미리 외장 저장장치나 별도 위치에 백업해 두세요.

자주 묻는 질문

  • 블루스크린 코드가 한 번 떴는데 계속 지켜봐야 하나요? 이 문제(0x00000101)가 한 번만 발생했다면 즉시 부품을 교체하기보다 재현 여부와 최근 변경 사항을 먼저 기록해두는 것으로 충분합니다. 반복된다면 그때 하드웨어 점검 범위를 넓히세요.
  • 덤프 파일은 어디서 확인하나요? C:\Windows\Minidump 폴더에 저장되며, BlueScreenView 같은 도구로 열어 정지 코드와 관련 드라이버를 확인할 수 있습니다.
  • 여러 코어 중 어느 코어가 문제인지 알 수 있나요? 미니덤프를 WinDbg로 분석하면 응답하지 않은 프로세서 번호를 확인할 수 있지만, 실무적으로는 오버클럭·전압을 기본값으로 되돌리는 것이 우선입니다.
