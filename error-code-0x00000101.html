에러 코드 상세

0x00000101 · CLOCK_WATCHDOG_TIMEOUT

보조 프로세서가 클럭 인터럽트를 처리하지 않을 때 나오는 코드입니다. 문서는 보통 해당 프로세서가 응답하지 않거나 교착 상태(deadlock)일 때라고 설명합니다.

이 코드를 어떻게 해석해야 하나요?

시스템은 각 프로세서가 클럭 인터럽트를 제때 처리하는지 감시합니다. 보조 프로세서가 허용 시간 안에 인터럽트를 처리하지 않으면 이 코드로 멈춥니다. Microsoft Learn은 응답하지 않는 프로세서의 번호와 PRCB 주소를 매개변수로 알려 준다고 하고, 해결 절차로 디버거 명령(!analyze, !pcr, !prcb, !irql 등)으로 어떤 코드가 진행을 막는지 찾으라고만 안내합니다. 일반 사용자용 절차는 문서에 없어서 아래 점검은 모두 문서 외 일반 점검입니다.

이 코드가 가리키는 것

원인 후보(문서 설명 기준): 지정된 프로세서가 인터럽트를 처리하지 않는 경우(문서 설명); 프로세서가 응답하지 않거나 교착 상태에 빠진 경우.

첫 점검 항목

  1. 공식 문서가 알려 주는 것: 덤프를 분석할 수 있다면 !analyze, !pcr, !prcb, !irql 같은 명령으로 응답하지 않는 프로세서와 실행 중인 코드를 확인하세요. 문서가 안내하는 유일한 방법입니다.
  2. 문서 외 일반 점검: BIOS에서 CPU 오버클럭, 전압 조정(언더볼팅 포함), 메모리 XMP·EXPO를 기본값으로 되돌려 재현 여부를 확인하세요.
  3. 문서 외 일반 점검: BIOS를 최신으로 업데이트하고, CPU 쿨러와 전원 공급(파워서플라이, 메인보드 전원 커넥터)을 점검하세요.
  4. 문서 외 일반 점검: 최근 설치한 드라이버나 가상화·보안 프로그램을 제거해 보세요.

확인 결과에 따른 다음 단계

  • 전압 조정이나 오버클럭을 끄면 사라질 때 — 기본값에서 안정적인지 며칠 지켜보세요. 이 사이트에는 CPU 언더볼팅 설정을 조정해 해결된 사례가 있지만 문서가 안내하는 방법은 아닙니다.
  • BIOS 업데이트로 사라질 때 — 업데이트한 버전과 날짜를 기록해 두세요. 업데이트 중에는 전원을 끄지 마세요.
  • 기본 설정에서도 반복될 때 — CPU 온도와 전원 공급을 점검하고, 가능하다면 다른 CPU나 메인보드로 교차 테스트하세요. 부품은 한 번에 하나씩만 바꾸세요.

데이터와 시스템을 보호하는 주의사항

원인이 확인되지 않은 상태에서 초기화, 레지스트리 수정, 시스템 파일 수동 교체를 먼저 진행하지 마세요.

앞 단계로 해결되지 않을 때

같은 코드가 재발할 때는 이벤트 로그와 장치 상태 기록을 보관하고, 코드가 그때그때 달라진다면 메모리·전원·발열 같은 전반적인 안정성 문제를 의심해보세요.

시스템 복구나 초기화, 드라이버 삭제처럼 원상복구가 힘든 작업을 시작하기 전에, 중요한 파일은 미리 외장 저장장치나 별도 위치에 백업해 두세요.

자주 묻는 질문

  • 멀티 프로세서 시스템에서만 나오나요? 문서는 이 코드를 멀티 프로세서 시스템의 보조 프로세서 클럭 인터럽트 미수신으로 설명합니다. 오늘의 일반 PC도 여러 코어를 가진 멀티 프로세서 시스템에 해당합니다.
  • CPU가 고장 난 건가요? 문서는 프로세서가 응답하지 않거나 교착 상태일 때라고만 설명하고 CPU 고장을 단정하지 않습니다. 오버클럭·전압 설정, 과열, BIOS 같은 요인을 먼저 가려내는 것이 일반적입니다.
