탐색기 멈춤 원인과 점검 순서

파일 탐색기가 응답하지 않거나 멈추는 경우

탐색기 멈춤은 윈도우 셸이 폴더를 열거나 우클릭 메뉴를 그리는 과정에서 응답을 잃을 때 생깁니다. 파일이 많아서 느린 경우도 있지만, 실제로는 셸 확장, 미리 보기, 네트워크 드라이브 같은 주변 요소가 원인인 경우가 많습니다.

증상이 탐색기에서만 반복된다면 전체 윈도우가 아닌 셸 구성 요소를 먼저 점검하는 것이 좋습니다. 특히 최근 설치한 압축 프로그램, 클라우드 동기화 프로그램, 우클릭 메뉴 추가 도구가 단서가 됩니다.

이 가이드는 폴더 문제와 프로그램 충돌을 구분해 보는 데 초점을 맞춥니다.

원인이 셸 확장인지 아닌지 빠르게 구분하는 방법이 있습니다. Shift를 누른 채 우클릭하면 확장 프로그램이 추가한 항목 없이 기본 메뉴만 뜨는데, 이때는 멈추지 않고 평소처럼 반응한다면 범인은 십중팔구 서드파티 셸 확장입니다. 반대로 Shift+우클릭에서도 똑같이 멈춘다면 탐색기 자체나 시스템 리소스 문제 쪽으로 봐야 합니다.

이 가이드가 필요한 상황

  • 특정 폴더를 열 때만 멈춘다.
  • 우클릭 메뉴가 뜨기 전에 오래 멈춘다.
  • 미리 보기 창을 켜면 더 느려진다.

먼저 확인할 항목

  1. 최근 추가한 셸 확장 확인 — 우클릭 메뉴나 미리 보기 확장은 탐색기와 밀접하게 붙어 있습니다. 최근 설치한 압축 프로그램, 백업 도구, 클라우드 유틸리티를 떠올려 보세요.
  2. 대용량 폴더와 네트워크 드라이브 분리 — 느린 경로가 하나만 있어도 전체 탐색기가 멈춘 것처럼 보일 수 있습니다. 문제가 나는 폴더와 네트워크 위치를 잠시 떼어 놓고 재현 여부를 봅니다.
  3. 썸네일과 미리 보기 확인 — 이미지나 영상이 많은 폴더는 미리 보기 생성에서 멈추는 경우가 있습니다. 미리 보기 창을 끈 상태와 켠 상태를 비교해 보세요.

원인을 더 정확히 나누는 방법

폴더가 아니라 확장 메뉴일 수 있음

같은 폴더라도 우클릭을 할 때만 멈춘다면 파일 자체보다 셸 확장 충돌일 가능성이 높습니다. 탐색기는 정상으로 보이지만, 메뉴를 만드는 확장 프로그램이 뒤에서 시간을 잡아먹는 경우가 있습니다.

확인 결과에 따른 다음 단계

  • 특정 폴더만 느릴 때 — 한 폴더에서만 멈춘다면 셸 확장보다 파일 수, 미리 보기, 네트워크 드라이브 쪽을 먼저 보는 것이 빠릅니다.
  • 우클릭에서만 멈출 때 — 우클릭 직후에만 멈춘다면 압축 프로그램이나 클라우드 동기화 유틸리티처럼 메뉴를 붙이는 프로그램을 먼저 확인하세요.

피해야 할 실수

  • 파일 개수만 원인으로 단정하는 것
  • 네트워크 드라이브를 계속 연결해 둔 채 확인하는 것

자주 묻는 질문

  • 재부팅하면 바로 괜찮아지는데 문제 아닌가요? 재부팅 후 잠시 괜찮아지는 것은 셸 확장 충돌에서도 자주 보입니다. 반복된다면 임시 현상으로 넘기지 말고 어떤 폴더나 프로그램에서 시작되는지 봐야 합니다.
