탐색기 멈춤 원인과 점검 순서

파일 탐색기가 응답하지 않거나 멈추는 경우

탐색기 멈춤은 윈도우 셸이 폴더를 열거나 우클릭 메뉴를 그리는 과정에서 응답을 잃을 때 생깁니다. 파일이 많아서 느린 경우도 있지만, 실제로는 셸 확장, 미리 보기, 네트워크 드라이브 같은 주변 요소가 원인인 경우가 많습니다.

증상이 탐색기에서만 반복된다면 전체 윈도우가 아닌 셸 구성 요소를 먼저 점검하는 것이 좋습니다. 특히 최근 설치한 압축 프로그램, 클라우드 동기화 프로그램, 우클릭 메뉴 추가 도구가 단서가 됩니다.

이 가이드는 폴더 문제와 프로그램 충돌을 구분해 보는 데 초점을 맞춥니다.

원인이 셸 확장인지 아닌지 빠르게 구분하는 방법이 있습니다. Shift를 누른 채 우클릭하면 확장 프로그램이 추가한 항목 없이 기본 메뉴만 뜨는데, 이때는 멈추지 않고 평소처럼 반응한다면 범인은 십중팔구 서드파티 셸 확장입니다. 반대로 Shift+우클릭에서도 똑같이 멈춘다면 탐색기 자체나 시스템 리소스 문제 쪽으로 봐야 합니다.

이 가이드가 필요한 상황

  • 특정 폴더를 열 때만 멈춘다.
  • 우클릭 메뉴가 뜨기 전에 오래 멈춘다.
  • 미리 보기 창을 켜면 더 느려진다.

먼저 확인할 항목

  1. 최근 추가한 셸 확장 확인 — 우클릭 메뉴나 미리 보기 확장은 탐색기와 밀접하게 붙어 있습니다. 최근 설치한 압축 프로그램, 백업 도구, 클라우드 유틸리티를 떠올려 보세요.
  2. 대용량 폴더와 네트워크 드라이브 분리 — 느린 경로가 하나만 있어도 전체 탐색기가 멈춘 것처럼 보일 수 있습니다. 문제가 나는 폴더와 네트워크 위치를 잠시 떼어 놓고 재현 여부를 봅니다.
  3. 썸네일과 미리 보기 확인 — 이미지나 영상이 많은 폴더는 미리 보기 생성에서 멈추는 경우가 있습니다. 미리 보기 창을 끈 상태와 켠 상태를 비교해 보세요.

원인을 더 정확히 나누는 방법

폴더가 아니라 확장 메뉴일 수 있음

같은 폴더라도 우클릭을 할 때만 멈춘다면 파일 자체보다 셸 확장 충돌일 가능성이 높습니다. 탐색기는 정상으로 보이지만, 메뉴를 만드는 확장 프로그램이 뒤에서 시간을 잡아먹는 경우가 있습니다.

검색 인덱서가 디스크를 점유하는 경우

Windows 검색 인덱서(SearchIndexer.exe)가 대량의 파일을 색인하는 동안에는 디스크 읽기가 몰려 탐색기 응답이 늦어질 수 있습니다. Ctrl+Shift+Esc로 작업 관리자를 열어 'Microsoft Windows Search Indexer'의 디스크 사용량이 계속 높은지 확인하면 구분할 수 있고, 큰 폴더를 새로 복사한 직후라면 색인이 끝날 때까지 기다리는 것만으로 좋아지기도 합니다.

연결된 저장장치 한 개가 전체를 붙잡는 경우

탐색기는 '내 PC'를 열 때 연결된 모든 드라이브의 상태를 읽습니다. 오류가 있는 외장하드나 접촉이 불안정한 USB 메모리가 하나만 끼워져 있어도 그 응답을 기다리느라 탐색기 전체가 멈춘 것처럼 보일 수 있습니다. 외장 저장장치를 모두 분리한 뒤 같은 동작을 해 보면 원인이 장치인지 탐색기인지 가를 수 있습니다.

빠른 실행에 고정된 끊어진 경로

탐색기를 열자마자 멈추거나 '빠른 실행' 목록이 한참 뒤에 나타난다면, 목록에 고정해 둔 폴더나 최근 항목 중 지금은 닿지 않는 경로가 있는지 의심해 보세요. 탐색기는 시작할 때 이 목록의 항목 상태를 확인하는데, 꺼진 NAS나 분리한 외장하드, 접속이 끊긴 공유폴더가 걸려 있으면 응답 대기 시간이 그대로 멈춤으로 보입니다. 빠른 실행의 해당 항목을 우클릭해 '빠른 실행에서 제거'를 누르고, 파일 탐색기 옵션(폴더 옵션)의 '개인 정보 보호'에서 '지우기'로 탐색기 기록을 비운 뒤 다시 열어 비교하세요. 이 방법은 파일 자체가 아니라 목록이 원인인 경우를 가려내는 데 쓰입니다.

확인 결과에 따른 다음 단계

  • 특정 폴더만 느릴 때 — 한 폴더에서만 멈춘다면 셸 확장보다 파일 수, 미리 보기, 네트워크 드라이브 쪽을 먼저 보는 것이 빠릅니다.
  • 우클릭에서만 멈출 때 — 우클릭 직후에만 멈춘다면 압축 프로그램이나 클라우드 동기화 유틸리티처럼 메뉴를 붙이는 프로그램을 먼저 확인하세요.

피해야 할 실수

  • 파일 개수만 원인으로 단정하는 것
  • 네트워크 드라이브를 계속 연결해 둔 채 확인하는 것
  • 멈춘 화면에서 기다리지 않고 바로 전원 버튼으로 강제 종료를 반복하는 것
  • 빠른 실행에 고정한 NAS·외장하드 항목이 끊긴 상태인지 보지 않는 것

자주 묻는 질문

  • 재부팅하면 바로 괜찮아지는데 문제 아닌가요? 재부팅 후 잠시 괜찮아지는 것은 셸 확장 충돌에서도 자주 보입니다. 반복된다면 임시 현상으로 넘기지 말고 어떤 폴더나 프로그램에서 시작되는지 봐야 합니다.
  • 탐색기가 멈추면 항상 재부팅해야 하나요? 작업 관리자에서 '탐색기' 프로세스만 다시 시작해도 대부분 해결되며, 재부팅 없이 빠르게 복구할 수 있습니다. 작업 관리자의 프로세스 탭에서 "Windows 탐색기"를 우클릭하고 "다시 시작"을 누릅니다(찾기 어려우면 위쪽 검색창에 "탐색기"를 입력). 다시 시작하는 동안 작업표시줄과 열려 있는 탐색기 창이 잠깐 사라졌다가 돌아옵니다. 아래는 우클릭 메뉴가 열린 화면입니다.
  • 특정 폴더에서만 멈추는 경우는 원인이 다른가요? 네, 특정 폴더에서만 멈춘다면 해당 폴더 내 파일 인덱싱이나 미리보기 생성 문제일 가능성이 높아 인덱싱 옵션을 점검해야 합니다.
  • '내 PC'나 '이 PC'를 열 때만 멈추는 건 어떤 원인이 많나요? '이 PC'는 연결된 모든 드라이브와 네트워크 위치의 상태를 읽어 오기 때문에, 응답이 느린 드라이브나 끊어진 네트워크 드라이브가 하나만 있어도 멈춤으로 이어질 수 있습니다. 외장 장치를 분리하고 네트워크 드라이브 연결을 끊은 뒤 다시 확인해 보세요.
