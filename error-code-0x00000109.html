에러 코드 상세

0x00000109 · CRITICAL_STRUCTURE_CORRUPTION

커널이 중요한 커널 코드나 데이터 구조가 변조된 것을 감지했을 때 나타나는 코드로, 드라이버의 커널 영역 침범이나 메모리 손상이 흔한 원인입니다.

이 코드를 어떻게 해석해야 하나요?

이 코드만으로 특정 부품의 고장을 단정할 수는 없습니다. 발생 시점과 재현 조건, 최근 변경 사항, 안전 모드 결과를 함께 기록하면 원인 범위를 좁히는 데 도움이 됩니다.

먼저 기록할 내용: 0x00000109가 발생한 시각, 직전에 실행한 작업, 최근 설치한 드라이버·업데이트, 재부팅 뒤 같은 코드가 반복되는지를 적어 두세요.

이 코드가 가리키는 것

Windows는 커널의 핵심 영역이 변조되면 이를 감지해 즉시 중단시킵니다. 따라서 이 코드는 정상적인 소프트웨어 동작으로는 잘 나오지 않습니다. 커널에 개입하는 프로그램(치트 방지 모듈, 일부 보안 소프트웨어, 시스템 후킹 도구)이나 메모리 불량이 주된 원인입니다.

첫 점검 항목

  1. 커널에 개입하는 프로그램 정리 — 치트 방지 모듈이 포함된 게임, 시스템 감시·후킹 도구, 서로 다른 백신 두 개가 함께 설치돼 있는지 확인합니다. 최근 설치한 순서대로 하나씩 제거하며 재현 여부를 봅니다.
  2. 메모리 진단 실행 — mdsched.exe로 검사하고, 이상이 없는데도 반복되면 MemTest86으로 여러 회차 확인합니다. 커널 데이터 손상은 메모리 불량으로도 충분히 발생합니다.
  3. 오버클럭 해제 — CPU·메모리 오버클럭과 XMP를 모두 끄고 기본값에서 재현되는지 확인합니다. 불안정한 설정에서 계산 결과가 어긋나면 커널 데이터 손상으로 이어질 수 있습니다.
  4. 시스템 파일 검사 — 관리자 명령 프롬프트에서 sfc /scannow를 실행하고, 복구되지 않으면 DISM /Online /Cleanup-Image /RestoreHealth 후 다시 실행합니다.

데이터와 시스템을 보호하는 주의사항

정확한 원인을 파악하기 전에 초기화나 레지스트리 수정, 시스템 파일 수동 교체부터 시도하지 않는 것이 좋습니다.

앞 단계로 해결되지 않을 때

코드가 매번 동일하게 반복된다면 이벤트 로그와 장치 상태를 기록해두고, 코드가 바뀐다면 메모리·전원·온도처럼 시스템 전체의 안정성을 먼저 살펴보세요.

복구, 초기화, 드라이버 제거처럼 되돌리기 어려운 작업 전에는 중요한 파일을 다른 물리 저장장치나 신뢰할 수 있는 백업 위치에 보관하세요.

자주 묻는 질문

  • 블루스크린 코드가 한 번 떴는데 계속 지켜봐야 하나요? 이 문제(0x00000109)가 한 번만 발생했다면 즉시 부품을 교체하기보다 재현 여부와 최근 변경 사항을 먼저 기록해두는 것으로 충분합니다. 반복된다면 그때 하드웨어 점검 범위를 넓히세요.
  • 덤프 파일은 어디서 확인하나요? C:\Windows\Minidump 폴더에 저장되며, BlueScreenView 같은 도구로 열어 정지 코드와 관련 드라이버를 확인할 수 있습니다.
