에러 코드 상세

0x00000109 · CRITICAL_STRUCTURE_CORRUPTION

커널이 중요한 커널 코드나 데이터가 손상되었음을 감지했을 때 나오는 코드입니다. 문서는 원인을 세 가지로 설명합니다. 드라이버의 커널 수정, 연결되지 않은 디버거에서의 일반 중단점 설정, 하드웨어 손상입니다.

이 코드를 어떻게 해석해야 하나요?

문서가 드는 일반적인 원인은 세 가지입니다. 첫째, 드라이버가 실수로나 의도적으로 중요한 커널 코드나 데이터를 수정한 경우입니다. x64용 Windows는 Microsoft가 만든 핫 패치를 제외하고 커널 패치를 허용하지 않습니다. 둘째, 개발자가 시작 때 연결되지 않은 커널 디버거로 일반 중단점(bp)을 건 경우입니다. 셋째, 커널 코드나 데이터가 저장된 메모리가 고장 나는 등 하드웨어 손상이 생긴 경우입니다. 해결 절차는 디버거로 스택 추적을 보는 것뿐이라 일반 사용자용 점검은 대부분 문서 외 일반 점검입니다.

이 코드가 가리키는 것

원인 후보(문서 설명 기준): 드라이버가 중요한 커널 코드나 데이터를 수정한 경우(문서가 가장 먼저 드는 원인); 개발 환경에서 시작 때 연결되지 않은 커널 디버거로 일반 중단점을 설정한 경우; 커널 코드나 데이터가 저장된 메모리가 고장 나는 하드웨어 손상.

첫 점검 항목

  1. 공식 문서가 알려 주는 것: 덤프를 분석할 수 있다면 !analyze와 스택 추적으로 손상된 영역과 관련 코드를 확인하세요. 네 번째 매개변수가 손상된 영역의 종류를 알려 줍니다.
  2. 문서 외 일반 점검: 메모리 진단 도구(mdsched.exe 또는 MemTest86+)로 램을 점검하고, XMP·EXPO와 오버클럭을 기본값으로 되돌려 보세요.
  3. 문서 외 일반 점검: 최근 설치한 드라이버, 특히 커널 수준으로 동작하는 보안·최적화·가상화·게임 안티치트 프로그램의 드라이버를 제거하거나 최신으로 업데이트하세요.
  4. 문서 외 일반 점검: sfc /scannow로 시스템 파일을 점검하고, 가능하다면 안전 모드에서 재현되는지 비교하세요.

확인 결과에 따른 다음 단계

  • 메모리 진단에서 오류가 나올 때 — 문서가 하드웨어 손상을 세 번째 원인으로 듭니다. 램 모듈을 하나씩 꽂아 불량 모듈을 가려내고 보증 기간 안에 교체를 신청하세요. 모듈 분리는 문서 외 일반 조치입니다.
  • 특정 드라이버나 보안 프로그램을 제거하면 사라질 때 — 문서는 드라이버가 커널 코드를 수정하는 것을 가장 먼저 드는 원인으로 설명합니다. 그 프로그램은 최신 버전으로 다시 설치하거나 제조사에 문의하세요. 이 사이트에는 코어 격리와 충돌한 드라이버를 업데이트해 해결된 사례가 있습니다.
  • 안전 모드에서는 재현되지 않을 때 — 문서 외 일반 점검으로, 안전 모드에서 최근 설치한 프로그램과 드라이버를 하나씩 제거하며 재현이 멈추는 시점을 찾으세요.

데이터와 시스템을 보호하는 주의사항

정확한 원인을 파악하기 전에 초기화나 레지스트리 수정, 시스템 파일 수동 교체부터 시도하지 않는 것이 좋습니다.

앞 단계로 해결되지 않을 때

코드가 매번 동일하게 반복된다면 이벤트 로그와 장치 상태를 기록해두고, 코드가 바뀐다면 메모리·전원·온도처럼 시스템 전체의 안정성을 먼저 살펴보세요.

복구, 초기화, 드라이버 제거처럼 되돌리기 어려운 작업 전에는 중요한 파일을 다른 물리 저장장치나 신뢰할 수 있는 백업 위치에 보관하세요.

자주 묻는 질문

  • 이 코드는 바이러스 때문인가요? 문서는 바이러스를 원인으로 언급하지 않습니다. 원인으로 설명하는 것은 드라이버의 커널 수정, 연결되지 않은 디버거의 중단점 설정, 하드웨어 손상 세 가지입니다.
  • 네 번째 매개변수는 무엇인가요? 손상된 영역의 종류입니다. 문서는 일반 데이터 영역, 함수 수정, 프로세서 IDT·GDT, 프로세스 목록 손상, 디버그 루틴 수정, 중요한 MSR 수정, 시스템 서비스 함수 수정 등으로 나눕니다.
