EVENT ID 161

Volmgr 이벤트 161 크래시 덤프 저장 실패 점검

블루스크린이나 시스템 중단 뒤 크래시 덤프를 저장하는 과정이 실패했음을 기록합니다. 이 이벤트는 원인이라기보다 장애 분석에 필요한 덤프가 남지 않은 이유를 보여주는 경우가 많습니다.

161은 블루스크린이나 시스템 중단 뒤 크래시 덤프를 저장하는 데 실패했다는 기록입니다. 중단의 원인이라기보다 분석용 덤프가 남지 않은 이유를 알려 주는 기록인 경우가 많습니다.

덤프가 남지 않으면 미니덤프 분석기로 볼 자료가 없으니, 페이지 파일 설정과 시스템 드라이브 여유 공간을 먼저 확인하세요. 같은 시각의 BugCheck 1001, Kernel-Power 41, WHEA 기록과 함께 보면 흐름을 알 수 있습니다.

발생 조건

  • 블루스크린 뒤 미니덤프가 생성되지 않음
  • Kernel-Power 41 직전에 기록됨
  • 덤프 파일 생성 실패 문구 표시

가능성 높은 원인

  • 페이지 파일이 없거나 덤프 저장에 충분하지 않은 경우
  • 덤프를 저장할 시스템 드라이브 공간 부족
  • 저장장치 오류·부팅 디스크 접근 실패
  • 예기치 않은 전원 차단으로 덤프 기록이 끝나지 않은 경우

점검 순서

  1. C:\Windows\Minidump와 C:\Windows\MEMORY.DMP 생성 여부 확인 — 되돌리기 쉬운 항목부터 확인해 위험 없이 범위를 줄입니다.
  2. 시스템 속성의 시작 및 복구에서 디버깅 정보 기록과 페이지 파일 설정 확인 — 첫 확인 결과와 비교해 원인 후보를 좁힙니다.
  3. 시스템 드라이브 여유 공간과 Disk·Ntfs·storport 이벤트 비교 — 이 단계에서도 재현되면 다음 항목으로 넘어가세요.
  4. 같은 시각의 BugCheck 1001·Kernel-Power 41·WHEA 기록 확인 — 변경 전후로 증상이 달라지는지 비교해보세요.
  5. 덤프가 생성된 경우 미니덤프 분석기로 원인 드라이버를 별도 확인 — 여기까지 확인해도 해결되지 않으면 다음 원인을 검토하세요.
주의사항

161만으로 GPU·PSU·저장장치 고장을 확정하지 마세요. 덤프 생성 실패와 실제 중단 원인을 분리해야 합니다.

저장장치 오류가 함께 있으면 덤프 설정을 바꾸기 전에 중요한 파일을 먼저 백업하세요.

자주 묻는 질문

  • 161이 있으면 SSD가 고장난 건가요? 그렇게 단정할 수 없습니다. 페이지 파일이 없거나 공간이 부족해도, 전원이 갑자기 끊겨 기록이 끝나지 않아도 남습니다. 저장장치 이벤트(Disk, Ntfs)가 함께 있는지 확인하세요.
  • 덤프를 남기려면 무엇을 확인하나요? 시스템 속성의 시작 및 복구에서 디버깅 정보 기록과 페이지 파일 설정을 확인하고, 시스템 드라이브에 여유 공간을 확보하세요.
