EVENT ID 137

Ntfs 이벤트 137 트랜잭션 리소스 관리자 시작 실패 점검

NTFS 볼륨의 기본 트랜잭션 리소스 관리자가 재시도할 수 없는 오류로 시작하지 못했다는 기록입니다. 이벤트 데이터에 오류 코드가 들어 있어, 볼륨 손상·쓰기 불가 볼륨·스냅샷이나 백업과의 상호작용을 구분해야 합니다.

137은 NTFS가 볼륨의 기본 트랜잭션 리소스 관리자를 시작하지 못했다는 기록입니다. 메시지만으로는 원인을 알 수 없어 이벤트 데이터의 오류 코드와 볼륨 종류를 함께 봐야 합니다.

백업·가상화 업체의 문서에는 스냅샷이나 백업 직후 50·57·137·140이 함께 남는 사례가 정리돼 있습니다. 같은 시각에 파일 시스템 손상 기록(55·57·140)이 있다면 저장장치 쪽을, 스냅샷·백업 시각과 겹친다면 그쪽을 먼저 의심하세요.

발생 조건

  • 부팅·종료 때 같은 볼륨에서 반복
  • 가상 머신 스냅샷이나 백업 직후
  • 램디스크·외장 볼륨 같은 특수 볼륨에서 발생

가능성 높은 원인

  • 볼륨 파일 시스템 손상 또는 저장장치 오류
  • 읽기 전용·쓰기 불가 상태이거나 램디스크 같은 특수 볼륨
  • 백업·스냅샷 작업이 볼륨 접근을 일시적으로 막은 경우

점검 순서

  1. 이벤트 본문에서 볼륨 이름과 데이터의 오류 코드 기록 — 되돌리기 쉬운 항목부터 확인해 위험 없이 범위를 줄입니다.
  2. 같은 시각의 Ntfs 55·57·140, Disk 7·11·153 기록과 비교 — 첫 확인 결과와 비교해 원인 후보를 좁힙니다.
  3. 볼륨이 램디스크·외장·가상 디스크인지 확인 — 이 단계에서도 재현되면 다음 항목으로 넘어가세요.
  4. 옵션 없이 실행하는 chkdsk(읽기 전용 검사) 결과 확인 — 변경 전후로 증상이 달라지는지 비교해보세요.
  5. 백업·스냅샷 일정과 발생 시각 대조 — 여기까지 확인해도 해결되지 않으면 다음 원인을 검토하세요.
주의사항

저장장치 오류가 의심되면 chkdsk /f를 실행하기 전에 백업부터 하세요.

램디스크처럼 원인이 분명한 볼륨이고 기능 문제가 없다면 관찰 대상일 수 있습니다.

자주 묻는 질문

  • 137이 부팅마다 뜨는데 위험한가요? 같은 볼륨에서 매번 남고 파일 오류가 없다면 램디스크 같은 특수 볼륨 때문일 수 있습니다. 파일 접근 오류나 다른 저장장치 기록이 함께 있다면 저장장치 점검으로 넘어가세요.
  • chkdsk를 바로 실행해도 되나요? 저장장치 오류가 의심되면 먼저 백업하세요. 옵션 없이 실행하는 검사는 읽기 전용이라 비교적 안전하지만, 복구 옵션(/f)은 상태가 나쁜 장치에 부담이 될 수 있습니다.
