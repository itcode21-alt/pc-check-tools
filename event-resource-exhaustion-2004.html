Resource-Exhaustion-Detector 2004 가상 메모리 부족 점검

Windows가 시스템의 가상 메모리·커밋 한도가 부족한 상태를 진단했다는 경고입니다. 이벤트 설명에는 당시 커밋 메모리를 많이 사용한 프로세스가 포함될 수 있어, 단순한 RAM 사용률보다 커밋 크기와 페이지 파일을 확인해야 합니다.

2004는 Windows가 시스템의 가상 메모리·커밋 한도가 부족한 상태를 진단했다는 경고입니다. 이벤트 설명에 당시 상위 커밋 사용 프로세스가 표시될 수 있으므로, RAM 사용률만 보지 말고 커밋 크기와 페이지 파일을 함께 확인해야 합니다.

특정 프로그램을 오래 실행할수록 커밋 사용량이 계속 증가한다면 앱이나 플러그인의 누수를 의심할 수 있습니다. 여러 프로그램에서 동시에 발생하면 페이지 파일과 시스템 여유 공간부터 확인하세요.

발생 조건

  • 프로그램이 갑자기 종료되거나 응답하지 않음
  • 게임·브라우저·가상 머신을 오래 실행한 뒤 메모리 부족
  • 작업 관리자에서 커밋 사용량이 한도에 가까움

가능성 높은 원인

  • 특정 프로그램·서비스의 가상 메모리 누수
  • 페이지 파일이 꺼졌거나 크기가 지나치게 제한된 경우
  • 여러 대형 프로그램을 동시에 실행해 커밋 한도를 초과한 경우
  • RAM 부족이 페이지 파일 사용 증가와 함께 나타난 경우

점검 순서

  1. 이벤트 설명에서 당시 상위 메모리 사용 프로세스와 사용량을 기록 — 되돌리기 쉬운 항목부터 확인해 위험 없이 범위를 줄입니다.
  2. 작업 관리자 성능·메모리에서 커밋 사용량과 커밋 한도를 확인 — 첫 확인 결과와 비교해 원인 후보를 좁힙니다.
  3. 설정의 페이지 파일이 자동 관리인지와 시스템 드라이브 여유 공간 확인 — 앞 단계에서 해결되지 않을 때 다음 원인을 검증합니다.
  4. 같은 프로그램이 재실행할수록 커밋을 계속 늘리는지 작업 관리자에서 비교 — 앞 단계에서 해결되지 않을 때 다음 원인을 검증합니다.
  5. 프로그램 업데이트·플러그인 제거·재시작으로 재현 여부를 나누고 여러 앱에서 반복되면 메모리 진단을 검토 — 앞 단계에서 해결되지 않을 때 다음 원인을 검증합니다.
주의사항

2004는 곧바로 RAM 불량을 뜻하지 않습니다. 이벤트가 지목한 프로세스와 커밋 크기를 먼저 확인하세요.

메모리 부족 상태에서 무거운 작업을 계속하면 저장하지 않은 데이터가 손실될 수 있으므로 작업을 먼저 저장하세요.
