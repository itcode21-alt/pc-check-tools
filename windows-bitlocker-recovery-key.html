📑 목차

    부팅

    BitLocker 복구 키(48자리) 입력 화면이 뜸 원인과 점검 순서

    부팅할 때 파란 화면에서 BitLocker 복구 키 48자리를 입력하라고 요구해 Windows로 들어가지 못하는 경우

    컴퓨터를 켰는데 Windows 로고 대신 BitLocker 복구 화면이 뜨고 48자리 숫자를 입력하라고 하는 경우가 있습니다. Microsoft 안내는 복구 키를 'BitLocker가 드라이브를 자동으로 잠금 해제하지 못할 때 필요한 48자리 숫자'로 설명합니다. 고장이 아니라 암호화된 드라이브를 보호하려고 BitLocker가 일부러 멈춘 상태입니다.

    이 화면이 뜨는 계기는 Microsoft 문서의 복구 시나리오 목록에 정리되어 있습니다. BIOS·UEFI 펌웨어 업그레이드, TPM 끄기·비활성화·지우기, 새 TPM이 달린 마더보드로 교체, 부팅 관리자 변경, 디스크의 NTFS 파티션 테이블 변경, 잘못된 PIN 반복 입력, 암호화된 드라이브를 새 컴퓨터로 옮기는 경우 등입니다.

    핵심은 복구 키가 어디에 저장되어 있는지입니다. 키를 찾으면 입력만으로 Windows로 들어갈 수 있지만, 찾지 못하면 Microsoft 지원팀도 분실된 키를 찾아 주거나 다시 만들어 줄 수 없다고 Microsoft가 밝히고 있습니다. 이 가이드는 키를 찾는 위치와 순서, 입력한 뒤에 해 둘 일, 같은 일을 다시 겪지 않는 방법을 Microsoft 공식 문서 기준으로 정리합니다.

    이 가이드가 필요한 상황

    • 부팅 직후 BitLocker 복구 화면이 표시되고 복구 키 입력을 요구한다.
    • 화면에 복구 키 ID가 함께 표시된다.
    • BIOS 업데이트, 하드웨어 교체, 부팅 설정 변경 직후부터 이 화면이 나온다.

    먼저 확인할 항목

    1. 복구 키 ID 앞 8자리 적어 두기 — 복구 키는 한 PC에 여러 개일 수 있어서, 화면에 표시된 키 ID와 같은 키를 써야 합니다. Microsoft 안내도 키 ID의 처음 8자리를 먼저 적어 두라고 합니다. ① 화면에 표시된 복구 키 ID를 휴대폰으로 찍거나 종이에 적으세요. ② 앞 8자리만 있어도 키 목록에서 맞는 항목을 고를 수 있습니다. ③ 아직 PC를 여러 번 껐다 켜거나 설정을 건드리지 말고 아래 위치에서 같은 ID의 키를 찾으세요.
    2. Microsoft 계정에 저장된 키 찾기 — 개인용 PC는 장치 암호화나 BitLocker를 켤 때 복구 키가 로그인한 Microsoft 계정에 저장되는 경우가 많습니다. Microsoft 안내가 가장 먼저 확인하라고 하는 위치입니다. ① 휴대폰이나 다른 PC의 브라우저에서 aka.ms/myrecoverykey에 접속하세요. ② 그 PC에 로그인하던 Microsoft 계정으로 로그인하세요. PC를 설정해 준 사람이 다른 계정을 썼을 수도 있습니다. ③ 목록에서 화면의 키 ID와 같은 항목의 48자리 키를 확인하세요. Windows 11 24H2부터는 복구 화면에 키가 연결된 Microsoft 계정의 힌트가 표시된다고 Microsoft가 안내합니다.
    3. 회사·학교 계정과 관리자 확인 — 회사나 학교에서 받은 PC는 키가 조직 계정(Microsoft Entra ID)이나 Active Directory에 저장됩니다. 개인 Microsoft 계정에는 없습니다. ① 다른 기기에서 aka.ms/aadrecoverykey에 접속해 조직 계정으로 로그인하세요. ② 디바이스 목록에서 해당 PC를 고르고 'BitLocker 키 보기'를 눌러 키 ID로 찾으세요. ③ 접근이 어렵다면 조직의 IT 지원팀에 키 조회를 요청하세요.
    4. 인쇄물·USB·저장 파일 확인 — BitLocker를 직접 켰다면 키를 인쇄하거나 USB, 파일로 저장하도록 안내받았을 수 있습니다. ① PC 관련 중요 서류 보관함에서 키 ID와 키가 함께 적힌 인쇄물을 찾아보세요. ② USB에 저장했다면 잠긴 PC에 연결하고 화면 안내를 따르세요. USB의 복구 키 파일 이름은 <보호기 ID>.bek 형식입니다. ③ 텍스트 파일로 저장했다면 다른 기기에서 열어 키 ID가 같은지 확인하세요. Microsoft 안내는 키를 저장하는 파일을 PC 자체가 아닌 곳(네트워크 폴더 등)에 두라고 합니다.
    5. Windows에 들어간 뒤 보호 상태 확인 — 키로 들어갔다고 원인이 해결된 것은 아닙니다. 보호 상태와 키 보호기를 확인해 두어야 같은 화면이 다시 나올지 판단할 수 있습니다. ① 화면에 복구 키를 입력해 Windows로 들어가세요. ② 관리자 권한 명령 프롬프트에서 manage-bde -status 를 실행해 보호 상태(Protection On)와 잠금 상태를 확인하세요. PowerShell에서는 Get-BitLockerVolume C: | fl 로도 볼 수 있습니다. ③ manage-bde -protectors -get C: 로 이 드라이브의 보호기(TPM, 숫자 암호 등)를 확인하세요. 문서 외 일반 점검: 이 화면이 나오기 직전에 바꾼 BIOS 설정이나 부품이 있다면 적어 두세요.
    6. 사용한 복구 암호 새로 만들기 — Microsoft 문서는 복구 암호를 사용한 뒤에는 그 암호를 무효화하고 새로 만들 것을 권장합니다. 한 번 화면에 입력된 키는 다른 사람이 볼 수도 있기 때문입니다. ① 관리자 권한 명령 프롬프트에서 manage-bde.exe -protectors -delete C: -type RecoveryPassword 로 기존 복구 암호 보호기를 제거하세요. ② manage-bde.exe -protectors -add C: -RecoveryPassword 로 새 복구 암호를 만드세요. ③ manage-bde.exe -protectors -get C: -Type RecoveryPassword 로 새 ID와 숫자 암호를 확인하고 안전한 곳에 저장하세요. 조직 PC는 정책에 따라 키가 자동 백업될 수 있으니 임의로 바꾸지 말고 IT 관리자에게 확인하세요.
    7. 계획된 BIOS·펌웨어 변경 전에는 BitLocker 일시 중단 — Microsoft 문서는 알려진 하드웨어·펌웨어 업그레이드 같은 계획된 변경에서는 BitLocker 보호를 일시 중단해 복구 화면을 피하라고 안내합니다. 일시 중단하면 드라이브는 암호화된 상태로 남고 키 입력 없이 암호화 키가 다시 봉인됩니다. ① BIOS 업데이트나 TPM·마더보드 관련 변경 직전에 관리자 권한 PowerShell에서 Suspend-BitLocker -MountPoint C 를 실행하세요. 명령 프롬프트에서는 manage-bde.exe -protectors -disable C: 입니다. ② 업데이트와 재부팅을 마치세요. 문서에 따르면 재부팅 횟수를 따로 지정하지 않으면 다시 부팅할 때 BitLocker가 자동으로 보호를 재개합니다. ③ 직접 재개하려면 Resume-BitLocker -MountPoint C 또는 manage-bde.exe -protectors -enable C: 를 쓰세요. ④ manage-bde -status 로 보호가 켜졌는지 확인하세요.

    원인을 더 정확히 나누는 방법

    장치 암호화와 BitLocker는 같은 것인가

    Microsoft 안내에 따르면 BitLocker 드라이브 암호화는 Windows Pro, Enterprise, Education에서 쓸 수 있고, 장치 암호화는 Windows Home을 포함한 더 많은 장치에서 BitLocker 암호화를 자동으로 켜 주는 기능입니다. Microsoft 계정이나 회사·학교 계정으로 처음 로그인하거나 설정할 때 장치 암호화가 켜지고, 이때 복구 키가 그 계정에 연결됩니다. 로컬 계정만 쓰면 장치 암호화가 자동으로 켜지지 않습니다. 그래서 Home 에디션 노트북에서도 복구 화면을 만날 수 있고, 키는 처음 로그인한 계정에 있을 가능성이 큽니다. 설정 앱의 암호화 항목이나 ms-settings:deviceencryption 바로 가기로 상태를 볼 수 있습니다.

    복구 암호·복구 키·키 패키지의 차이

    복구 암호는 복구 모드에서 볼륨을 풀 때 쓰는 48자리 숫자입니다. 복구 키는 이동식 미디어에 저장된 암호화 키로 파일 이름이 <보호기 ID>.bek 형식입니다. 키 패키지는 손상된 드라이브의 일부를 복구 도구로 해독할 때 쓰는 별도 키로 자동 생성되지 않습니다. 이 가이드에서 '복구 키 48자리'는 이 중 48자리 복구 암호를 가리키며, Microsoft 지원 문서도 복구 키를 48자리 숫자로 설명합니다.

    Windows 복구 환경(WinRE)에서도 키를 요구할 수 있다

    Microsoft 문서에 따르면 부팅 실패가 두 번 이어지면 시작 복구가 자동으로 실행됩니다. Windows 복구 환경이 변경되었거나(예: TPM이 꺼진 경우) 복구 디스크에서 수동으로 들어간 경우에는 BitLocker로 보호된 드라이브를 풀려면 복구 키를 입력해야 합니다. 또 TPM+PIN이나 암호를 쓰는 OS 드라이브에서 모든 항목 제거로 초기화를 시작할 때도 키를 요구합니다. 복구 환경 화면에는 내레이터(WIN+CTRL+Enter)와 화상 키보드 같은 접근성 도구가 있습니다.

    키를 끝내 찾지 못한 경우

    Microsoft 안내는 키를 찾을 수 없고 되돌릴 수 없는 변경이 있었다면 Windows 복구 옵션으로 PC를 초기화해야 할 수 있다고 하며, 초기화하면 모든 파일이 삭제된다고 경고합니다. 조직에서 관리하는 PC라면 먼저 IT 부서에 키 조회를 요청하세요. 고객 PC를 점검하는 경우에는 키 없이 데이터를 살려 드릴 수 없다는 점과 초기화 시 데이터가 사라진다는 점을 작업 전에 알리고 동의를 받으세요.

    확인 결과에 따른 다음 단계

    • Microsoft 계정에서 키 ID가 같은 키를 찾았을 때 — 48자리 키를 입력해 들어간 뒤 manage-bde -status 로 상태를 확인하고, 사용한 복구 암호는 새로 만들어 두세요. 이후 BIOS 변경 전에는 BitLocker를 일시 중단하세요.
    • 로그인하던 계정에 키가 없을 때 — PC를 설정한 사람이 쓴 다른 Microsoft 계정, 회사·학교 계정(aka.ms/aadrecoverykey), 인쇄물, USB, 저장 파일 순서로 확인하세요. 조직 PC라면 IT 관리자에게 조회를 요청하세요.
    • 키를 입력했는데 다음 부팅에서 또 화면이 뜰 때 — BIOS 설정이나 부팅 순서, TPM 설정이 계속 바뀌고 있는지 확인하세요. 문서 외 일반 점검: 최근 바꾼 설정을 되돌려 보고, 원인이 보이지 않으면 PC 제조사나 전문가에게 점검을 요청하세요.
    • 키를 끝내 찾지 못했고 데이터가 중요할 때 — 임의로 초기화하지 말고 키 저장 가능성이 있는 계정과 서류를 한 번 더 확인하세요. 그래도 없다면 초기화 말고는 방법이 없고 파일은 사라진다는 점을 감안해 결정하세요.

    피해야 할 실수

    • 복구 키 ID를 확인하지 않고 여러 PC의 키를 섞어 입력해 보는 것
    • 키를 PC 안의 파일로만 저장해 두는 것(PC가 못 켜지면 읽을 수 없습니다)
    • BIOS 업데이트 전에 BitLocker를 일시 중단하지 않는 것
    • 여러 Microsoft 계정 중 한 곳만 확인하고 키가 없다고 단정하는 것

    자주 묻는 질문

    • BitLocker 복구 키는 어디서 확인하나요? Microsoft 안내 기준으로 Microsoft 계정은 aka.ms/myrecoverykey, 회사·학교 계정은 aka.ms/aadrecoverykey에서 다른 기기로 로그인해 키 ID가 같은 키를 찾습니다. 그 밖에 인쇄물과 USB, 저장한 파일을 확인하고, 조직 PC는 IT 관리자에게 요청합니다.
    • 복구 키를 잃어버렸는데 Microsoft에 요청하면 다시 만들어 주나요? Microsoft는 지원팀도 분실된 BitLocker 복구 키를 검색하거나 제공하거나 다시 만들 수 없다고 안내합니다. 키가 계정에 저장되어 있는지 확인하는 것이 유일한 길이고, 없다면 초기화가 필요할 수 있으며 그러면 모든 파일이 삭제됩니다.
