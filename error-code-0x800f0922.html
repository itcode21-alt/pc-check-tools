0x800F0922 · Windows 업데이트 실패

업데이트 설치 중 구성 요소 설치기가 실패해 설치가 롤백됐다는 코드입니다. 실패한 설치기는 CBS.log에서 확인하고, Microsoft 문서에 실린 원인과 커뮤니티 보고를 구분해서 점검합니다.

0x800F0922(CBS_E_INSTALLERS_FAILED)는 업데이트를 설치하는 도중 '설치기' 하나가 실패해, Windows가 그때까지의 변경을 되돌렸다는 결과 코드입니다. 코드 자체가 원인을 알려주지는 않으므로 CBS.log에서 어떤 설치기가 실패했는지 먼저 확인합니다.

쉽게 말하면

'설치가 끝까지 되지 않았다'는 결과만 알려 주는 코드입니다. 어느 부분이 실패했는지는 C:\Windows\Logs\CBS\CBS.log에 남아 있어서, 같은 0x800F0922라도 로그를 보면 원인이 PC마다 다르다는 것을 알 수 있습니다.

이 코드를 어떻게 해석해야 하나요?

0x800F0922는 CBS_E_INSTALLERS_FAILED, 즉 업데이트 설치 중 설치기(installer) 하나가 실패해서 Windows가 지금까지의 변경을 되돌린(롤백) 상태입니다. 이 코드는 실패의 이유가 아니라 '어느 설치기가 실패했다'는 결과여서, 같은 코드라도 원인이 PC마다 다를 수 있습니다. Microsoft가 이 코드에 대해 공개한 두 사례(예약 작업 SecureBootEncodeUEFI 손상, 라이선스 토큰 갱신 실패)는 모두 Windows Server 2016을 대상으로 한 문서라, Windows 10·11 가정용 PC에 그대로 적용된다고 단정할 수 없습니다. 그래서 순서는 원인을 추측하는 것이 아니라 CBS.log에서 실패한 설치기 이름을 먼저 확인하는 것입니다.

가능성 높은 원인

  • 예약 작업 SecureBootEncodeUEFI가 손상된 경우 — Microsoft의 서버용 문서(Windows Server 2016 사례)에 실린 원인으로, 작업 스케줄러 설치기가 파일을 찾지 못해 실패합니다
  • 라이선스·제품 키 토큰을 갱신하지 못해 설치가 롤백되는 경우 — Microsoft 클라이언트용 문서의 사례(Windows Server 2016 7월 누적 업데이트)로, 문서의 조치는 C:\Windows\System32\spp 폴더 쓰기 권한 부여입니다
  • EFI·시스템 예약 파티션 공간이 부족한 경우 — Microsoft 문서가 아니라 Microsoft Q&A 커뮤니티 글에서 자주 보고되는 원인입니다(100MB EFI 파티션에서 25H2 업그레이드가 실패한 사례 등)
  • VPN·프록시 연결이 설치를 방해하는 경우 — 커뮤니티에서 끄고 다시 시도하라는 조언이 있는 정도이며 공식 문서에는 없습니다

첫 점검 항목

  1. 탐색기에서 C:\Windows\Logs\CBS 폴더를 열고 CBS.log를 메모장으로 연 뒤 Ctrl+F로 0x800f0922를 검색하세요. 그 줄 바로 위쪽에 'Failed execution of queue item Installer: …'로 시작하는 줄이 있으면 뒤에 적힌 이름이 실패한 설치기입니다(예: Task Scheduler).
  2. 실패한 설치기가 Task Scheduler이고 로그에 SecureBootEncodeUEFI나 'RegisterTask failed 0x80070002'가 보이면 서버용 Microsoft 문서의 예약 작업 손상 사례와 같은 형태입니다. 이벤트 뷰어의 응용 프로그램 및 서비스 로그 > Microsoft > Windows > TaskScheduler > Operational에 같은 시각의 이벤트 ID 146이 있는지도 확인하세요.
  3. 로그에 라이선스·제품 키 토큰 갱신 실패가 보이면 클라이언트용 Microsoft 문서의 사례와 같은 형태입니다. 다만 그 조치는 시스템 폴더 권한을 바꾸는 작업이라 아래 '확인 결과에 따른 다음 단계'를 먼저 읽으세요.
  4. 설치 화면에 '시스템 예약 파티션을 업데이트할 수 없습니다'가 함께 나온다면 디스크 관리(diskmgmt.msc)에서 EFI 시스템 파티션의 크기를 확인하고, 25H2 업그레이드 가이드의 파티션 항목을 참고하세요.
  5. VPN·프록시를 쓰고 있다면 설치하는 동안만 끄고 한 번 다시 시도해 연결 문제를 배제하세요. 공식 문서의 조치는 아니고 원인을 가려내기 위한 확인입니다.
  6. 위 어디에도 맞지 않으면 CBS.log의 실패한 설치기 이름과 직전 몇 줄을 메모해 두고, 업데이트 반복 실패 가이드의 순서로 구성 요소 저장소 손상 여부를 확인하세요.

확인 결과에 따른 다음 단계

  • 실패한 설치기가 Task Scheduler이고 SecureBootEncodeUEFI 기록이 보일 때 — Microsoft 서버용 문서의 조치는 DISM으로 대기 중인 업데이트 패키지를 제거한 뒤 해당 예약 작업의 레지스트리 항목을 삭제하는 것입니다. 레지스트리 삭제가 포함된 관리자용 절차라 가정용 PC에서 그대로 따라 하지 말고, 복원 지점과 백업을 만든 뒤 전문가와 함께 진행하세요. 문서: Microsoft Learn: Error code 0x800F0922 (Windows Server)
  • 로그에 라이선스·제품 키 토큰 갱신 실패가 보일 때 — Microsoft 문서는 C:\Windows\System32\spp 폴더에 'User'와 'Network Service' 계정의 쓰기 권한을 추가하라고 안내합니다. 시스템 폴더 권한 변경은 보안에 영향을 주므로 백업 뒤 관리자가 진행하고, 가정용 PC에서는 먼저 아래 마지막 방법을 시도하세요.
  • 파티션 공간 부족 메시지가 보일 때 — 파티션 확장은 되돌리기 어렵습니다. 중요한 파일을 다른 저장장치에 백업한 뒤 25H2 업그레이드 가이드의 순서를 따르세요.
  • 어느 형태에도 맞지 않거나 로그를 찾지 못할 때 — Microsoft 공식 사이트의 미디어 생성 도구로 설치 USB를 만든 뒤 setup.exe에서 '개인 파일과 앱 유지'로 업그레이드하세요. 클린 설치는 데이터를 지우므로 마지막 방법으로만 쓰세요.

점검 전 주의

레지스트리 삭제나 시스템 폴더 권한 변경이 필요한 조치는 복원 지점과 백업 없이 시도하지 마세요. 로그에서 같은 형태가 확인되기 전에는 파티션 확장도 하지 마세요.

자주 묻는 질문

  • 0x800F0922가 나오면 시스템 예약 파티션부터 늘려야 하나요? 아니요. 파티션 확장은 되돌리기 어렵고, Microsoft 공식 문서에는 이 코드의 원인으로 나오지 않습니다. 설치 화면에 '시스템 예약 파티션을 업데이트할 수 없습니다' 메시지가 함께 나오거나 CBS.log에 파티션 관련 기록이 있을 때만 검토하세요.
  • Windows 10·11에서도 Microsoft 문서의 해결 방법이 그대로 통하나요? Microsoft가 이 코드에 대해 공개한 두 사례는 모두 Windows Server 2016이 대상입니다. 일반 PC에서 같은 형태의 로그가 나오면 같은 원인일 수 있지만 문서가 Windows 10·11에서 확인된 사실이라고 밝히지는 않았으므로, CBS.log에서 같은 항목이 실제로 보일 때만 따르세요.
  • CBS.log에서 어디를 봐야 하나요? 메모장으로 열어 0x800f0922를 검색한 뒤 그 위쪽에서 'Failed execution of queue item Installer'로 시작하는 줄을 찾으세요. 같은 시각의 Error 줄들이 실패 직전에 무슨 일이 있었는지 보여 줍니다. 파일이 크면 설치를 다시 시도한 시각과 맞는 부분만 보면 됩니다.
