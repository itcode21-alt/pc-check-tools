에러 코드 상세

0x0000003B · SYSTEM_SERVICE_EXCEPTION

시스템 서비스를 처리하는 도중 예상치 못한 예외가 발생했을 때 나타나는 코드로, 드라이버 결함이나 시스템 파일 손상이 흔한 원인입니다.

이 코드를 어떻게 해석해야 하나요?

오류 코드는 원인 후보를 좁히는 단서일 뿐, 고장 부품을 확정하는 근거는 아닙니다. 최근에 무엇이 바뀌었는지, 어떤 조건에서 반복되는지, 안전 모드에서도 재현되는지를 함께 기록해두세요.

먼저 기록할 내용: 0x0000003B가 발생한 시각, 직전에 실행한 작업, 최근 설치한 드라이버·업데이트, 재부팅 뒤 같은 코드가 반복되는지를 적어 두세요.

가능성 높은 원인

  • 그래픽이나 오디오 등 특정 드라이버의 버그
  • 시스템 파일 일부가 손상된 경우
  • 최근 윈도우 업데이트와 기존 드라이버 간의 호환성 문제
  • 램 불안정으로 인한 잘못된 메모리 접근
  • 보안 소프트웨어와 시스템 서비스 간의 충돌

첫 점검 항목

  1. 이벤트 뷰어에서 블루스크린 발생 직전 어떤 드라이버나 서비스가 관여했는지 확인하세요.
  2. sfc /scannow로 시스템 파일 손상 여부를 점검하고 복구하세요.
  3. 최근 업데이트된 드라이버를 이전 버전으로 되돌려 재현 여부를 확인하세요.
  4. 메모리 진단 도구로 램 상태를 점검하세요.
  5. 먼저 차단·격리 기록과 허용 목록을 확인하세요. 꼭 필요할 때만 보호 기능을 짧게 중지해 증상을 비교하고, 테스트 직후 다시 켜세요.

확인 결과에 따른 다음 단계

  • sfc /scannow로 해결될 때 — 재발 여부만 지켜보면 됩니다.
  • 드라이버 롤백으로 해결될 때 — 해당 드라이버의 수정된 버전이 나올 때까지 사용을 자제하세요.
  • 메모리 진단에서 오류가 발견될 때 — 램 모듈을 하나씩 장착해가며 어떤 모듈이 문제인지 확인하세요.

데이터와 시스템을 보호하는 주의사항

원인이 확인되지 않은 상태에서 초기화, 레지스트리 수정, 시스템 파일 수동 교체를 먼저 진행하지 마세요.

앞 단계로 해결되지 않을 때

같은 코드가 재발할 때는 이벤트 로그와 장치 상태 기록을 보관하고, 코드가 그때그때 달라진다면 메모리·전원·발열 같은 전반적인 안정성 문제를 의심해보세요.

시스템 복구나 초기화, 드라이버 삭제처럼 원상복구가 힘든 작업을 시작하기 전에, 중요한 파일은 미리 외장 저장장치나 별도 위치에 백업해 두세요.

관련 증상 가이드 확인하기

  • 0x00000050 · PAGE_FAULT_IN_NONPAGED_AREA
  • 0x000000EF · CRITICAL_PROCESS_DIED
  • 0x000000D1 · DRIVER_IRQL_NOT_LESS_OR_EQUAL

자주 묻는 질문

  • 블루스크린 코드가 한 번 떴는데 계속 지켜봐야 하나요? 이 문제(0x0000003B)가 한 번만 발생했다면 즉시 부품을 교체하기보다 재현 여부와 최근 변경 사항을 먼저 기록해두는 것으로 충분합니다. 반복된다면 그때 하드웨어 점검 범위를 넓히세요.
  • 최근에 설치한 프로그램이 원인일 수도 있나요? 네, 최근 설치한 드라이버나 소프트웨어가 원인인 경우가 많아 시스템 복원 지점으로 되돌리는 것도 방법입니다.
  • 그래픽 드라이버가 원인인지 어떻게 확인하나요? 이벤트 뷰어의 발생 직전 로그에서 관련 .sys 파일명을 확인하거나, DDU로 그래픽 드라이버를 완전히 제거한 뒤 재현 여부를 비교해보세요.
