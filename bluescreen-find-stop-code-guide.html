홈/가이드/블루스크린 코드를 못 봤을 때

📑 목차

    STOP CODE RECOVERY

    화면은 사라졌지만, 코드는 윈도우가 기록해 두었습니다

    블루스크린이 지나간 뒤에도 이벤트 뷰어와 덤프 폴더에는 흔적이 남습니다. 코드를 찾는 순서와, 괄호 안 숫자를 코드로 착각하지 않는 법을 정리했습니다.

    이런 상황이라면 이 글이 맞습니다

    • 작업 중에 파란 화면이 잠깐 떴다가 바로 재부팅돼서 중지 코드를 못 읽었다.
    • 자리를 비운 사이에 PC가 혼자 재시작돼 있었고, 블루스크린이었는지도 확실하지 않다.
    • 화면은 봤지만 글자가 작아서 코드를 놓쳤고 사진도 못 찍었다.

    코드를 알면 어디서부터 의심할지 범위가 훨씬 좁아집니다. 다행히 윈도우는 블루스크린이 난 뒤에 흔적을 몇 군데 남겨 둡니다. 아래 순서로 찾아보세요. 첫 번째 방법에서 찾으면 나머지는 건너뛰어도 됩니다.

    1. 이벤트 뷰어에서 찾기 — 가장 먼저 할 일

    1. Win+R을 누르고 eventvwr.msc를 실행합니다.
    2. 왼쪽에서 Windows 로그 → 시스템을 선택합니다.
    3. 오른쪽 현재 로그 필터링에서 이벤트 원본을 BugCheck로 고르거나 이벤트 ID에 1001을 입력합니다.
    4. 해당 시각의 이벤트를 열어 The bugcheck was: 0x000000… 줄을 찾습니다. 한국어 윈도우에서는 '버그 검사'라는 표현으로 보이는 경우가 많습니다.

    여기서 중요한 읽는 법이 하나 있습니다. 문장 뒤에 괄호로 묶인 숫자는 코드가 아니라 매개변수입니다. 코드는 0x로 시작하는 첫 번째 값입니다. 문구를 통째로 복사해서 블루스크린 코드 해석기에 붙여 넣으면 첫 값만 코드로 읽고 나머지는 걸러 줍니다.

    Get-WinEvent -FilterHashtable @{LogName='System'; Id=1001} -MaxEvents 10 |
  Select-Object TimeCreated, ProviderName, Message | Format-List

    PowerShell이 편하다면 위 명령으로 최근 1001 이벤트를 한 번에 볼 수 있습니다. 목록에 블루스크린과 무관한 항목이 섞이면 Message에 bugcheck 또는 '버그 검사'가 들어 있는 것만 보세요.

    같은 시각의 Kernel-Power 41은 코드가 아닙니다

    이벤트 뷰어에서 Kernel-Power 41(예기치 않은 재시작)을 먼저 보게 되는 경우가 많습니다. 이것은 "비정상적으로 꺼졌다"는 결과 기록이라 원인을 직접 말해 주지 않습니다. 41과 함께 1001(BugCheck)이 있으면 코드를 남기고 멈춘 것이고, 41만 있고 1001이 없으면 코드를 남길 틈도 없이 꺼졌을 수 있습니다. 자세한 해석은 Kernel-Power 41 가이드를 참고하세요.

    2. 덤프 파일로 흔적 확인하기

    블루스크린이 나면 윈도우가 메모리 내용을 파일로 저장하는 설정이 기본으로 켜져 있습니다. 파일 탐색기에서 다음 위치를 열어 보세요.

    • C:\Windows\Minidump — 날짜 순으로 쌓이는 작은 덤프(.dmp). 파일 날짜만 봐도 블루스크린이 몇 번, 언제 났는지 알 수 있습니다.
    • C:\Windows\MEMORY.DMP — 설정에 따라 가장 최근 한 번의 큰 덤프가 이 이름으로 저장됩니다.

    덤프가 있다면 블루스크린 덤프 분석기에 올려 정지 코드와 로드된 드라이버 목록을 볼 수 있습니다. 올린 파일은 브라우저 안에서만 처리됩니다. 폴더가 비어 있거나 아예 없다면 덤프가 만들어지지 않는 설정일 수 있으니 3번으로 넘어갑니다.

    3. 다음번을 위해 덤프와 화면이 남도록 바꾸기

    코드를 이번에 못 찾았더라도 같은 증상이 반복된다면 다음번에는 남도록 설정해 두는 것이 가장 확실합니다.

    1. Win+R → sysdm.cpl → 고급 탭 → 시작 및 복구의 설정을 엽니다.
    2. 디버깅 정보 쓰기가 '(없음)'이면 덤프가 안 남습니다. '작은 메모리 덤프' 또는 '자동 메모리 덤프'로 바꿉니다.
    3. 자동으로 다시 시작 체크를 해제하면 다음 블루스크린 때 재부팅하지 않고 화면이 그대로 남아 사진을 찍을 수 있습니다.
    4. 덤프는 윈도우가 설치된 드라이브의 페이지 파일을 거쳐 만들어집니다. 가상 메모리(페이지 파일)를 끄거나 아주 작게 줄여 두었다면 덤프가 만들어지지 않을 수 있습니다.
    자동 다시 시작을 끈 뒤에는

    오류가 났을 때 PC가 멈춘 채로 있으니 전원 버튼으로 직접 껐다 켜야 합니다. 원인을 찾은 뒤에는 다시 체크해 두는 편이 편합니다. 부팅이 아예 안 되는 PC에는 이 설정을 만지기 어려우니 자동 복구 루프 가이드를 보세요.

    코드를 찾았다면, 다음에 할 일

    찾은 단서의미다음 행동
    같은 코드가 날짜를 달리해 반복같은 영역의 문제가 되풀이된다해석기의 점검 순서를 위에서부터 진행하고, 마지막으로 바꾼 드라이버·업데이트·장치부터 되돌려 본다
    날짜마다 코드가 모두 다르다특정 드라이버보다 하드웨어 불안정을 의심할 만한 패턴메모리 검사, 저장장치 상태, 전원·온도 점검으로 넘어간다
    코드 이름에 DRIVER 또는 VIDEO가 보인다드라이버·그래픽 영역그래픽 드라이버 재설치와 최근 업데이트 이력을 확인한다
    부팅 직후 항상 나고 로그가 없다윈도우가 시작하기도 전에 멈춘 경우일 수 있다0x7B 가이드, BIOS·부팅 확인을 본다
    이벤트 뷰어에 1001이 하나도 없다블루스크린이 아니었거나 기록을 남기지 못했다Kernel-Power 41, 전원·과열 가능성을 함께 본다

    코드 하나로 고장 부품을 확정하지 마세요. 같은 코드도 드라이버, 메모리, 저장장치 등 여러 원인에서 나옵니다. 반복되는지, 최근에 무엇을 바꿨는지를 함께 기록해 두면 점검이 훨씬 빨라집니다.

    자주 묻는 질문

    • 이벤트 뷰어에 1001이 여러 개 있는데 어느 것이 방금 난 건가요? 각 이벤트의 '기록된 시간'을 보세요. 블루스크린 후 재부팅하고 로그인했을 때쯤 기록되므로, 의심되는 시각 직후의 1001이 해당 건입니다. 이벤트를 열어 일반 탭의 설명 문장에 코드가 있습니다.
    • 최신 윈도우 11에서는 파란색이 아니라 검은 화면으로 나오던데요? 윈도우 11 최신 버전에서는 오류 화면이 검은색 배경으로 나오는 경우가 있습니다. 이름만 다를 뿐 같은 정지 화면이며, 아래쪽의 '중지 코드'와 이름은 똑같이 확인하면 됩니다.
    • 덤프 파일을 지워도 되나요? 분석이 끝났다면 지워도 PC 동작에는 영향이 없습니다. 다만 반복되는 문제를 추적 중이라면 날짜별로 남겨 두는 것이 도움이 됩니다. 파일을 다른 사람에게 보낼 때는 컴퓨터 이름과 사용자 이름이 들어 있을 수 있다는 점을 알아 두세요.
