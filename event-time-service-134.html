    EVENT ID 134 · Time-Service

    대개 DNS·네트워크 타이밍 문제이며 시계 고장이 아닙니다 확인 필요

    Time-Service(W32Time) 이벤트 134는 설정된 시간 서버 이름을 DNS로 확인하지 못해 시간 동기화에 실패했다는 기록입니다.

    "DNS resolution error on 'time.windows.com'" 같은 설명과 함께 기록되며, 대부분 네트워크가 아직 준비되지 않은 부팅 직후나 절전 복귀 직후에 발생합니다. 시스템 시계 하드웨어 자체의 고장을 의미하지 않습니다.

    먼저 구분할 상황

    • 부팅·절전 복귀 직후 한 번만 기록됐다면 네트워크 준비 타이밍 문제로 대개 자동 재시도됩니다.
    • 반복되고 실제 시계가 어긋나 있다면 DNS·방화벽·VPN 설정을 점검해야 합니다.
    • 회사·학교 도메인 PC라면 도메인 컨트롤러 시간 서버 접근 여부를 먼저 확인합니다.

    안전한 점검 순서

    1. 이벤트 설명에 표시된 시간 서버 이름과 DNS 오류 코드를 기록합니다.
    2. 관리자 권한 명령 프롬프트에서 w32tm /resync로 수동 동기화를 시도합니다.
    3. w32tm /query /status로 현재 동기화 소스와 마지막 성공 시각을 확인합니다.
    4. 일반 가정용 네트워크라면 DNS 서버 설정과 인터넷 연결 상태를 확인합니다.
    5. 사내망·VPN 환경이라면 관리자에게 NTP(UDP 123) 아웃바운드 트래픽 허용 여부를 문의합니다.

    하면 안 되는 실수

    이벤트가 한두 번 기록됐다고 곧바로 시간 서비스를 재설치하거나 레지스트리를 직접 수정하지 마세요. 대부분 일시적인 네트워크 타이밍 문제이며, 반복 여부와 실제 시계 오차를 먼저 확인하는 것이 우선입니다.

    즉시 점검이 필요한 경우

    시간이 몇 분 이상 벌어져 로그인·인증서·Windows Update 오류가 함께 발생한다면 수동으로 w32tm /resync를 실행하고, 반복되면 네트워크 관리자 또는 ISP 상태를 확인하세요.

    자주 묻는 질문

    • 이벤트 134가 한 번 뜨면 바로 조치해야 하나요? 단발성이라면 대개 절전 복귀나 부팅 직후 네트워크가 준비되지 않은 타이밍 문제로, 잠시 후 자동으로 재시도되어 해결됩니다. 반복적으로 기록되고 실제 시계가 어긋난다면 그때 DNS와 네트워크 설정을 점검하세요.
    • 시간이 몇 분만 어긋나도 문제가 되나요? 시간 차이가 커지면 HTTPS 인증서 검증, Kerberos 인증, 클라우드 로그인, Windows Update 서명 확인에서 오류가 발생할 수 있습니다. 몇 초 수준의 차이는 대개 문제가 없지만 몇 분 이상 벌어졌다면 동기화를 확인하세요.
    • 회사·학교 PC에서는 어떻게 다른가요? 도메인에 가입된 PC는 보통 도메인 컨트롤러를 시간 서버로 사용하며, 사내망 정책이나 방화벽이 외부 NTP 서버 접근을 막는 경우가 많습니다. 이 경우 개인 설정을 바꾸기 전에 관리자에게 문의하세요.
