Kernel-Processor-Power 이벤트 55 프로세서 전원 관리 기록 해석

부팅 때 논리 프로세서마다 CPU가 알려 주는 전원 관리 기능(유휴 상태, 성능 상태, 기준 주파수, 최대·최소 성능 비율)을 기록하는 정보성 이벤트입니다.

Kernel-Processor-Power 55는 부팅할 때 논리 프로세서마다 유휴 상태(C-state), 성능 상태(CPPC 등), 기준 주파수, 최대·최소 성능 비율을 기록하는 정보성 이벤트입니다. 예를 들어 'Processor 11 in group 0 exposes the following power management capabilities'로 시작하는 본문이 프로세서 수만큼 남습니다.

건수가 수백 건으로 보여도 논리 프로세서 수와 부팅 횟수를 곱한 값이라 정상입니다. CPU 성능 저하나 과열은 이 이벤트가 아니라 같은 공급자의 다른 ID와 온도·클럭 기록으로 판단해야 합니다.

발생 조건

  • 부팅할 때마다 논리 프로세서 수만큼 한꺼번에 기록됨

가능성 높은 원인

  • 정상 부팅 기록 — 건수는 논리 프로세서 수 × 부팅 횟수

점검 순서

  1. 건수가 (논리 프로세서 수 × 부팅 횟수)와 크게 다르지 않은지 확인 — 되돌리기 쉬운 항목부터 확인해 위험 없이 범위를 줄입니다.
  2. 유휴 상태 수나 성능 상태 방식이 표시되지 않으면 BIOS의 CPU 전원 관리(C-state, CPPC) 설정 확인 — 첫 확인 결과와 비교해 원인 후보를 좁힙니다.
  3. 성능 저하·과열 문제는 이 이벤트가 아니라 같은 공급자의 다른 ID(예: 37)와 온도 기록으로 확인 — 이 단계에서도 재현되면 다음 항목으로 넘어가세요.
주의사항

오류나 경고가 아닙니다. 건수가 많아 보여도 정상입니다.

자주 묻는 질문

  • 55가 수백 건 있는데 문제인가요? 아닙니다. 논리 프로세서 수 × 부팅 횟수만큼 남는 기록입니다. 예를 들어 24개 논리 프로세서 PC를 10번 부팅하면 240건이 됩니다.
  • CPU 성능이 떨어질 때 이 이벤트를 봐야 하나요? 이 이벤트는 CPU가 어떤 전원 관리 기능을 제공하는지만 알려 줍니다. 성능 저하는 HWiNFO의 온도·전력 제한 기록과 Kernel-Processor-Power의 다른 이벤트를 함께 확인하세요.
