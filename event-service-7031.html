EVENT ID 7031

Service Control Manager 7031 서비스 비정상 종료 점검

서비스가 예기치 않게 종료되었고 Windows가 재시작 같은 복구 작업을 예약한 기록입니다.

7031은 서비스가 예기치 않게 종료됐고 Windows가 재시작 같은 복구 작업을 예약했다는 기록입니다. 반복 횟수가 늘어나는지가 조치 필요 여부를 가르는 기준입니다.

복구 동작이 예약됐다는 것은 Windows가 문제를 인지하고 있다는 뜻이므로, 반복 여부를 지켜보되 급하게 시스템 파일을 손대지 마세요.

발생 조건

  • 앱·네트워크 기능이 갑자기 중단

가능성 높은 원인

  • 서비스 충돌
  • 관련 모듈·드라이버 오류

7031이 알려주는 것과 알려주지 않는 것

7031은 무엇이 멈췄고 Windows가 어떻게 대응할 것인지는 알려주지만, 왜 멈췄는지는 담고 있지 않습니다. 원인은 같은 시각의 다른 기록에서 찾아야 합니다.

  • Application Error 1000 — 오류 모듈 이름과 예외 코드가 남습니다. 가장 직접적인 단서입니다.
  • Windows Error Reporting 1001 — 충돌 보고서가 만들어졌다면 여기에 요약이 남습니다.
  • 같은 서비스의 7000·7023 — 재시작 후 다시 실패했다면 이어서 기록됩니다.

점검 순서

  1. 서비스 이름과 종료 횟수 확인 — 설명의 이 작업을 N번 수행했습니다에서 N이 반복 정도입니다. N이 계속 늘어난다면 일시적 오류가 아니라 재현되는 문제입니다.
  2. Application Error 1000이 함께 있는지 확인 — 7031은 결과만 알려주고 원인 모듈은 알려주지 않습니다. 같은 시각의 Application Error 1000에는 오류 모듈 이름과 예외 코드가 남습니다. 실제 조사는 그 모듈 이름에서 시작해야 합니다.
  3. 복구 동작 설정 확인 — services.msc → 해당 서비스 속성 → 복구 탭에서 첫 번째·두 번째 실패 시 동작을 봅니다. 여기에 재시작이 설정돼 있어서 7031로 기록된 것이며, 이 설정 자체가 문제는 아닙니다.
  4. 원인 모듈에 해당하는 프로그램 복구 — 1000에서 확인한 모듈이 특정 프로그램의 파일이면 그 프로그램을 복구 설치하거나 최신 버전으로 올립니다. 모듈이 드라이버 파일이면 장치 관리자에서 해당 드라이버를 다시 설치합니다.
주의사항

반복 횟수가 증가할 때 조치하세요.

자주 묻는 질문

  • Windows가 자동으로 재시작한다는데 기다리면 되나요? 예약된 복구 작업이 있다면 잠시 기다려볼 수 있습니다. 다만 반복 횟수가 계속 늘어난다면 관련 프로그램을 재설치하는 것이 안전합니다.
  • Application Error 1000과 함께 뜨면 어떤 관계인가요? 같은 프로그램의 충돌을 서비스 관점과 응용 프로그램 관점에서 각각 기록한 것일 수 있습니다. 두 기록의 시각과 대상 프로그램을 비교하세요.
  • Application Error 1000에서 어떤 항목을 봐야 하나요? 오류 모듈 이름과 예외 코드 두 가지입니다. 오류 모듈이 특정 프로그램의 DLL이면 그 프로그램을, 드라이버 파일(.sys)이면 해당 장치 드라이버를 조사 대상으로 삼습니다.
