EVENT ID 36887

Schannel 36887 TLS 치명적 경고 수신 점검

원격 끝점(서버)이 이 PC와의 TLS 핸드셰이크를 거부하며 치명적 경고를 보내왔음을 기록합니다. 36888(이 PC가 보낸 경고)과 반대 방향의 기록입니다.

Schannel은 Windows의 TLS/SSL 처리 구성 요소입니다. 36887은 이 PC가 상대 서버로부터 "치명적 경고(fatal alert)"를 받아 핸드셰이크가 중단됐다는 뜻으로, 이벤트 설명의 실제 경고 코드와 호출 프로세스를 함께 확인해야 원인을 좁힐 수 있습니다.

서버 쪽에서 거부한 결과 기록이지만, 실제 원인은 이 PC의 TLS 설정이나 보안 프로그램에 있는 경우가 흔합니다. 36874(프로토콜·암호화 방식 불일치)와 같은 시각에 반복된다면 협상 실패의 연장선으로 봐야 합니다.

발생 조건

  • 특정 사이트·서버 접속 실패
  • VPN·프록시·백신 HTTPS 검사 사용 중
  • 36874와 같은 시각에 반복

가능성 높은 원인

  • 서버가 이 PC의 TLS 버전·암호화 스위트를 지원하지 않는 경우
  • 인증서가 만료됐거나 신뢰할 수 없는 경우
  • 백신·VPN의 HTTPS 검사가 핸드셰이크를 가로채 서버 쪽에서 거부하는 경우
  • 시스템 날짜·시간 오류로 인증서 유효기간 검증이 실패하는 경우

점검 순서

  1. 이벤트 설명의 fatal alert 코드와 호출 프로세스(PID) 확인 — 되돌리기 쉬운 항목부터 확인해 위험 없이 범위를 줄입니다.
  2. 설정 > 시간 및 언어에서 날짜·시간 자동 설정이 켜져 있는지 확인 — 첫 확인 결과와 비교해 원인 후보를 좁힙니다.
  3. 백신·VPN의 HTTPS 검사 기능을 잠시 끄고 재현 여부 비교 — 이 단계에서도 재현되면 다음 항목으로 넘어가세요.
  4. 브라우저와 Windows를 최신 버전으로 업데이트해 TLS 지원 범위 확인 — 변경 전후로 증상이 달라지는지 비교해보세요.
  5. 특정 서버에서만 반복되는지, 여러 곳에서 무작위로 발생하는지 구분 — 특정 서버에서만 반복되면 그 서버 쪽 설정 문제일 가능성이 큽니다.

실제 사용자 사례

이벤트 설명에 %1·%2·%3 같은 자리표시자가 그대로 보인 사례입니다.

이벤트 설명에 %3 같은 원시 값이 그대로 남아있던 사례

이벤트 뷰어에서 36887을 열었더니 "치명적인 경고 코드가 %3. SSPI 클라이언트 프로세스(PID: %1)%2."처럼 실제 값 대신 자리표시자가 그대로 표시된 경우가 있었습니다. 원본 PC가 아닌 다른 PC에서 저장된 로그(.evtx) 파일을 열었을 때 흔히 나타나는 현상으로, 메시지 형식을 채우는 데 필요한 원본 PC의 리소스 파일이 없어서 값을 채우지 못한 것입니다.

포인트: 이런 자리표시자가 보이면 오류 자체보다 "다른 PC의 로그를 열람 중"이라는 신호로 먼저 이해하세요. 정확한 경고 코드·PID를 보려면 이벤트가 기록된 원본 PC에서 직접 이벤트 뷰어로 열어야 합니다.

주의사항

백신의 HTTPS 검사 기능을 끄는 동안에는 피싱·위장 사이트 탐지 능력이 함께 낮아질 수 있으니, 원인 확인이 끝나면 바로 다시 켜두세요. 보안을 낮추기 위해 TLS 1.0·1.1을 무조건 활성화하지 마세요.

자주 묻는 질문

  • 36887이 뜨면 해킹당한 건가요? 아닙니다. 대부분 인증서 만료, 오래된 TLS 버전, 보안 프로그램의 HTTPS 검사 충돌처럼 정상적인 네트워크 환경에서도 발생하는 기록입니다.
  • 이벤트 설명에 %1, %3 같은 게 그대로 보이는데 왜 그런가요? 이벤트가 기록된 PC가 아닌 다른 PC에서 저장된 로그 파일을 열람할 때 나타나는 현상입니다. 정확한 값은 원본 PC에서 직접 확인해야 합니다.
