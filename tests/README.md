# 분석기 자체 점검

진단 페이지의 **로그 분석기(HWiNFO·dxdiag·msinfo32·CrystalDiskInfo)**, **이벤트 뷰어 분석기**, **시간축 종합 리포트**가
샘플 파일을 올렸을 때 기대한 결과를 내는지 브라우저에서 확인합니다. Node가 필요 없습니다.

## 실행

```
python -m http.server 8811      # 저장소 루트에서
```

브라우저에서 `http://localhost:8811/tests/analyzer-tests.html` 을 열고 **전체 실행**을 누릅니다
(`?run`을 붙이면 자동 실행, `?case=hwinfo`처럼 이름 일부로 좁힐 수 있음).
결과는 `window.__ANALYZER_TEST_RESULT`(총 개수·실패 목록)에도 남으므로 자동화 도구로 읽을 수 있습니다.

## 어떻게 동작하나

- `diagnostic.html`을 iframe에 불러와 실제 화면의 파일 선택칸에 `fixtures/`의 파일을 올립니다(사람이 올리는 것과 같은 경로).
- 결과 영역의 텍스트에 대해 `analyzer-cases.js`의 규칙(`has` / `not` / `count`)을 검사합니다.
- 사용자 기기의 localStorage는 메모리 저장소로 대체하고, 통계·광고 스크립트는 불러오지 않습니다.
- 케이스마다 새 iframe을 만들어 서로 영향을 주지 않게 합니다.

## 케이스를 추가하는 방법

분석기의 오류를 고칠 때마다 **그 오류를 재현하는 샘플 + 케이스**를 함께 추가하세요.

1. `fixtures/`에 작은 샘플 파일을 넣습니다. 개인 정보(컴퓨터 이름, 사용자 이름, 시리얼 번호, IP·MAC)는 지우거나 합성하세요.
   실제 로그를 쓸 때는 필요한 행만 잘라 내고 시리얼은 `(SERIAL)` 등으로 바꿉니다.
2. `analyzer-cases.js`에 `add(이름, 설명, "log"|"event", 파일, [규칙...], 로그 종류)`를 추가합니다.
3. 전체 실행이 모두 통과하는지 확인합니다.

## 알아 둘 점

- 시각은 시간대에 따라 달라지므로, 시간대에 민감한 값(UTC로 기록된 XML 시각 등)은 검사하지 않습니다.
- 시간축 종합 리포트의 덤프 경로는 분석 서버가 필요해 이 페이지에서는 확인하지 않습니다(HWiNFO + 텍스트 이벤트 조합만 확인).
- EVTX·덤프 파일은 실제 파일에 개인 정보가 많아 샘플로 넣지 않았습니다. 서버 쪽 파서는 `ai-service/test_*.py`(pytest)로 점검합니다.
- 경고·결론 문구를 고치면 이 케이스의 정규식도 함께 바뀌어야 합니다. 그것이 의도한 변경인지 이 페이지에서 확인하세요.
