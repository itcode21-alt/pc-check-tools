EVENT ID 7011

Service Control Manager 7011 서비스 제어 요청 시간 초과 점검

서비스 제어 요청이 시간 안에 응답하지 않았음을 나타냅니다.

7011은 서비스 제어 요청이 시간 안에 응답하지 않았다는 기록으로, 종료나 재부팅이 지연되는 증상과 함께 나타나는 경우가 많습니다.

매번 종료할 때마다 반복된다면, 최근 설치한 프로그램의 백그라운드 서비스를 하나씩 비활성화하며 원인을 좁혀보세요.

발생 조건

  • 종료·부팅 지연
  • 장치 서비스 멈춤

가능성 높은 원인

  • 서비스 교착
  • 저장장치 지연
  • 드라이버 응답 문제

교착 상태로 볼 수 있는 신호

7011은 서비스가 제어 요청(시작·중지·일시 중지)에 응답하지 못한 기록입니다. 아래 신호가 함께 보이면 단순 지연보다 교착에 가깝습니다.

  • 종료할 때 서비스를 종료하는 중 화면이 수십 초 이상 유지된다.
  • 같은 서비스에 대해 7011이 반복되고, 그때마다 강제 종료로 이어진다.
  • 작업 관리자에서 해당 서비스 프로세스의 CPU 사용률은 0인데 상태가 바뀌지 않는다.

점검 순서

  1. 서비스 이름과 발생 시점 기록 — 이 이벤트도 기본 30000밀리초 대기 후 기록됩니다. 종료 중에 났는지 부팅 중에 났는지를 함께 적어 두면 다음 단계에서 범위가 크게 줄어듭니다.
  2. 종료 지연과 함께 나타나는지 확인 — 종료 시 서비스를 종료하는 중 화면이 오래 머무른다면 그 서비스가 제어 요청에 응답하지 못하는 상태, 즉 교착일 가능성이 큽니다. EventLog 6008이 함께 있으면 강제 종료로 이어졌다는 뜻입니다.
  3. 디스크 129·153 동반 여부 확인 — storahci 129나 Disk 153이 같은 시각에 있으면 저장장치 응답 지연이 서비스 응답까지 막은 경우입니다. 이때는 케이블·NVMe 슬롯·펌웨어를 먼저 봅니다.
  4. 클린 부팅으로 서드파티 서비스 배제 — msconfig → 서비스 탭에서 Microsoft 서비스 모두 숨기기를 체크한 뒤 나머지를 모두 사용 안 함으로 두고 재부팅합니다. 증상이 사라지면 절반씩 되살리며 원인 서비스를 좁힙니다.
주의사항

서비스 강제 삭제는 마지막 수단입니다.

관련 코드·가이드

0x00000133 오류 코드 확인하기시작 속도 저하 가이드

자주 묻는 질문

  • 종료가 오래 걸리는 것도 이 이벤트 때문인가요? 네, 서비스가 응답 없이 종료 절차를 막고 있으면 시스템 종료·재부팅이 지연되고 이 이벤트가 함께 기록될 수 있습니다.
  • 서비스를 강제로 삭제해도 되나요? 마지막 수단으로 남겨두세요. 먼저 클린 부팅에서 재현되는지 확인하고, 관련 프로그램을 업데이트하거나 재설치하는 방법을 우선 시도하세요.
  • 클린 부팅으로 확인한 뒤에는 어떻게 되돌리나요? msconfig를 다시 열어 일반 탭에서 정상 시작을 선택하고 재부팅하면 원래 상태로 돌아갑니다. 원인 서비스를 찾았다면 그 항목만 사용 안 함으로 두세요.
