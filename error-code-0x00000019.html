에러 코드 상세

0x00000019 · BAD_POOL_HEADER

메모리 풀의 구조 정보가 손상되었을 때 나타나는 블루스크린 코드로, 드라이버 오류나 램 문제가 주요 원인입니다.

이 코드를 어떻게 해석해야 하나요?

메모리 관련 코드는 RAM 자체뿐 아니라 잘못된 메모리 주소를 사용한 드라이버, 페이지 파일, 저장장치 오류와 함께 나타날 수 있습니다. 코드가 매번 바뀌는지도 중요한 단서입니다.

먼저 기록할 내용: 0x00000019가 발생한 시각, 직전에 실행한 작업, 최근 설치한 드라이버·업데이트, 재부팅 뒤 같은 코드가 반복되는지를 적어 두세요.

가능성 높은 원인

  • 드라이버가 메모리 풀을 잘못 다루는 경우
  • 램 모듈의 물리적 결함
  • 보안 프로그램과의 충돌
  • 시스템 파일 손상
  • 오버클럭으로 인한 메모리 불안정

첫 점검 항목

  1. 최근 설치한 드라이버를 확인하고 제거 또는 롤백해 보세요.
  2. 메모리 진단 도구로 램 상태를 점검하세요.
  3. 시스템 복원 지점이 있다면 이전 상태로 되돌려 보세요.
  4. 먼저 차단·격리 기록과 허용 목록을 확인하세요. 원인 분리를 위해 꼭 필요할 때만 보호 기능을 짧게 중지해 재현 여부를 확인하고, 테스트 직후 다시 켜세요.
  5. 오버클럭 설정을 기본값으로 되돌리세요.

확인 결과에 따른 다음 단계

  • 최근 드라이버를 롤백한 뒤 해결될 때 — 재발 여부만 지켜보면 됩니다.
  • 메모리 진단에서 오류가 발견될 때 — 램 모듈을 하나씩 장착해가며 어떤 모듈이 문제인지 확인하세요.
  • 오버클럭 해제 후에도 반복될 때 — 보안 프로그램 재설치나 sfc /scannow로 시스템 파일 손상 여부를 확인하세요.

데이터와 시스템을 보호하는 주의사항

메모리 검사가 한 번 통과했다고 즉시 정상으로 단정하지 말고 XMP·EXPO 해제 상태와 모듈별 결과를 비교하세요.

앞 단계로 해결되지 않을 때

모듈을 한 개씩 기본 속도로 장착해 슬롯을 교차하고, 안전 모드와 클린 부팅에서 같은 작업이 재현되는지 확인하세요.

이런 조치는 취소가 어려운 경우가 많으므로, 복구·초기화·드라이버 제거를 실행하기 전에 중요한 파일부터 별도 저장장치에 백업해 두시길 권장합니다.

관련 증상 가이드 확인하기

  • 0x00000050 · PAGE_FAULT_IN_NONPAGED_AREA

  • 0x000000D1 · DRIVER_IRQL_NOT_LESS_OR_EQUAL

자주 묻는 질문

  • 블루스크린 코드가 한 번 떴는데 계속 지켜봐야 하나요? 이 문제(0x00000019)가 한 번만 발생했다면 즉시 부품을 교체하기보다 재현 여부와 최근 변경 사항을 먼저 기록해두는 것으로 충분합니다. 반복된다면 그때 하드웨어 점검 범위를 넓히세요.
  • 최근에 설치한 프로그램이 원인일 수도 있나요? 네, 최근 설치한 드라이버나 소프트웨어가 원인인 경우가 많아 시스템 복원 지점으로 되돌리는 것도 방법입니다.
  • 메모리 진단이 오래 걸리는데 얼마나 돌려야 하나요? 기본(표준) 검사로 최소 1회 실행하고, 재현이 잦다면 확장 모드로 반나절 이상 돌려 간헐적으로만 나타나는 오류까지 잡아내는 것이 좋습니다.
