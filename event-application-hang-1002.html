EVENT ID 1002

Application Hang 이벤트 1002 프로그램 멈춤 점검

응용 프로그램이 일정 시간 응답하지 않아 Windows가 멈춤 상태로 기록한 이벤트입니다. 앱 충돌 1000과 달리 프로세스가 종료되지 않고 기다리는 상황이 핵심입니다.

1002는 프로그램이 일정 시간 응답하지 않아 Windows가 멈춤 상태로 기록한 이벤트입니다. Application Error 1000처럼 예외로 종료된 기록과는 다르므로, 멈춤이 시작된 작업과 회복 여부를 먼저 확인해야 합니다.

한 앱에서만 반복되면 앱 설정·플러그인·오버레이를 우선 확인하고, 여러 앱이 같은 시간대에 멈추면 그래픽 드라이버·저장장치·메모리 사용량을 비교하세요.

발생 조건

  • 창에 응답 없음 표시
  • 게임·탐색기·문서 앱이 멈춤
  • 잠시 후 회복되거나 강제 종료

가능성 높은 원인

  • 앱 내부 작업 또는 플러그인 대기
  • 그래픽·저장장치·네트워크 응답 지연
  • 오버레이·보안 프로그램 충돌

행(Hang)과 충돌(1000)의 차이

이 기록은 앱이 죽은 것이 아니라 응답을 멈춘 것입니다. 충돌(Application Error 1000)은 프로세스가 즉시 종료되지만, 행은 프로세스가 살아있는 채로 응답만 멈춥니다. 그래서 방식이 다릅니다 — 충돌은 원인 모듈을 바로 알 수 있지만, 행은 무엇을 기다리는지부터 좁혀야 합니다.

점검 순서

  1. 응답하지 않은 앱 이름과 Hang 유형 기록 — 이벤트 설명에서 앱 이름과 Hang Type 값을 확인합니다. Type 0은 창이 완전히 멈춘 경우, Type 1은 메시지 큐가 정체된 경우로 원인 방향이 다릅니다.
  2. 같은 앱에서만 재현되는지 비교 — 여러 프로그램에서 골고루 발생한다면 시스템 전체의 디스크·메모리 지연을 의심하고, 특정 앱 하나에서만 반복된다면 그 프로그램의 업데이트나 재설치를 먼저 시도합니다.
  3. 오버레이·플러그인을 끄고 클린 부팅에서 재현 — 게임 오버레이, 백신 실시간 검사, 브라우저 확장 프로그램을 순서대로 꺼서 재현 여부를 봅니다. 여전히 발생하면 msconfig로 클린 부팅해 서드파티 프로그램 전체를 배제한 상태에서 다시 확인합니다.
  4. 동시각 Disk·Display·Application Error 이벤트 확인 — 같은 시각에 Disk 153이나 Display 4101이 있으면 저장장치나 그래픽 드라이버 응답 지연이 앱까지 멈추게 한 경우입니다. 이때는 앱보다 그쪽을 먼저 봅니다.
주의사항

1002만으로 RAM이나 저장장치 고장을 확정하지 마세요. 멈춘 앱과 작업 조건이 더 중요한 단서입니다.

관련 코드·가이드

0xC0000005 오류 코드 확인하기관련 가이드 보기앱 실행 불가 가이드

자주 묻는 질문

  • 1002는 RAM 고장을 의미하나요? 아닙니다. 앱 자체의 대기, 저장장치 지연, 그래픽 드라이버, 플러그인 충돌 등 여러 원인이 가능합니다. 여러 앱에서 무작위로 반복되는지부터 비교하세요.
  • 1000과 1002는 어떻게 구분하나요? 1000은 처리하지 못한 예외로 앱이 종료된 기록이고, 1002는 응답 없음 상태가 이어진 기록입니다. 1000은 예외 코드·모듈을, 1002는 멈춤 시점·작업·반복 빈도를 확인하세요.
