에러 코드 상세

0x00000079 · MISMATCHED_HAL

HAL과 커널 파일의 종류가 서로 맞지 않을 때 나타나는 코드입니다.

이 코드를 어떻게 해석해야 하나요?

오류 코드는 고장 부품을 확정하는 판정이 아니라 발생 시점과 함께 원인 범위를 좁히는 단서입니다. 최근 변경, 반복 조건, 안전 모드 재현 여부를 함께 기록하세요.

먼저 기록할 내용: 0x00000079가 발생한 시각, 직전에 실행한 작업, 최근 설치한 드라이버·업데이트, 재부팅 뒤 같은 코드가 반복되는지를 적어 두세요.

이 코드가 가리키는 것

이 코드는 자연스럽게 발생하기보다 시스템 파일이 수동으로 교체됐거나 BIOS 설정이 바뀐 뒤 나타납니다. 예전에는 단일 프로세서용과 다중 프로세서용 HAL이 섞였을 때 주로 발생했고, 요즘은 BIOS의 ACPI 관련 설정 변경이나 시스템 파일 임의 교체가 원인인 경우가 많습니다.

첫 점검 항목

  1. 최근 수동으로 바꾼 시스템 파일 되돌리기 — 문제 해결 목적으로 hal.dll이나 ntoskrnl.exe 같은 파일을 직접 교체한 적이 있으면 그 조치를 원래대로 돌립니다. 이런 수동 교체는 이 코드의 가장 직접적인 원인입니다.
  2. BIOS의 ACPI 관련 설정 확인 — BIOS에서 ACPI 모드나 전원 관리 관련 항목을 바꾼 적이 있으면 이전 값으로 되돌립니다. 기억나지 않으면 Load Optimized Defaults로 한 번에 기본값을 적용합니다.
  3. 복구 환경에서 시스템 파일 검사 — 설치 USB로 부팅해 명령 프롬프트를 열고 sfc /scannow /offbootdir=C:\ /offwindir=C:\Windows 형태로 오프라인 검사를 실행합니다. 드라이브 문자는 복구 환경에서 다를 수 있으므로 먼저 확인하세요.
  4. 복원 지점으로 되돌리기 — 복구 환경의 시스템 복원에서 문제 발생 이전 지점을 선택합니다. 복원 지점이 없다면 백업 후 정상 설치 미디어로 복구 설치를 검토합니다.

실제 사용자 사례

위 점검 순서로도 해결되지 않았을 때, 다른 원인으로 해결된 사례입니다.

메인보드 교체 후 재설치로 해결한 사례

메인보드를 새 제품으로 교체한 뒤 이전 윈도우가 설치된 디스크를 그대로 연결했더니 이 블루스크린이 발생했던 사례가 있습니다. 복구 환경에서 시스템 파일 복구를 시도해도 해결되지 않았고, 결국 새 하드웨어에 맞춰 윈도우를 새로 설치한 뒤에야 정상적으로 부팅됐습니다.

포인트: 메인보드나 CPU를 완전히 교체한 경우, 기존 설치를 복구하려 하기보다 처음부터 새로 설치하는 편이 더 빠르고 확실한 해결책이 될 수 있습니다.

데이터와 시스템을 보호하는 주의사항

원인이 확인되지 않은 상태에서 초기화, 레지스트리 수정, 시스템 파일 수동 교체를 먼저 진행하지 마세요.

앞 단계로 해결되지 않을 때

같은 코드가 반복되면 이벤트 로그와 장치 상태를 보존하고, 코드가 계속 달라지면 메모리·전원·온도처럼 시스템 전체 안정성을 확인하세요.

복구, 초기화, 드라이버 제거처럼 되돌리기 어려운 작업 전에는 중요한 파일을 다른 물리 저장장치나 신뢰할 수 있는 백업 위치에 보관하세요.

자주 묻는 질문

  • 블루스크린 코드가 한 번 떴는데 계속 지켜봐야 하나요? 이 문제(0x00000079)가 한 번만 발생했다면 즉시 부품을 교체하기보다 재현 여부와 최근 변경 사항을 먼저 기록해두는 것으로 충분합니다. 반복된다면 그때 하드웨어 점검 범위를 넓히세요.
  • 덤프 파일은 어디서 확인하나요? C:\Windows\Minidump 폴더에 저장되며, BlueScreenView 같은 도구로 열어 정지 코드와 관련 드라이버를 확인할 수 있습니다.
