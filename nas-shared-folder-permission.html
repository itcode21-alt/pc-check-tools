홈/NAS/공유폴더 접근 권한이 꼬여서 특정 PC·계정만 접속 안 됨

📑 목차

    계정/권한

    공유폴더 접근 권한이 꼬여서 특정 PC·계정만 접속 안 됨 원인과 점검 순서

    일부 계정이나 PC에서만 공유폴더 접근이 안 되거나, 상위 폴더는 보이는데 하위 폴더는 열리지 않는 경우

    NAS를 처음 설정할 때 가장 흔히 헷갈리는 부분이 권한 구조입니다. 공유폴더 자체의 권한과 그 안의 하위 폴더 권한이 따로 관리되고, 사용자와 그룹의 권한이 겹칠 때는 '가장 제한적인 쪽'이 최종 적용됩니다. 이 구조를 모르면 '권한을 줬는데도 왜 안 되지' 하는 혼란이 반복됩니다.

    특정 PC에서만 안 되는지, 특정 계정으로 로그인했을 때만 안 되는지부터 구분하면 권한 문제인지 다른 원인(자격 증명 캐시 등)인지 빠르게 좁힐 수 있습니다.

    이 가이드가 필요한 상황

    • 특정 계정으로 접속하면 공유폴더 자체가 안 보이거나 열리지 않는다.
    • 상위 폴더는 보이는데 그 안의 특정 하위 폴더만 접근이 안 된다.
    • 권한을 준 것 같은데도 여전히 읽기만 되고 쓰기가 안 된다.

    먼저 확인할 항목

    1. 공유폴더 자체 권한 확인 — 제어판 → 공유 폴더 → 해당 폴더 선택 → 편집 → 권한 탭에서 해당 사용자·그룹에 읽기 이상의 권한이 있는지 확인하세요.
    2. 하위 폴더 개별 권한 확인 — File Station에서 해당 하위 폴더 우클릭 → 속성 → 권한에서 개별 설정을 확인하세요.
    3. 그룹 간 권한 충돌 확인 — 사용자 및 그룹 → 해당 사용자 → 그룹 탭에서 소속된 모든 그룹을 확인하고, 그룹별 권한이 서로 충돌하지 않는지 점검하세요.
    4. '접근 거부' 기본값 확인 — 새로 만든 계정이나 그룹이라면 처음부터 필요한 폴더에 권한을 직접 부여했는지 확인하세요.

    원인을 더 정확히 나누는 방법

    권한 우선순위: 가장 제한적인 쪽이 이긴다

    시놀로지 DSM은 한 사용자가 여러 그룹에 속해 서로 다른 권한을 받을 경우, 그중 가장 제한적인 권한(예: 거부)을 최종적으로 적용합니다. 특정 그룹에서만 '거부'로 설정했다면 다른 그룹에서 '읽기/쓰기'를 줘도 결과적으로 접근이 막힙니다.

    하위 폴더 숨기기 옵션

    제어판 → 공유 폴더에서 '권한 없는 사용자에게 하위 폴더 및 파일 숨기기' 옵션을 켜면, 권한이 없는 사용자에게는 애초에 폴더 목록 자체가 보이지 않아 혼란을 줄일 수 있습니다.

    확인 결과에 따른 다음 단계

    • 특정 계정만 안 될 때 — 그 계정이 속한 그룹의 권한을 확인하세요. 다른 그룹에 '거부'가 걸려 있으면 그 계정에는 아무리 개별 권한을 줘도 소용없습니다.
    • 특정 하위 폴더만 안 될 때 — 상위 폴더 권한이 아니라 그 하위 폴더 자체에 별도로 걸린 권한을 확인하세요.

    자주 묻는 질문

    • 권한을 분명히 줬는데도 왜 접근이 안 되나요? 그 계정이 속한 다른 그룹에 '거부' 권한이 걸려 있을 수 있습니다. 시놀로지는 여러 권한이 충돌할 때 가장 제한적인 쪽을 우선 적용하므로, 소속된 모든 그룹의 권한을 함께 확인해야 합니다.
    • 하위 폴더마다 권한을 따로 설정할 수 있나요? 네. File Station에서 개별 폴더의 속성 → 권한에서 상위 폴더와 별개로 설정할 수 있습니다. 상위 폴더 권한과 하위 폴더 권한이 다르면 더 구체적으로 설정된 하위 폴더 권한이 적용됩니다.
