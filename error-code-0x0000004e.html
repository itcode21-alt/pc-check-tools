에러 코드 상세

0x0000004E · PFN_LIST_CORRUPT

물리 메모리 페이지 목록이 손상되었다는 뜻으로, 램 불안정과 커널 드라이버의 메모리 오용을 함께 확인해야 합니다.

이 코드를 어떻게 해석해야 하나요?

오류 코드는 고장 부품을 확정하는 판정이 아니라 발생 시점과 함께 원인 범위를 좁히는 단서입니다. 최근 변경, 반복 조건, 안전 모드 재현 여부를 함께 기록하세요.

먼저 기록할 내용: 0x0000004E가 발생한 시각, 직전에 실행한 작업, 최근 설치한 드라이버·업데이트, 재부팅 뒤 같은 코드가 반복되는지를 적어 두세요.

가능성 높은 원인

  • 램 모듈 불량이나 슬롯 접촉 불량으로 메모리 내용이 손상되는 경우
  • XMP/EXPO 또는 수동 메모리 오버클럭이 시스템에서 불안정한 경우
  • 드라이버가 메모리 페이지를 잘못 잠그거나 해제하는 경우
  • 가상화·보안·스토리지 필터 드라이버가 커널 메모리를 잘못 다루는 경우
  • PCIe 장치의 DMA 전송이나 메인보드 펌웨어 호환성 문제

첫 점검 항목

  1. 중요 파일을 먼저 백업한 뒤 BIOS에서 XMP/EXPO와 오버클럭을 기본값으로 되돌리세요. — 되돌리기 쉬운 항목부터 확인해 위험 없이 범위를 줄입니다.
  2. Windows 메모리 진단보다 긴 검사가 필요하면 MemTest86 등 부팅형 메모리 검사로 여러 패스를 진행하세요. — 첫 확인 결과와 비교해 소프트웨어와 하드웨어 가능성을 나눕니다.
  3. 램을 한 개씩 꽂고 슬롯을 바꿔 재현 여부를 비교해 모듈과 슬롯을 분리하세요. — 앞 단계에서 해결되지 않을 때 다음 원인 후보를 검증합니다.
  4. 블루스크린 직전 설치한 그래픽·네트워크·저장장치·가상화 드라이버를 업데이트하거나 롤백하세요. — 앞 단계에서 해결되지 않을 때 다음 원인 후보를 검증합니다.
  5. 덤프 분석에서 특정 드라이버가 반복 지목되지 않는다면 메모리와 메인보드의 기본 설정 상태를 우선 확인하세요. — 앞 단계에서 해결되지 않을 때 다음 원인 후보를 검증합니다.

데이터와 시스템을 보호하는 주의사항

원인이 확인되지 않은 상태에서 초기화, 레지스트리 수정, 시스템 파일 수동 교체를 먼저 진행하지 마세요.

앞 단계로 해결되지 않을 때

같은 코드가 반복되면 이벤트 로그와 장치 상태를 보존하고, 코드가 계속 달라지면 메모리·전원·온도처럼 시스템 전체 안정성을 확인하세요.

복구, 초기화, 드라이버 제거처럼 되돌리기 어려운 작업 전에는 중요한 파일을 다른 물리 저장장치나 신뢰할 수 있는 백업 위치에 보관하세요.

상세 해설

PFN 목록은 윈도우가 실제 물리 메모리 페이지를 관리하는 목록입니다. 이 목록이 손상됐다는 것은 메모리를 다루는 과정에서 잘못된 값이 기록됐다는 뜻이라, 램 불량이나 메모리 오버클럭, 메모리를 잘못 쓰는 드라이버가 대표적인 원인입니다. 하드웨어를 교체하기 전에 메모리 설정을 기본값으로 되돌리고 메모리 진단을 먼저 실행하세요.

관련 증상 가이드 확인하기

자주 묻는 질문

  • 블루스크린 코드가 한 번 떴는데 계속 지켜봐야 하나요? 이 문제(0x0000004E)가 한 번만 발생했다면 즉시 부품을 교체하기보다 재현 여부와 최근 변경 사항을 먼저 기록해두는 것으로 충분합니다. 반복된다면 그때 하드웨어 점검 범위를 넓히세요.
  • 덤프 파일은 어디서 확인하나요? C:\Windows\Minidump 폴더에 저장되며, BlueScreenView 같은 도구로 열어 정지 코드와 관련 드라이버를 확인할 수 있습니다.
