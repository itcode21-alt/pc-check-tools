에러 코드 상세

0x0000004E · PFN_LIST_CORRUPT

물리 메모리 페이지를 추적하는 PFN 목록이 손상됐다는 코드입니다. 문서는 목록 머리·항목의 손상, PTE 손상(하드웨어 비트 오류나 DMA 전송 오류가 원인일 수 있음), 드라이버가 페이지를 잠근 횟수보다 더 많이 푼 경우 등을 구분합니다.

이 코드를 어떻게 해석해야 하나요?

PFN 목록은 Windows가 물리 메모리 페이지가 지금 무엇에 쓰이는지 추적하는 장부입니다. Microsoft Learn은 첫 번째 매개변수로 손상 유형을 나눕니다. 목록 머리가 손상된 경우와 목록 항목이 손상된 경우가 있고, 하드웨어 PTE나 프로토타입 PTE가 손상된 경우는 하드웨어의 단일 비트 오류나 DMA 전송 오류가 원인일 수 있다고 합니다. 드라이버가 페이지를 잠근 횟수보다 더 많이 풀었을 때도 나오며, 일부 유형(예: 0x8D의 여유 페이지 목록 손상)은 하드웨어 문제일 가능성이 크다고 적습니다. 일반 사용자용 해결 절차는 문서에 없어서 아래 점검은 대부분 문서 외 일반 점검입니다.

가능성 높은 원인

  • 하드웨어의 단일 비트 오류나 DMA 전송 오류로 PTE 구조가 손상된 경우(문서 설명)
  • 여유 페이지 목록이 손상된 경우(문서는 하드웨어 문제일 가능성이 크다고 설명)
  • 드라이버가 페이지를 잠근 횟수보다 더 많이 푼 경우
  • PFN 목록의 머리나 항목이 손상된 경우

첫 점검 항목

  1. 공식 문서가 알려 주는 것: 블루스크린의 첫 번째 매개변수(손상 유형)를 기록하세요. 문서가 유형별로 원인(하드웨어 오류, 드라이버 잠금 오류 등)을 나누고 있어 같은 값이 반복되는지가 단서가 됩니다.
  2. 문서 외 일반 점검: 메모리 진단 도구(mdsched.exe 또는 MemTest86+)로 램을 점검하세요. 실제 검사 방법과 결과 해석 보기 →
  3. 문서 외 일반 점검: BIOS에서 XMP·EXPO나 오버클럭을 기본값으로 되돌려 증상이 사라지는지 확인하세요.
  4. 문서 외 일반 점검: 최근 설치하거나 업데이트한 드라이버, 특히 저장장치·그래픽·가상 장치 드라이버를 이전 버전으로 되돌려 재현 여부를 확인하세요.
  5. 문서 외 일반 점검: chkdsk와 sfc /scannow로 디스크와 시스템 파일 상태를 점검하세요.

확인 결과에 따른 다음 단계

  • 메모리 진단에서 오류가 나왔을 때 — 램 모듈을 하나씩 꽂아 오류가 나는 모듈과 슬롯을 가려내세요. 모듈 분리는 문서 외 일반 조치입니다. 불량 모듈은 보증 기간 안에 교체를 신청하세요.
  • XMP·EXPO를 끄면 사라질 때 — 기본 클럭에서 안정적인지 며칠 지켜보세요. 다시 켜려면 전압과 타이밍을 낮춰 시험하세요. 이 사이트에는 EXPO를 해제해 해결된 사례가 있습니다.
  • 특정 드라이버를 되돌리면 사라질 때 — 그 드라이버 업데이트는 보류하고 제조사가 수정 버전을 내는지 확인하세요. 문서는 드라이버가 페이지를 잘못 풀어 생기는 유형도 설명합니다.

데이터와 시스템을 보호하는 주의사항

원인이 확인되지 않은 상태에서 초기화, 레지스트리 수정, 시스템 파일 수동 교체를 먼저 진행하지 마세요.

앞 단계로 해결되지 않을 때

같은 코드가 반복되면 이벤트 로그와 장치 상태를 보존하고, 코드가 계속 달라지면 메모리·전원·온도처럼 시스템 전체 안정성을 확인하세요.

복구, 초기화, 드라이버 제거처럼 되돌리기 어려운 작업 전에는 중요한 파일을 다른 물리 저장장치나 신뢰할 수 있는 백업 위치에 보관하세요.

자주 묻는 질문

  • PFN 목록 손상은 램이 불량이라는 뜻인가요? 그렇게 단정할 수는 없습니다. Microsoft Learn은 하드웨어 비트 오류와 DMA 전송 오류, 여유 페이지 목록 손상은 하드웨어 문제일 가능성이 크다고 하지만, 드라이버가 페이지를 잘못 푼 경우도 같은 코드로 나옵니다.
  • 블루스크린 첫 번째 값은 무엇을 뜻하나요? 손상 유형입니다. 문서는 목록 머리 손상, 목록 항목 손상, PTE 구조 손상, 여유 페이지 목록 손상(0x8D) 등으로 나누고 유형별로 매개변수 의미가 다르다고 설명합니다.
