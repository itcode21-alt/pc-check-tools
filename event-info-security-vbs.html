가상화 기반 보안(VBS)·Credential Guard·TPM 정보 기록 정리

메모리 무결성(VBS·HVCI), Windows Hello, TPM, Credential Guard가 켜진 PC는 부팅할 때마다 보안 기능이 시작됐다는 정보 기록을 남깁니다. 기록이 많이 보여도 정상 동작의 증거입니다.

Hyper-V-Hypervisor 1이 부팅 때마다 보이는 것은 하이퍼바이저가 정상 시작됐다는 뜻이며, 메모리 무결성(VBS)이나 WSL2·가상 머신 기능을 쓰면 남습니다. 가상 머신을 안 쓰더라도 VBS 때문에 보일 수 있습니다.

값이 0으로 적힌 항목(예: LsaSrv 6156, Wininit 14)은 해당 기능의 조건을 충족하지 않거나 쓰지 않는다는 뜻이지 오류가 아닙니다. 이 묶음에서 실제로 확인할 가치가 있는 값은 아래 '걱정해야 하는 때'에 정리했습니다.

원본·ID의미확인할 때
Hyper-V-Hypervisor 1하이퍼바이저(Hyper-V 계층)가 정상적으로 시작되었음을 기록합니다. 메모리 무결성(VBS)이나 WSL2·가상 머신 기능을 쓰면 부팅 때마다 남습니다.가상화 기능을 끄고 싶다면 Windows 기능과 메모리 무결성 설정 확인
Hyper-V-Hypervisor 2하이퍼바이저 스케줄러 유형(SchedulerType)을 기록합니다.가상 머신 성능 문제를 조사할 때 참고
Hyper-V-Hypervisor 129하이퍼바이저가 I/O 리매핑(IOMMU)을 초기화한 결과(하드웨어 존재·사용 여부, Problems 값)를 기록합니다. Problems가 0x0이면 문제가 없다는 뜻입니다.Problems 값이 0이 아니면 BIOS의 IOMMU·가상화 설정 확인
Hyper-V-Hypervisor 156가상 머신용 CPU 취약점(CVE-2018-3646) 완화 설정을 하이퍼바이저가 적용한 내용을 기록합니다.성능 저하가 우려되면 가상화 보안 기능 사용 여부와 함께 확인
Hyper-V-Hypervisor 165가상 머신용 CPU 취약점(MDS 계열 CVE) 완화 설정을 하이퍼바이저가 적용한 내용을 기록합니다.성능 저하가 우려되면 가상화 보안 기능 사용 여부와 함께 확인
IsolatedUserMode 1보안 격리 영역에서 Secure Trustlet(예: NgcIso.exe, Windows Hello 관련)이 시작되었음을 기록합니다. status가 STATUS_SUCCESS면 성공입니다.STATUS_SUCCESS가 아닌 경우에만 해당 Trustlet과 상태 확인
IsolatedUserMode 2Secure Trustlet이 종료되었음을 기록합니다.반복 횟수가 많아도 로그인·종료 때마다 남아 정상
IsolatedUserMode 3Secure Kernel(가상화 기반 보안)이 시작되었음을 기록합니다. flags에 HvciEnabled가 있으면 메모리 무결성(HVCI)이 켜진 상태입니다.호환되지 않는 드라이버 때문에 메모리 무결성을 끄는 경우 이 flags 변화를 참고
IsolatedUserMode 5Secure Trustlet이 시작되었음을 기록합니다(이미지 이름이 NULL인 기본 항목 포함).STATUS_SUCCESS가 아닌 경우에만 확인
Kernel-Boot 153가상화 기반 보안(VBS)이 사용 설정되어 있고 그 이유(레지스트리 구성 등)를 기록합니다.같은 번호의 Disk 153·nvlddmkm 153과 무관 — 원본이 Kernel-Boot인지 확인
Wininit 12LSASS.exe가 보호된 프로세스(protected process)로 시작되었음을 기록합니다.보안 프로그램 충돌이 의심될 때 참고
Wininit 14Credential Guard 구성 값(레지스트리 설정, 테스트 구성, 자동 사용 여부)을 기록합니다.Credential Guard를 쓰려는 환경이면 값 확인
Wininit 18VBS 키 격리가 시작되어 VSM으로 격리된 키를 보호하기 시작했음을 기록합니다.가상화 기반 보안을 끈 환경이면 나타나지 않음
Wininit 19가상화 기반 보안의 타이머 생성 결과(HRESULT)를 기록합니다. 성공이면 문제가 없습니다.HRESULT가 성공이 아닌 경우에만 확인
LsaSrv 6156부팅 때 Credential Guard 자동 사용 여부를 판단한 결과(가상화 기반 보안 하드웨어 요건, 도메인 가입 여부, 라이선스)를 기록합니다.Credential Guard를 쓰려는 환경이면 각 항목 값을 확인
HAL 16IOMMU 오류 보고 기능이 초기화되었음을 기록합니다.장치 DMA 오류를 조사할 때 참고
TPM-WMI 1025TPM(신뢰 플랫폼 모듈)이 성공적으로 프로비저닝되어 사용 준비가 되었음을 기록합니다.TPM 관련 오류가 있을 때만 tpm.msc에서 상태 확인
TPM-WMI 1046측정된 부팅(Measured Boot) 로그 파일을 정리(삭제)했음을 기록합니다.삭제된 파일 경로가 MeasuredBoot 폴더인지 확인
TPM-WMI 1282TBS(TPM 기본 서비스) 장치 식별자가 생성되었음을 기록합니다.TPM 관련 오류가 있을 때만 상태 확인
TPM 18TPM 프로비저닝·상태 점검이 실행되도록 하는 기록입니다.TPM 관련 오류가 있을 때만 tpm.msc에서 상태 확인
Directory-Services-SAM 16962SAM(계정 데이터베이스)에 대한 원격 호출이 기본 보안 설명자로 제한되고 있음을 기록합니다.보안 정책을 점검할 때 참고
Directory-Services-SAM 16977최소 암호 길이 관련 설정 값(MinimumPasswordLength 등)을 기록합니다.암호 정책을 점검할 때 참고
Directory-Services-SAM 16983원격 클라이언트의 예전 방식 암호 변경 호출에 대한 주기적 요약 이벤트를 남기기 시작했음을 기록합니다.보안 정책을 점검할 때 참고

걱정해야 하는 때

  • Hyper-V-Hypervisor 129의 Problems 값이 0x0이 아니면 BIOS의 IOMMU·가상화 설정을 확인합니다.
  • IsolatedUserMode 1·5의 status가 STATUS_SUCCESS가 아닐 때만 해당 Trustlet(예: Windows Hello 관련 NgcIso.exe)을 확인합니다.
  • IsolatedUserMode 3의 flags에 HvciEnabled가 있으면 메모리 무결성이 켜진 상태입니다. 호환되지 않는 드라이버 때문에 메모리 무결성을 끈 경우 이 flags가 달라집니다.
  • Wininit 19·23·25는 HRESULT, Wininit 24는 Win32Error가 성공(0)이 아닐 때만 확인합니다.
  • TPM 관련 오류(경고·오류 수준)가 따로 있을 때만 tpm.msc로 상태를 확인합니다. BitLocker 복구 키를 확보하기 전에 TPM을 초기화하지 마세요.
  • Directory-Services-SAM 기록은 Windows의 기본 보안 강화·감사 동작입니다. 암호 정책을 점검하는 경우가 아니면 볼 필요가 없습니다.
주의사항

정보 수준 기록 하나만으로 부품 고장이나 보안 사고를 판단하지 마세요. 같은 시각의 오류·경고 기록과 실제 증상(끊김, 재부팅, 느려짐)이 함께 있을 때만 단서로 씁니다.

자주 묻는 질문

  • Hyper-V를 쓰지 않는데 Hyper-V-Hypervisor 기록이 남아요. 메모리 무결성(VBS)이나 WSL2·샌드박스처럼 하이퍼바이저를 쓰는 기능이 켜져 있으면 가상 머신을 직접 쓰지 않아도 부팅 때마다 남습니다. 끄고 싶다면 Windows 기능과 메모리 무결성 설정을 확인하세요.
  • LsaSrv 6156이나 Wininit 14의 값이 0인데 괜찮은가요? 괜찮습니다. 값 0은 Credential Guard를 자동 사용하는 조건(가상화 기반 보안 하드웨어 요건, 도메인 가입 여부, 라이선스)을 충족하지 않거나 쓰지 않는다는 뜻입니다. Credential Guard를 쓰려는 환경일 때만 각 값을 확인하세요.
  • Kernel-Boot 153이 보이는데 디스크 오류인가요? 아닙니다. 원본이 Kernel-Boot인 153은 가상화 기반 보안이 사용 설정되어 있다는 부팅 보안 기록입니다. Disk 153(입출력 재시도)이나 nvlddmkm 153(그래픽)과는 무관합니다.
