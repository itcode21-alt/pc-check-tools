에러 코드 상세

0x00000080 · NMI_HARDWARE_FAILURE

하드웨어 오작동으로 NMI(마스크할 수 없는 인터럽트)가 발생했을 때 나오는 코드입니다. 문서는 최근 설치한 하드웨어나 드라이버를 제거하고 모든 메모리 모듈이 같은 종류인지 확인하라고 안내합니다.

이 코드를 어떻게 해석해야 하나요?

다양한 하드웨어 오작동이 이 코드를 일으킬 수 있어 정확한 원인을 가리기 어렵다고 문서는 설명합니다. 매개변수는 없습니다. 문서가 사용자에게 안내하는 점검은 두 가지입니다. 최근에 설치한 하드웨어나 드라이버를 제거해 보는 것, 그리고 모든 메모리 모듈이 같은 종류인지 확인하는 것입니다. 나머지 점검은 문서 외 일반 점검입니다.

이 코드가 가리키는 것

원인 후보(문서 설명 기준): 여러 종류의 하드웨어 오작동(문서는 정확한 원인을 알아내기 어렵다고 설명); 최근 설치한 하드웨어나 드라이버; 서로 종류가 다른 메모리 모듈이 섞여 있는 경우(문서의 점검 항목).

첫 점검 항목

  1. 공식 문서가 알려 주는 것: 최근에 설치한 하드웨어나 드라이버를 제거하고 재현되는지 보세요.
  2. 공식 문서가 알려 주는 것: 메모리 모듈이 모두 같은 종류인지 확인하세요.
  3. 문서 외 일반 점검: 메모리 진단 도구(mdsched.exe 또는 MemTest86+)로 램을 점검하고, 램을 한 개씩 꽂아 특정 모듈이나 슬롯에서만 재현되는지 확인하세요.
  4. 문서 외 일반 점검: BIOS의 XMP·EXPO와 오버클럭을 기본값으로 되돌리고, 파워서플라이와 케이블 연결을 점검하세요.

확인 결과에 따른 다음 단계

  • 최근 추가한 하드웨어를 빼면 사라질 때 — 그 장치를 빼 둔 채 사용해 보고, 제조사에 호환 정보나 업데이트가 있는지 확인하세요.
  • 메모리 모듈 구성을 바꾸면 사라질 때 — 같은 제조사·같은 규격의 모듈로 맞추세요. 문서가 모든 메모리 모듈이 같은 종류인지 확인하라고 안내합니다.
  • 메모리 진단에서 오류가 나올 때 — 램 모듈을 하나씩 꽂아 불량 모듈이나 슬롯을 가려내세요. 이 사이트에는 MemTest86으로 불량 램 슬롯을 찾아 해결한 사례가 있습니다. 슬롯 분리 점검은 문서 외 일반 조치입니다.

해결 사례 예시

위 점검 순서로도 해결되지 않았을 때 다른 원인으로 해결될 수 있는 예시입니다. 실제 제보를 그대로 옮긴 것이 아니라 일반적인 사례를 바탕으로 구성한 참고용 예시이며, 환경에 따라 결과가 다를 수 있습니다.

MemTest86로 불량 램 슬롯을 특정해 해결한 사례

몇 주간 불규칙하게 NMI_HARDWARE_FAILURE 블루스크린이 발생했던 사례가 있습니다. MemTest86을 돌려보니 특정 슬롯에 꽂힌 램에서만 수백 개의 오류가 나왔고, 해당 램을 교체한 뒤로 블루스크린이 완전히 멈췄습니다.

포인트: 많은 NMI 오류가 램이 완전히 고장 나서가 아니라 슬롯 접촉 불량이나 특정 모듈만의 불량 때문에 발생합니다. 우선 램을 재장착해보고, 그래도 반복되면 MemTest86으로 스틱별로 나눠 테스트해보세요.

데이터와 시스템을 보호하는 주의사항

원인이 분명하지 않은데 초기화·레지스트리 수정·시스템 파일 교체 같은 조치를 먼저 시도하면 오히려 문제가 커질 수 있습니다.

앞 단계로 해결되지 않을 때

같은 코드가 반복되면 이벤트 로그와 장치 상태를 보존하고, 코드가 계속 달라지면 메모리·전원·온도처럼 시스템 전체 안정성을 확인하세요.

시스템 복구나 초기화, 드라이버 삭제처럼 원상복구가 힘든 작업을 시작하기 전에, 중요한 파일은 미리 외장 저장장치나 별도 위치에 백업해 두세요.

Microsoft Learn: Windows Debugger 문서

자주 묻는 질문

  • NMI가 무엇인가요? 마스크할 수 없는 인터럽트(Non-Maskable Interrupt)로, 보통 심각한 하드웨어 오류를 알리는 신호입니다. Microsoft Learn은 이 코드의 원인을 다양한 하드웨어 오작동으로 설명합니다.
  • 램 종류를 맞추는 것이 왜 필요한가요? 문서가 점검 항목으로 안내합니다. 종류가 다른 모듈이 섞이면 동작이 불안정해질 수 있다는 정도로만 설명할 수 있고, 구체적인 이유는 문서에 없습니다.
