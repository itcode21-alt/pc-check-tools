📑 목차

에러 코드 상세

0x00000080 · NMI_HARDWARE_FAILURE

하드웨어가 마스크 불가 인터럽트(NMI)로 직접 보고한 오류입니다.

이 코드를 어떻게 해석해야 하나요?

오류 코드는 원인 후보를 좁히는 단서일 뿐, 고장 부품을 확정하는 근거는 아닙니다. 최근에 무엇이 바뀌었는지, 어떤 조건에서 반복되는지, 안전 모드에서도 재현되는지를 함께 기록해두세요.

먼저 기록할 내용: 0x00000080가 발생한 시각, 직전에 실행한 작업, 최근 설치한 드라이버·업데이트, 재부팅 뒤 같은 코드가 반복되는지를 적어 두세요.

이 코드가 가리키는 것

NMI는 소프트웨어가 무시할 수 없는 신호로, 하드웨어가 직접 문제를 보고했다는 뜻입니다. 따라서 이 코드는 드라이버 재설치나 Windows 복구로 해결될 가능성이 낮습니다. 메모리 패리티 오류, 메인보드 결함, 전원 이상 순으로 확인하는 편이 맞습니다.

첫 점검 항목

  1. 메모리 교차 시험 — 메모리를 한 개씩만 장착해 부팅하며 어느 쪽에서 재현되는지 확인합니다. 슬롯도 바꿔 가며 시험해 메모리 불량과 슬롯 불량을 구분합니다.
  2. 확장카드와 주변장치 최소 구성으로 축소 — 그래픽카드를 제외한 확장카드를 모두 빼고, USB 장치도 키보드·마우스만 남깁니다. 최소 구성에서 재현되지 않으면 하나씩 되꽂으며 원인 장치를 찾습니다.
  3. 전원 공급 상태 확인 — 24핀 메인 전원과 CPU 보조전원의 체결을 다시 확인하고, 멀티탭 대신 벽면 콘센트에 직접 연결해 봅니다. 다른 파워서플라이로 교체해 볼 수 있으면 가장 확실한 구분이 됩니다.
  4. 제조사 하드웨어 진단 실행 — 브랜드 PC나 노트북이라면 제조사가 제공하는 하드웨어 진단(부팅 시 전용 키로 진입)을 실행합니다. 메인보드 결함이 의심되면 보증 기간 내 서비스 접수를 우선하세요.

확인 결과에 따른 다음 단계

  • 메모리 교차 시험으로 해결될 때 — 사례처럼 문제 모듈을 교체하세요.
  • 최소 구성으로 재현되지 않을 때 — 장치를 하나씩 되꽂으며 원인 장치를 특정하세요.
  • 전원 점검으로도 해결되지 않을 때 — 제조사 진단이나 서비스 접수로 넘어가세요.

실제 사용자 사례

위 점검 순서로도 해결되지 않았을 때, 다른 원인으로 해결된 사례입니다.

MemTest86로 불량 램 슬롯을 특정해 해결한 사례

몇 주간 불규칙하게 NMI_HARDWARE_FAILURE 블루스크린이 발생했던 사례가 있습니다. MemTest86을 돌려보니 특정 슬롯에 꽂힌 램에서만 수백 개의 오류가 나왔고, 해당 램을 교체한 뒤로 블루스크린이 완전히 멈췄습니다.

포인트: 많은 NMI 오류가 램이 완전히 고장 나서가 아니라 슬롯 접촉 불량이나 특정 모듈만의 불량 때문에 발생합니다. 우선 램을 재장착해보고, 그래도 반복되면 MemTest86으로 스틱별로 나눠 테스트해보세요.

데이터와 시스템을 보호하는 주의사항

원인이 분명하지 않은데 초기화·레지스트리 수정·시스템 파일 교체 같은 조치를 먼저 시도하면 오히려 문제가 커질 수 있습니다.

앞 단계로 해결되지 않을 때

같은 코드가 반복되면 이벤트 로그와 장치 상태를 보존하고, 코드가 계속 달라지면 메모리·전원·온도처럼 시스템 전체 안정성을 확인하세요.

시스템 복구나 초기화, 드라이버 삭제처럼 원상복구가 힘든 작업을 시작하기 전에, 중요한 파일은 미리 외장 저장장치나 별도 위치에 백업해 두세요.

자주 묻는 질문

  • 블루스크린 코드가 한 번 떴는데 계속 지켜봐야 하나요? 이 문제(0x00000080)가 한 번만 발생했다면 즉시 부품을 교체하기보다 재현 여부와 최근 변경 사항을 먼저 기록해두는 것으로 충분합니다. 반복된다면 그때 하드웨어 점검 범위를 넓히세요.
  • 덤프 파일은 어디서 확인하나요? C:\Windows\Minidump 폴더에 저장되며, BlueScreenView 같은 도구로 열어 정지 코드와 관련 드라이버를 확인할 수 있습니다.
  • NMI 오류는 항상 하드웨어 고장을 의미하나요? 대부분 하드웨어 신호지만 접촉 불량처럼 완전 고장이 아닌 경우도 많으므로, 재장착과 교차 테스트를 먼저 시도하는 것이 합리적입니다.
