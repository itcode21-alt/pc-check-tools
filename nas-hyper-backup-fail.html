    백업

    Hyper Backup 백업 작업이 실패하거나 멈춤 원인과 점검 순서

    Hyper Backup으로 예약한 백업이 실패하거나, 작업 상태가 '복원 전용'으로 바뀌어 더 이상 백업이 진행되지 않는 경우

    Hyper Backup은 한 번 설정해두면 알아서 예약 실행되기 때문에, 오히려 오랫동안 방치하다가 실제로 필요한 순간에야 '몇 년째 백업이 안 되고 있었다'는 것을 뒤늦게 발견하는 사례가 흔합니다. 정기적으로 작업 상태를 확인하는 습관이 무엇보다 중요합니다.

    실패 상태와 '복원 전용' 상태는 원인이 다릅니다. 실패는 대개 공간·연결 문제로 재시도하면 해결되지만, '복원 전용'은 원본과 백업본의 구조가 어긋나 더 이상 새 백업을 추가할 수 없는 상태로, 새 작업을 다시 만들어야 합니다.

    이 가이드가 필요한 상황

    • 백업 작업 목록에서 상태가 실패(빨간색)로 계속 표시된다.
    • 작업 상태가 '복원 전용(Restore Only)'으로 바뀌어 있다.
    • 알림을 꺼두거나 확인하지 않아 백업이 오랫동안 중단된 걸 몰랐다.

    먼저 확인할 항목

    1. 백업 대상 여유 공간 확인 — 백업 대상 장치(외장하드, 원격 NAS 등)의 여유 공간을 확인하고, 부족하다면 오래된 백업 버전을 정리하거나 용량을 늘리세요.
    2. 실패 로그 확인 — Hyper Backup → 해당 작업 선택 → 로그에서 최근 실패 기록의 상세 메시지를 확인하세요.
    3. '복원 전용' 상태 확인 및 재구성 — 작업 상태가 '복원 전용'이라면 기존 작업은 과거 데이터 복원용으로만 남겨두고, 새 백업 작업을 처음부터 다시 생성하세요.
    4. 백업 알림 설정 확인 — 제어판 → 알림에서 백업 실패 시 이메일·푸시 알림을 받도록 설정하세요.

    원인을 더 정확히 나누는 방법

    '복원 전용' 상태가 생기는 이유

    백업 작업을 오래 방치하거나, 원본 볼륨을 재구성·재설치하면 백업본의 증분 체인이 원본과 어긋나게 됩니다. 이 경우 시놀로지는 데이터 손실을 막기 위해 해당 작업을 복원 전용으로 전환하고, 더 이상 그 작업으로는 새 백업을 쌓지 못하게 합니다.

    백업이 '되고 있는 줄 알았던' 사고를 막는 법

    백업은 설정하는 것보다 '되고 있는지 주기적으로 확인하는 것'이 더 중요합니다. 알림을 켜두고, 분기에 한 번 정도는 실제로 복원 테스트를 해보는 것이 안전합니다.

    확인 결과에 따른 다음 단계

    • 용량 확보 후 정상화될 때 — 저장 공간 부족이 원인이었던 것입니다. 앞으로는 백업 대상 용량에 여유를 두고, 보관 버전 수를 정책으로 관리하세요.
    • '복원 전용' 상태일 때 — 기존 작업 수정으로는 해결되지 않습니다. 기존 백업은 복원용으로 보관하고, 새 백업 작업을 만들어 처음부터 다시 시작하세요.

    자주 묻는 질문

    • 몇 년간 백업이 안 되고 있었다는 걸 뒤늦게 알았어요. 지금이라도 고칠 수 있나요? 가능합니다. 먼저 실패 로그로 원인을 확인하고, 용량·연결 문제를 해결한 뒤에도 계속 실패하거나 '복원 전용' 상태라면 새 백업 작업을 다시 만드는 것이 가장 확실합니다. 이후에는 알림을 켜서 같은 일이 반복되지 않게 하세요.
    • '복원 전용' 상태인 작업은 그냥 삭제해도 되나요? 기존 백업 데이터로 복원할 계획이 없다면 삭제해도 됩니다. 다만 과거 데이터가 필요할 수 있다면 삭제하지 말고 복원 전용으로 남겨둔 채, 새 백업 작업을 별도로 만드세요.
