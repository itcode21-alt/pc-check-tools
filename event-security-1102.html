Security 1102 감사 로그 지움 점검

감사 로그가 지워졌음을 기록합니다. 관리 목적으로 지우는 경우도 있지만, 침해 사고 후 흔적 삭제 시도로도 나타납니다.

1102는 보안 감사 로그가 지워졌다는 기록입니다. 관리자가 의도적으로 로그를 정리한 경우도 있지만, 침해 사고 뒤 흔적을 지우려는 시도로도 나타날 수 있어 누가·언제 지웠는지 반드시 확인해야 합니다.

본인이나 IT 담당자가 지운 기억이 없는 상태에서 이 이벤트가 나타났다면, 삭제 직전 로그인 기록과 실행된 프로그램 흔적을 다른 로그(예: 시스템 로그)에서 함께 대조해보세요.

발생 조건

  • 보안 이벤트 로그 초기화 후
  • 악성 소프트웨어 감염 의심 상황

가능성 높은 원인

  • 관리자의 의도적인 로그 삭제
  • 악성 소프트웨어에 의한 로그 삭제

점검 순서

  1. 로그를 삭제한 계정 이름과 시각 확인 — 되돌리기 쉬운 항목부터 확인해 위험 없이 범위를 줄입니다.
  2. 삭제 전후 비정상적인 로그인 또는 실행 흔적 비교 — 첫 확인 결과와 비교해 원인 후보를 좁힙니다.
  3. 의도치 않은 삭제라면 보안 점검을 진행하세요 — 앞 단계에서 해결되지 않을 때 다음 원인을 검증합니다.
주의사항

의도하지 않은 보안 로그 삭제는 보안 사고의 신호일 수 있습니다.

자주 묻는 질문

  • 1102가 있으면 무조건 해킹인가요? 아닙니다. 관리 목적의 정상적인 로그 정리에서도 남습니다. 다만 지운 기억이 없다면 이벤트의 계정 이름과 시각을 확인해 본인·IT 담당자의 작업이 맞는지부터 확인하세요.
  • 로그가 지워지면 이전 기록은 복구할 수 없나요? 기본적으로 지워진 이벤트 로그 자체는 복구가 어렵습니다. 정기적으로 로그를 파일로 내보내 보관하면 이런 상황에서도 이전 기록을 확인할 수 있습니다.
