    WINDOWS UPDATE

    윈도우 업데이트 오류 완벽 정리 — 원인별로 찾는 오류 코드 21개

    Windows 업데이트가 실패하는 원인은 코드마다 완전히 다릅니다. 네트워크 문제인지, 디스크 공간 부족인지, 시스템 파일 손상인지에 따라 점검 순서가 달라지므로, 코드를 먼저 확인하는 것이 재시도를 반복하는 것보다 빠릅니다. 이 페이지는 업데이트 실패 시 공통으로 확인할 절차와, 이 사이트가 다루는 오류 코드 21개를 원인별로 정리했습니다.

    업데이트가 실패하면 가장 먼저 확인할 것

    1. 디스크 여유 공간: 설정 → 시스템 → 저장공간에서 C드라이브 여유 공간이 20GB 이상인지 확인하세요. 대형 기능 업데이트일수록 임시 공간을 많이 요구합니다.
    2. 인터넷 연결 안정성: VPN이나 사내망을 사용 중이라면 잠시 끄고 재시도해보세요. 회사·학교 네트워크는 업데이트 서버 접속을 차단하는 경우가 있습니다.
    3. 화면에 뜬 코드 정확히 기록: "업데이트 실패" 알림을 클릭하면 코드가 표시됩니다. 코드에 따라 아래에서 바로 해당 원인 계열을 찾아 이동하세요.

    코드와 무관하게 먼저 시도할 공통 점검 절차

    1. 1단계 - Windows Update 문제 해결사: 설정 → 시스템 → 문제 해결 → 기타 문제 해결사에서 "Windows Update"를 실행하면 흔한 원인 상당수를 자동으로 감지·수정합니다.
    2. 2단계 - 업데이트 캐시 초기화: 관리자 권한 명령 프롬프트에서 wuauserv, bits, cryptsvc 서비스를 중지한 뒤 C:\Windows\SoftwareDistribution과 C:\Windows\System32\catroot2 폴더 내용을 비우고 서비스를 다시 시작하세요. 캐시가 손상되어 같은 코드로 반복 실패하는 사례에 특히 효과적입니다.
    3. 3단계 - 시스템 파일·구성 요소 복구: DISM /Online /Cleanup-Image /RestoreHealth 실행 후 sfc /scannow를 이어서 실행하세요. 구성 요소 저장소(WinSxS) 손상이 원인인 코드에서는 이 단계가 핵심입니다.
    4. 4단계 - 클린 부팅 후 재시도: 클린 부팅 상태에서 업데이트를 다시 시도해, 백신·서드파티 프로그램의 간섭 여부를 분리하세요.
    5. 5단계 - 이벤트 뷰어로 실패 지점 확인: Windows 로그 → 시스템에서 원본이 "WindowsUpdateClient"인 오류를 찾으면, 어느 단계에서 실패했는지 더 정확히 알 수 있습니다. 사용법은 이벤트 뷰어 가이드를 참고하세요.

    원인별로 찾는 오류 코드 21개

    아래에서 증상과 가까운 카테고리를 먼저 고르세요. 각 코드를 누르면 원인·점검 순서·공식 자료를 담은 상세 페이지로 이동합니다.

    네트워크·서버 연결 문제 (7개)

    업데이트 서버와의 통신이 DNS·타임아웃·보안 연결 단계에서 끊기는 경우입니다. VPN·보안 프로그램·공유기 DNS 설정을 먼저 의심하세요.

    • 0x800705b4 · 작업 시간 초과 — 업데이트나 특정 작업이 정해진 시간 안에 완료되지 못하고 시간 초과로 중단됐을 때 나타나는 오류입니다.
    • 0x8007232B · DNS 이름을 확인할 수 없음 — 업데이트 서버나 활성화 서버의 도메인 이름을 DNS가 확인하지 못했을 때 나타나는 오류입니다.
    • 0x8007274C · 네트워크 요청 시간 초과 — 서버로 보낸 요청이 정해진 시간 안에 응답을 받지 못했을 때 나타나는 오류로, 네트워크 지연이나 서버 응답 지연이 주요 원인입니다.
    • 0x80072EFD · 서버에 연결할 수 없음 — 앱이나 서비스가 원격 서버에 접속을 시도했지만 연결 자체가 이루어지지 않을 때 나타나는 오류입니다.
    • 0x80072F8F · 보안 연결 실패·시스템 시간 오류 — Windows Update나 Microsoft Store가 보안 연결을 만들지 못할 때 나타나며, 날짜·시간과 인증서 신뢰 상태를 먼저 확인해야 합니다.
    • 0x8024402C · WU_E_PT_WINHTTP_NAME_NOT_RESOLVED 서버 연결 실패 — 윈도우 업데이트 클라이언트가 마이크로소프트 업데이트 서버의 주소를 확인(DNS)하지 못했을 때 나타나는 오류입니다.
    • 0x8024a105 · 업데이트 다운로드 실패 — 업데이트 파일을 서버에서 내려받는 도중 연결이 끊기거나 검증에 실패했을 때 나타나는 코드입니다.

    디스크 공간·리소스 부족 (4개)

    업데이트 파일을 내려받고 적용할 공간이나 메모리가 부족할 때 나타납니다. C드라이브 여유 공간(권장 20GB 이상)을 가장 먼저 확인하세요.

    • 0x80070003 · 지정된 경로를 찾을 수 없음 — 설치나 업데이트, 파일 접근 시 시스템이 지정된 경로 자체를 찾지 못했을 때 나타나는 오류로, 경로 손상이나 이동된 폴더가 주요 원인입니다.
    • 0x8007000e · 메모리 또는 시스템 리소스 부족 — 업데이트나 프로그램 실행에 필요한 메모리 또는 시스템 리소스가 부족할 때 나타나는 오류로, 실제 램 부족뿐 아니라 가상 메모리 설정 문제로도 발생할 수 있습니다.
    • 0x80070020 · 파일이 다른 프로세스에서 사용 중 — 업데이트나 설치가 필요로 하는 파일을 다른 프로그램이나 프로세스가 이미 점유하고 있어 접근이 거부될 때 나타나는 오류입니다.
    • 0x80070070 · 디스크 공간 부족 — Windows 업데이트, 앱 설치, 임시 파일 생성에 필요한 여유 공간이 부족할 때 나타나는 코드입니다.

    구성 요소 저장소(WinSxS)·시스템 파일 손상 (5개)

    업데이트 적용에 필요한 시스템 파일 저장소 자체가 손상된 경우로, DISM 복구가 다른 어떤 조치보다 우선입니다.

    • 0x80073712 · 구성 요소 저장소 손상 오류 — 업데이트 설치에 필요한 시스템 파일이 저장된 구성 요소 저장소(WinSxS)의 일부가 손상되었을 때 나타나는 오류입니다.
    • 0x800F081F · 원본 파일을 찾을 수 없음 — Windows 기능 추가나 복구 과정에서 필요한 구성 요소 원본을 찾지 못할 때 보이는 코드입니다.
    • 0x800F0831 · Windows 구성 요소 저장소 손상 — Windows 업데이트에 필요한 구성 요소 패키지를 찾거나 적용하지 못할 때 나타나는 코드입니다.
    • 0x800F0983 · CBS 매니페스트 손상 오류 — 누적 업데이트 설치 중 CBS 매니페스트 손상으로 설치가 롤백될 때 나타나는 코드입니다.
    • 0x800f0821 · 업데이트 패키지 설치 실패 — 다운로드까지는 완료됐지만 실제 설치 단계에서 패키지 적용에 실패했을 때 나타나는 코드입니다.

    서비스·인증서·드라이버 설정 (3개)

    Windows Update 관련 서비스가 꺼져 있거나, 시스템 시간·인증서·드라이버 호환성 문제로 설치가 막히는 경우입니다.

    • 0x80070422 · 필요한 서비스가 비활성화됨 — Windows Update나 관련 서비스가 중지 또는 비활성화되어 작업을 진행하지 못할 때 나타날 수 있습니다.
    • 0x800B0101 · 인증서 유효 기간 오류 — 업데이트 파일의 인증서가 만료됐거나 시스템 시간이 잘못되어 서명 검증에 실패할 때 나타날 수 있습니다.
    • 0xC1900101 · 업데이트 드라이버 호환성 실패 — Windows 기능 업데이트 중 드라이버가 설치 또는 롤백 단계에서 충돌할 때 자주 보이는 코드입니다.

    원인 불명확한 포괄 오류 (2개)

    구체적인 원인 없이 실패했다는 포괄적인 코드로, 이벤트 뷰어에서 실제 실패 단계를 먼저 확인해야 합니다.

    • 0x80240034 · WU_E_UNKNOWN 알 수 없는 업데이트 오류 — 윈도우 업데이트 클라이언트가 다운로드나 설치 과정에서 분류되지 않은 오류를 만났을 때 표시되는 포괄적인 코드입니다.
    • 0x80240FFF · Windows Update 알 수 없는 오류 — Windows Update 진행 중 구체적인 원인 없이 실패했을 때 나타나는 일반 오류 코드입니다.

    피해야 할 실수

    • 같은 방법으로 계속 재시도만 하는 것 — 코드가 바뀌지 않고 반복된다면 근본 원인이 그대로라는 뜻입니다. 재시도 대신 위 공통 점검 절차로 넘어가세요.
    • 출처가 불분명한 "업데이트 오류 자동 수정" 프로그램 사용 — 레지스트리를 임의로 변경해 다른 문제를 만들 수 있습니다. Windows 자체 문제 해결사와 DISM/SFC 같은 공식 도구를 우선 사용하세요.
    • 디스크 공간 부족을 무시하고 계속 설치 시도 — 공간이 부족한 상태에서 반복 시도하면 설치가 중간에 멈춰 구성 요소 저장소 손상으로 이어질 수 있습니다. 공간을 먼저 확보하세요.

    자주 묻는 질문

    • 업데이트를 계속 재시도하면 언젠가는 성공하나요? 일시적인 서버 혼잡이 원인이면 재시도로 해결되기도 하지만, 디스크 공간 부족이나 구성 요소 저장소 손상처럼 근본 원인이 그대로면 몇 번을 시도해도 같은 코드로 실패합니다. 같은 코드가 3회 이상 반복되면 재시도보다 원인별 점검으로 넘어가는 것이 시간을 아낍니다.
    • SoftwareDistribution 폴더를 지워도 되나요? 네, wuauserv·bits 서비스를 먼저 중지한 뒤 C:\Windows\SoftwareDistribution 폴더 내용을 비우고 서비스를 다시 시작하는 것은 Microsoft도 안내하는 표준 절차입니다. 이 폴더는 업데이트 캐시일 뿐이라 삭제해도 개인 데이터에는 영향이 없습니다.
    • 업데이트 오류로 컴퓨터를 초기화해야 하나요? 대부분은 필요하지 않습니다. DISM /RestoreHealth와 sfc /scannow로 시스템 파일을 복구하는 것만으로 해결되는 사례가 많고, 초기화는 이 절차들을 모두 시도한 뒤에도 반복 실패할 때 고려할 마지막 수단입니다.
