에러 코드 상세

0x00000077 · KERNEL_STACK_INPAGE_ERROR

커널 스택 데이터를 디스크에서 읽어오는 과정에서 실패했을 때 나타나는 코드로, 디스크 오류나 케이블 문제가 흔한 원인입니다.

이 코드를 어떻게 해석해야 하나요?

저장장치 계열 오류는 Windows가 필요한 데이터를 제때 읽지 못했거나 파일 시스템과 장치 연결에 문제가 생겼다는 단서입니다. 물리 장치 상태와 논리 파일 시스템을 분리해 봐야 합니다.

먼저 기록할 내용: 0x00000077가 발생한 시각, 직전에 실행한 작업, 최근 설치한 드라이버·업데이트, 재부팅 뒤 같은 코드가 반복되는지를 적어 두세요.

가능성 높은 원인

  • 디스크 배드섹터나 물리적 결함
  • 저장장치 케이블이나 슬롯 접촉 불량
  • 페이지 파일(가상 메모리)이 저장된 영역의 손상
  • 갑작스러운 전원 종료로 인한 디스크 손상
  • 저장장치 드라이버 문제

첫 점검 항목

  1. 디스크 상태를 chkdsk나 제조사 진단 도구로 점검하세요.
  2. 저장장치 케이블 연결 상태를 물리적으로 확인하세요.
  3. 가상 메모리(페이지 파일) 설정을 확인하고 필요시 다른 드라이브로 옮겨보세요.
  4. 중요 데이터는 미리 백업해 두는 것이 안전합니다.
  5. 저장장치 드라이버를 최신 버전으로 업데이트하세요.

확인 결과에 따른 다음 단계

  • chkdsk나 제조사 진단에서 배드섹터가 발견될 때 — 데이터 백업을 최우선으로 하고 디스크 교체를 검토하세요.
  • 진단은 정상인데 페이지 파일이 있는 드라이브에서만 반복될 때 — 페이지 파일을 다른 정상 드라이브로 옮겨 재현 여부를 확인하세요.
  • 케이블 재장착·드라이버 업데이트 후에도 반복될 때 — 다른 SATA·M.2 슬롯이나 케이블로 교차 테스트하세요.

데이터와 시스템을 보호하는 주의사항

SMART 경고, 읽기 실패, Disk 7·129·153 반복이 있으면 복구 명령보다 중요한 파일 백업을 먼저 진행하세요.

앞 단계로 해결되지 않을 때

백업 후 케이블·포트·M.2 슬롯을 교차하고 제조사 진단과 펌웨어를 확인한 뒤 파일 시스템 검사를 계획하세요.

되돌리기 어려운 조치(복구, 초기화, 드라이버 제거 등)에 들어가기 전에는 반드시 중요 데이터를 다른 저장장치로 옮겨 두는 것이 안전합니다.

관련 증상 가이드 확인하기

같은 증상과 연결된 다른 오류 코드

  • 0x0000007B · INACCESSIBLE_BOOT_DEVICE
  • 0x00000133 · DPC_WATCHDOG_VIOLATION
  • 0x00000024 · NTFS_FILE_SYSTEM
  • 0x80070570 · 파일이 손상되었거나 읽을 수 없음

공식 참고자료

Microsoft Learn: Bug Check 0x77 KERNEL_STACK_INPAGE_ERROR

자주 묻는 질문

  • SSD·NVMe를 바로 교체해야 하나요? 이 문제(0x00000077)만으로 저장장치 고장을 단정하기는 어렵습니다. 슬롯 재장착과 펌웨어 업데이트를 먼저 확인한 뒤에도 반복되면 다른 슬롯이나 드라이브로 교차 테스트해보는 것이 안전합니다.
  • 오래된 SSD라서 그런 걸까요? 사용 기간보다는 남은 수명(TBW)과 펌웨어 버전이 더 중요한 지표이므로 진단 도구로 확인하는 것이 좋습니다.
  • 메모리(RAM) 문제일 수도 있나요? 커널 스택도 결국 메모리에 올라오는 데이터이므로, Windows 메모리 진단으로 램 상태도 함께 확인하는 것이 좋습니다.
