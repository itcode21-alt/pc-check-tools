📑 목차

에러 코드 상세

0x000000C2 · BAD_POOL_CALLER

드라이버나 커널 모드 소프트웨어가 메모리 풀을 잘못된 방식으로 호출했을 때 나타나는 코드로, 특정 드라이버의 결함이 주요 원인입니다.

이 코드를 어떻게 해석해야 하나요?

드라이버 계열 오류는 커널에서 장치가 잘못된 메모리 또는 전원 상태를 사용했을 가능성을 보여줍니다. 최근 추가한 장치와 업데이트 시점을 기준으로 범위를 줄이는 것이 효율적입니다.

먼저 기록할 내용: 0x000000C2가 발생한 시각, 직전에 실행한 작업, 최근 설치한 드라이버·업데이트, 재부팅 뒤 같은 코드가 반복되는지를 적어 두세요.

가능성 높은 원인

  • 최근 설치한 드라이버의 버그
  • 보안 소프트웨어와 커널 모드 코드 간의 충돌
  • 램 불안정
  • 시스템 파일 손상
  • 타사 프로그램의 잘못된 메모리 관리

첫 점검 항목

  1. 이벤트 뷰어에서 오류 발생 직전 관련된 드라이버 파일을 확인하세요.
  2. 최근 설치한 드라이버나 프로그램을 제거해 재현 여부를 확인하세요.
  3. 메모리 진단 도구로 램 상태를 점검하세요.
  4. 먼저 차단·격리 기록과 허용 목록을 확인하세요. 꼭 필요할 때만 보호 기능을 짧게 중지해 테스트하고, 확인 직후 다시 켜세요.
  5. sfc /scannow로 시스템 파일 손상 여부를 점검하세요.

확인 결과에 따른 다음 단계

  • 최근 드라이버를 제거한 뒤 재현되지 않을 때 — 해당 드라이버의 수정된 최신 버전이 나올 때까지 사용을 자제하세요.
  • 메모리 진단에서 오류가 발견될 때 — 램 모듈을 하나씩 장착해가며 어떤 모듈이 문제인지 확인하세요.
  • sfc /scannow로도 해결되지 않을 때 — 보안 프로그램을 다른 제품으로 교체하거나 임시로 제거해 재현 여부를 확인하세요.

데이터와 시스템을 보호하는 주의사항

모든 드라이버를 한꺼번에 갱신하면 어떤 변경이 영향을 줬는지 확인하기 어려우므로 한 항목씩 변경하세요.

앞 단계로 해결되지 않을 때

안전 모드에서 멈추지 않는다면 최근 드라이버와 장치를 하나씩 되돌리고 장치 관리자와 같은 시각의 이벤트 원본을 함께 확인하세요.

되돌리기 어려운 조치(복구, 초기화, 드라이버 제거 등)에 들어가기 전에는 반드시 중요 데이터를 다른 저장장치로 옮겨 두는 것이 안전합니다.

관련 증상 가이드 확인하기

  • 0x00000050 · PAGE_FAULT_IN_NONPAGED_AREA
  • 0x000000EF · CRITICAL_PROCESS_DIED
  • 0x000000D1 · DRIVER_IRQL_NOT_LESS_OR_EQUAL

자주 묻는 질문

  • 블루스크린 코드가 한 번 떴는데 계속 지켜봐야 하나요? 이 문제(0x000000C2)가 한 번만 발생했다면 즉시 부품을 교체하기보다 재현 여부와 최근 변경 사항을 먼저 기록해두는 것으로 충분합니다. 반복된다면 그때 하드웨어 점검 범위를 넓히세요.
  • 블루스크린 이후 데이터가 손상되나요? 대부분은 강제 재시작만 발생할 뿐 저장된 파일이 곧바로 손상되지는 않지만, 저장하지 않은 작업 내용은 사라질 수 있습니다.
  • 미니덤프 파일로 원인을 알 수 있나요? WinDbg 같은 도구로 미니덤프를 분석하면 어떤 드라이버가 문제를 일으켰는지 특정할 수 있으므로, 반복된다면 미니덤프 분석을 시도해보세요.
