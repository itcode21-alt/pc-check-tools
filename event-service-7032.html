EVENT ID 7032

Service Control Manager 7032 서비스 복구 동작 실패 점검

서비스가 예기치 않게 종료된 뒤 Windows가 예약된 복구 동작(예: 서비스 다시 시작)을 시도했지만 그 동작마저 실패했다는 기록입니다.

7032는 서비스가 종료된 뒤 Windows가 시도한 복구 동작이 실패했다는 기록입니다. 서비스가 한 번 종료된 사건(7031·7034)과, 그 뒤 복구까지 실패한 사건을 나눠서 읽어야 합니다.

Microsoft 문서는 서비스의 복구 동작을 서비스 속성의 복구 탭에서 확인·변경하도록 안내합니다. 이벤트 본문에 실패 이유가 함께 적히므로, 이유 문장이 '이미 실행 중'인지 '시작할 수 없음'인지에 따라 점검 방향이 달라집니다.

발생 조건

  • 서비스가 종료된 뒤 자동으로 다시 시작되지 않음
  • 7031·7034 기록 직후에 이어서 남음
  • 서비스 복구 설정이 '서비스 다시 시작'으로 되어 있음

가능성 높은 원인

  • 다시 시작하는 시점에 같은 서비스가 이미 실행 중이거나 종속 항목이 준비되지 않은 경우
  • 서비스 파일·권한·계정 문제
  • 프로그램 충돌로 서비스가 계속 즉시 종료되는 경우

점검 순서

  1. 이벤트의 서비스 이름, 시도한 복구 동작, 실패 오류 문장 기록 — 되돌리기 쉬운 항목부터 확인해 위험 없이 범위를 줄입니다.
  2. 서비스 속성의 복구 탭에서 첫 번째·두 번째 실패 때 동작 확인 — 첫 확인 결과와 비교해 원인 후보를 좁힙니다.
  3. 같은 시각의 7031·7034, Application Error 1000 비교 — 이 단계에서도 재현되면 다음 항목으로 넘어가세요.
  4. 서비스를 수동으로 시작해 보고 시작되는지 확인 — 변경 전후로 증상이 달라지는지 비교해보세요.
  5. 관련 프로그램 업데이트·복구 — 여기까지 확인해도 해결되지 않으면 다음 원인을 검토하세요.
주의사항

복구 동작을 '컴퓨터 다시 시작'으로 바꾸는 것은 원인을 가릴 수 있으니 꼭 필요한 서비스가 아니면 권하지 않습니다.

원인을 모른 채 서비스 계정·권한을 바꾸지 마세요.

자주 묻는 질문

  • 7031 다음에 7032가 뜨면 어떻게 읽나요? 서비스가 종료됐고(7031), 예약된 복구 동작(서비스 다시 시작 등)까지 실패했다는 뜻입니다. 서비스가 계속 꺼진 상태인지 확인하고 수동 시작이 되는지 보세요.
  • 복구 설정을 바꾸면 해결되나요? 복구 동작은 실패 뒤의 대응일 뿐 종료 원인을 고치지 않습니다. 반복 종료의 원인(충돌, 설정, 종속 서비스)을 먼저 찾으세요.
