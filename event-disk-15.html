EVENT ID 15

Disk 이벤트 15 장치 접근 준비 안 됨 점검

저장장치가 아직 접근할 수 있는 상태가 아니라는 기록입니다. 가상 머신 스냅샷 직후처럼 무해한 경우도 있고, 물리 디스크에서 반복되면 연결·컨트롤러·장치 응답 지연을 확인해야 합니다.

15는 지정된 디스크 장치가 아직 접근할 준비가 되지 않았다는 기록입니다. 발생 시점이 연결·절전 복귀·가상 머신 스냅샷과 겹치는지가 가장 먼저 보는 기준입니다.

VMware(Broadcom) 지식 문서는 가상 머신의 quiesce 스냅샷 직후 이 이벤트가 남을 수 있고 무시해도 된다고 안내합니다. 물리 PC에서 증상 없이 한두 번이면 관찰 대상이고, 멈춤이나 파일 오류가 함께 반복되면 저장장치 점검으로 넘어가세요.

발생 조건

  • 외장 드라이브·USB 저장장치를 연결하거나 절전에서 복귀한 직후
  • 가상 머신 스냅샷(quiesce) 직후
  • 부팅 중 저장장치 인식이 늦음

가능성 높은 원인

  • 장치가 초기화되는 동안 접근 요청이 먼저 도착한 경우
  • 컨트롤러·드라이버·펌웨어 문제
  • 케이블·포트·전원 공급 불안정
  • 가상 머신 스냅샷이 임시 디스크를 제거한 경우

점검 순서

  1. 어느 디스크 번호인지, 외장인지 내장인지 확인 — 되돌리기 쉬운 항목부터 확인해 위험 없이 범위를 줄입니다.
  2. 발생 시각이 연결·절전 복귀·스냅샷 시점과 겹치는지 확인 — 첫 확인 결과와 비교해 원인 후보를 좁힙니다.
  3. 같은 시각의 Disk 7·11·51·153 기록이 있는지 비교 — 이 단계에서도 재현되면 다음 항목으로 넘어가세요.
  4. 케이블·포트를 바꾸고 USB 선택적 절전 설정을 비교 — 변경 전후로 증상이 달라지는지 비교해보세요.
  5. 내장 장치에서 반복되면 SMART와 컨트롤러 드라이버 확인 — 여기까지 확인해도 해결되지 않으면 다음 원인을 검토하세요.
주의사항

디스크 접근 오류와 함께 반복되면 점검보다 백업이 먼저입니다.

원인을 모른 채 장치 제한 시간 값을 바꾸지 마세요.

자주 묻는 질문

  • 외장 하드를 꽂을 때마다 15가 남는데 괜찮나요? 장치가 준비되기 전에 접근 요청이 도착해 남는 경우가 흔합니다. 실제 파일 접근 오류가 없다면 관찰하고, 오류가 있으면 케이블·포트·USB 절전 설정을 확인하세요.
  • 가상 머신에서만 뜨는데요? 스냅샷 직후라면 무해한 경우가 있다고 VMware가 안내합니다. 스냅샷과 무관하게 반복되거나 게스트 안의 디스크 오류가 함께 있으면 저장소 연결을 점검하세요.
