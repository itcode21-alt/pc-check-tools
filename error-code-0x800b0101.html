에러 코드 상세

0x800B0101 · 인증서 유효 기간 오류

Microsoft 문서에서 CERT_E_EXPIRED, 즉 필요한 인증서가 현재 시스템 시계나 서명 파일의 타임스탬프 기준 유효 기간을 벗어났다는 코드입니다.

이 코드를 어떻게 해석해야 하나요?

Microsoft의 업데이트 손상 해결 문서는 0x800B0101을 CERT_E_EXPIRED로 정의하며, 인증서 유효 기간을 현재 시스템 시계나 서명 파일의 타임스탬프와 비교해 벗어났을 때 나타난다고 설명합니다. 그래서 PC의 날짜·시간·시간대가 틀렸는지 먼저 확인하는 것이 맞습니다. Microsoft의 일반 사용자용 문서도 자동 시간·시간대 설정을 켜 두라고 안내합니다. 시간이 정확한데도 반복되면 프록시나 보안 프로그램의 인증서 검사 등은 문서 외 일반 점검입니다.

가능성 높은 원인

  • PC의 날짜·시간 또는 시간대가 실제 시간과 크게 다른 경우
  • 업데이트 패키지 서명 인증서가 만료되었거나 신뢰 체인이 완성되지 않은 경우
  • 오래된 Windows에서 루트 인증서 업데이트가 누락된 경우
  • WSUS·프록시·보안 프로그램이 HTTPS 연결을 중간에서 검사하면서 인증서 신뢰가 깨진 경우

첫 점검 항목

  1. 공식 문서가 알려 주는 것: 인증서 유효 기간은 현재 시스템 시계와 서명 파일의 타임스탬프를 기준으로 판단됩니다. 설정 > 시간 및 언어 > 날짜 및 시간에서 시간 자동 설정과 시간대 자동 설정을 켜고 지금 동기화를 실행하세요.
  2. 시간을 맞춘 뒤 Windows Update를 다시 실행하세요. 성공하면 시스템 시계 오류가 원인이었습니다.
  3. 문서 외 일반 점검: 다른 HTTPS 사이트가 정상으로 열리는지 확인해 시간 문제와 네트워크·인증서 문제를 구분하세요.
  4. 문서 외 일반 점검: 회사·학교 PC라면 WSUS나 보안 프록시의 인증서 정책을 관리자에게 확인하세요. 인증서를 임의로 설치하거나 삭제하지 마세요.
  5. 문서 외 일반 점검: 시간이 맞는데도 반복되면 DISM.exe /Online /Cleanup-image /Restorehealth와 sfc /scannow로 구성 요소 손상을 복구한 뒤 다시 시도하세요. 보안 설정이나 TLS를 낮춰 성공시키는 방법은 쓰지 마세요.

데이터와 시스템을 보호하는 주의사항

원인이 확인되지 않은 상태에서 초기화, 레지스트리 수정, 시스템 파일 수동 교체를 먼저 진행하지 마세요.

앞 단계로 해결되지 않을 때

같은 코드가 반복되면 이벤트 로그와 장치 상태를 보존하고, 코드가 계속 달라지면 메모리·전원·온도처럼 시스템 전체 안정성을 확인하세요.

복구, 초기화, 드라이버 제거처럼 되돌리기 어려운 작업 전에는 중요한 파일을 다른 물리 저장장치나 신뢰할 수 있는 백업 위치에 보관하세요.

상세 해설

관련 증상 가이드 확인하기

자주 묻는 질문

  • 0x800B0101은 윈도우가 정품이 아니라는 뜻인가요? 아닙니다. Microsoft 정의는 필요한 인증서가 유효 기간을 벗어났다는 것으로, 정품 여부와 관계가 없습니다. 가장 흔한 확인 사항은 PC의 날짜·시간입니다.
  • 시간이 맞는데도 계속 나와요. 서명 파일의 타임스탬프 기준으로도 유효 기간이 판단되므로 시스템 시계만이 원인은 아닙니다. 구성 요소 손상 복구(DISM·SFC)와 회사·학교 환경의 인증서 정책 확인을 순서대로 해 보고, 보안 설정을 낮춰 우회하지는 마세요.
