에러 코드 상세

네트워크 드라이브 탐색기 멈춤 · 네트워크 드라이브나 공유 폴더 탐색 시 탐색기가 멈춤

탐색기가 네트워크 드라이브나 공유 폴더의 파일 목록, 썸네일을 가져오려다 응답이 없는 서버나 끊긴 연결 때문에 전체 창이 멈추는 증상입니다. 로컬 폴더는 정상인지 먼저 구분하는 것이 중요합니다.

이 코드를 어떻게 해석해야 하나요?

부품 고장을 코드 하나로 단정 짓기보다는, 발생 시점과 최근 변경 사항, 반복 조건, 안전 모드 재현 여부를 함께 기록해 원인 범위를 좁혀가는 것이 정확합니다.

먼저 기록할 내용: 네트워크 드라이브 탐색기 멈춤가 발생한 시각, 직전에 실행한 작업, 최근 설치한 드라이버·업데이트, 재부팅 뒤 같은 코드가 반복되는지를 적어 두세요.

가능성 높은 원인

  • 연결이 끊긴 네트워크 드라이브가 여전히 매핑되어 있는 경우
  • 공유 폴더 서버가 응답하지 않는 경우
  • 썸네일 미리보기 생성이 대용량 폴더에서 지연되는 경우

첫 점검 항목

  1. 매핑된 드라이브 목록과 상태 확인 — 명령 프롬프트에서 net use를 실행해 어떤 드라이브가 "사용할 수 없음" 상태인지 먼저 확인하세요. 탐색기 GUI보다 응답이 빠릅니다.
  2. 연결 끊긴 드라이브 연결 해제 — 응답 없는 드라이브는 net use X: /delete(X는 드라이브 문자)로 해제하거나 탐색기에서 연결을 끊어보세요.
  3. 로컬 폴더와 비교 — 내 PC나 바탕화면 같은 로컬 폴더에서도 탐색기가 느린지 비교해, 네트워크만의 문제인지 탐색기 전체 문제인지 구분하세요.
  4. 네트워크 자동 검색 끄기 — 탐색기 메뉴 > 보기 > 옵션 > 폴더 옵션 > 보기 탭에서 "자동으로 네트워크 폴더 및 프린터 검색"의 체크를 해제하면, 탐색기 열 때마다 네트워크를 스캔하며 멈추는 지연을 줄일 수 있습니다.
  5. 공유 폴더 기기 상태 점검 — NAS나 공유 PC가 절전 모드에 들어갔거나 응답이 없는지, 같은 네트워크에 정상 연결되어 있는지 다른 기기에서도 확인하세요.

확인 결과에 따른 다음 단계

  • 특정 드라이브 연결 해제로 바로 풀릴 때 — 해당 드라이브를 다시 매핑할 때 "로그온할 때 다시 연결"을 해제하거나, 연결 대상 기기의 전원·절전 설정을 먼저 확인하세요.
  • 로컬 폴더에서도 느릴 때 — 네트워크가 아니라 탐색기 자체나 셸 확장 문제일 수 있으므로 셸 확장 충돌 페이지를 함께 확인하세요.
  • 자동 검색을 꺼도 특정 공유 폴더에서만 멈출 때 — 그 공유 폴더를 호스팅하는 기기(NAS·공유 PC)의 응답 지연이나 절전 설정이 원인일 가능성이 큽니다.

데이터와 시스템을 보호하는 주의사항

원인이 분명하지 않은데 초기화·레지스트리 수정·시스템 파일 교체 같은 조치를 먼저 시도하면 오히려 문제가 커질 수 있습니다.

앞 단계로 해결되지 않을 때

코드가 매번 동일하게 반복된다면 이벤트 로그와 장치 상태를 기록해두고, 코드가 바뀐다면 메모리·전원·온도처럼 시스템 전체의 안정성을 먼저 살펴보세요.

복구, 초기화, 드라이버 제거처럼 되돌리기 어려운 작업 전에는 중요한 파일을 다른 물리 저장장치나 신뢰할 수 있는 백업 위치에 보관하세요.

관련 증상 가이드 확인하기

공식 참고자료

Microsoft Learn: Applications freeze accessing network drive files

자주 묻는 질문

  • 탐색기가 멈추면 바로 재설치해야 하나요? 이 문제(네트워크 드라이브 탐색기 멈춤)는 재설치보다 셸 재시작과 원인이 되는 폴더·드라이브 분리로 대부분 해결됩니다. 재설치는 이 단계 이후에도 반복될 때 고려하세요.
