📑 목차

    EVENT ID 10 · WinMgmt

    대부분 잔여 WMI 등록 정보이며 시스템 고장 신호가 아닙니다 확인 필요

    WinMgmt(WMI) 이벤트 10은 영구 이벤트 구독이 바인딩된 필터를 통해 이벤트를 전달하지 못했다는 기록입니다.

    "Event filter with query ... could not be reactivated" 형태의 설명과 함께 0x80041003 같은 오류 코드가 표시됩니다. 대개 예전에 설치했다가 제거한 프로그램이나 OEM 유틸리티가 남긴 WMI 필터·구독이 원인이며, 이 이벤트 하나만으로 하드웨어나 운영체제 손상을 의미하지는 않습니다.

    먼저 구분할 상황

    • 다른 증상 없이 이벤트만 쌓인다면 급하게 조치할 필요가 낮은 잔여 등록 정보일 가능성이 큽니다.
    • 특정 모니터링·보안 프로그램 설치 직후 시작됐다면 해당 프로그램의 WMI 등록 실패 가능성을 먼저 봅니다.
    • 부팅 지연·서비스 오류가 함께 있다면 WMI 리포지토리 자체 손상 여부를 확인해야 합니다.

    안전한 점검 순서

    1. 이벤트 세부 정보에서 문제가 된 필터(Filter) 이름과 네임스페이스, 오류 코드를 기록합니다.
    2. 관리자 권한 PowerShell에서 Get-WmiObject -Namespace root/subscription -Class __EventFilter로 등록된 필터 목록을 조회해 이름이 일치하는 항목을 찾습니다.
    3. 같은 이름의 프로그램이 현재 설치돼 있는지, 최근 제거한 프로그램과 시점이 겹치는지 비교합니다.
    4. 제거된 프로그램이 남긴 필터라면 Get-WmiObject로 확인 후 관련 __EventFilter·__FilterToConsumerBinding·__EventConsumer 인스턴스를 신중히 삭제합니다.
    5. 다른 기능 이상이 없다면 굳이 리포지토리를 초기화하지 않고 지켜봐도 됩니다.

    하면 안 되는 실수

    이벤트 개수를 줄이겠다고 곧바로 net stop winmgmt 후 리포지토리 폴더 이름을 바꾸는 초기화를 실행하지 마세요. 다른 정상 프로그램이 사용 중인 WMI 등록 정보까지 함께 사라져 재등록이 필요해질 수 있습니다. 먼저 어떤 필터가 문제인지 특정한 뒤 그 항목만 정리하는 것이 안전합니다.

    즉시 점검이 필요한 경우

    WMI 이벤트 10과 함께 서비스 시작 실패, 원격 관리 도구 오류, 백신·모니터링 프로그램의 기능 이상이 동반된다면 해당 프로그램을 재설치하거나 제조사 지원에 문의하세요.

    자주 묻는 질문

    • WMI 이벤트 10이 반복되면 PC가 고장난 건가요? 아닙니다. 대부분 오래되거나 잘못 설치된 소프트웨어가 남긴 WMI 이벤트 구독·필터가 원인이며, 시스템 기능에 실질적인 문제를 일으키지 않는 경우가 많습니다. 다른 증상 없이 이벤트만 쌓인다면 급하게 조치할 필요는 없습니다.
    • 어떤 소프트웨어가 원인인지 어떻게 확인하나요? 이벤트 설명에 표시되는 필터(Filter) 이름과 네임스페이스를 기록한 뒤, PowerShell의 Get-WmiObject -Namespace root/subscription -Class __EventFilter 명령으로 등록된 필터 목록을 조회하면 어떤 프로그램이 등록했는지 추정할 단서를 얻을 수 있습니다.
    • WMI 리포지토리를 초기화하면 바로 해결되나요? 리포지토리 초기화는 관련 모니터링·보안 프로그램이 사용하는 WMI 등록 정보까지 함께 재설정됩니다. 다른 프로그램이 WMI에 의존하고 있다면 재초기화 뒤 재등록이 필요할 수 있으므로, 이벤트 개수를 줄이는 목적만으로 성급하게 실행하지 마세요.
