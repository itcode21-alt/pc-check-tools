    EVENT ID 137

    Ntfs Event 137: Default Transaction Resource Manager Failed to Start

    137 records that NTFS could not start the default transaction resource manager of a volume. The message alone does not reveal the cause, so look at the error code in the event data together with the kind of volume.

    Documents from backup and virtualisation vendors list cases where 50, 57, 137 and 140 are left together right after a snapshot or a backup. If file-system corruption records (55, 57, 140) are present at the same time, suspect the storage side first; if it coincides with the snapshot or backup time, suspect that first.

    When it appears

    • Repeats on the same volume at boot and shutdown
    • Right after a virtual-machine snapshot or a backup
    • Occurs on special volumes such as a RAM disk or an external volume

    Likely causes

    • File-system corruption of the volume or a storage-device error
    • A read-only or non-writable state, or a special volume such as a RAM disk
    • A backup or snapshot job temporarily blocked access to the volume

    What to check, in order

    1. Record the volume name and the error code in the data from the event body.
    2. Compare with Ntfs 55, 57 and 140 and Disk 7, 11 and 153 records from the same time.
    3. Check whether the volume is a RAM disk, an external or a virtual disk.
    4. Check the result of chkdsk run without options (a read-only check).
    5. Compare the backup and snapshot schedule with the time it occurred.
    Caution

    If a storage-device error is suspected, back up before running chkdsk /f.

    If the volume is one with an obvious cause such as a RAM disk and there is no functional problem, it may be just something to observe.

    Frequently asked questions

    • 137 appears at every boot. Is it dangerous? If it is left on the same volume every time and there are no file errors, a special volume such as a RAM disk may be the reason. If file-access errors or other storage-device records appear with it, move on to checking the storage device.
    • Can I run chkdsk right away? If a storage-device error is suspected, back up first. A check run without options is read-only and relatively safe, but the repair option (/f) can be a burden on a device in poor condition.
