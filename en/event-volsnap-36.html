    EVENT ID 36

    volsnap Event 36: Shadow Copy Storage Limit Reached

    volsnap 36 records that a volume shadow copy was aborted because of the configured shadow copy storage limit. System Restore, Windows Backup or backup software may not be able to create new copies.

    Even when the disk has plenty of free space, the dedicated limit used by restore points and backups can be too small, so check the two values separately.

    If you need System Restore points or backups on this PC, confirm that a substitute backup works before deleting existing copies. If storage errors appear at the same time, check the disk path and VSS state together instead of only adding space.

    When it appears

    • Creating a restore point fails
    • Windows Backup or backup software errors
    • volsnap 36 repeats on a specific volume

    Likely causes

    • The user-set maximum size of the shadow copy storage was exceeded
    • Many restore points or backup jobs piled up in a short time
    • I/O delay or Disk/Ntfs errors on the source volume
    • VSS writer, backup provider or storage state problems

    What to check, in order

    1. Note the source volume and the number of the stopped shadow copy shown in the event.
    2. Check the dedicated storage and existing copies with vssadmin list shadowstorage and vssadmin list shadows.
    3. In System Protection, check the maximum usage for that volume and whether you really need restore points.
    4. Compare VSS, Disk, Ntfs and storahci events from the same time.
    5. If you need backups, confirm a substitute backup is healthy before deleting existing recovery points.
    Caution

    The shadow-copy-specific limit can be too small even when the disk has plenty of free space.

    Running vssadmin delete shadows /all carelessly can delete existing restore points and backup copies, so check the target and your recovery plan first.

    Frequently asked questions

    • Why does 36 happen when drive C has plenty of free space? The maximum usage of shadow copies can be set separately from ordinary free space. Check the allocated limit and usage of the source volume with vssadmin list shadowstorage.
    • Is it OK to run vssadmin delete shadows /all? It can wipe all existing System Restore points and backup copies, so do not run it casually. Confirm your recovery plan and a substitute backup, then handle only the targets you need.
