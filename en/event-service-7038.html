    EVENT ID 7038

    Service Control Manager Event 7038: Service Logon Failed

    7038 records that a service could not start because it failed to log on as the specified account. On an ordinary PC it mainly appears when the password or state of the account has changed for a program that assigns a separate account to its service.

    Microsoft Learn's guide to SQL Server service error 1069 also lists a changed password or a disabled account as common causes of 7038. The error sentence in the event body (for example a disabled account or a wrong password) decides the direction of the check.

    When it appears

    • A service does not start right after a password or account-policy change
    • It occurs in programs that assign a separate user account to a service (backup, database, security software and so on)
    • Service start failure records such as 7000 appear with it

    Likely causes

    • The password stored in the service differs from the current account password
    • The account is disabled, locked or expired
    • The account name was changed or deleted

    What to check, in order

    1. Write down the service name, the logon account and the error sentence in the event. Start with what is easy to undo so you can narrow the range without risk.
    2. Check the Log On tab of the service properties. Compare with the first check to narrow the cause candidates.
    3. Check whether the account is usable (not disabled, locked or expired). If it still reproduces at this step, move on to the next item.
    4. Re-enter the current password, save it and start the service. See whether the symptoms differ before and after the change.
    5. If it is a “Log on as a service” right problem, check whether a 7041 record is also logged at the same time. If it is still unsolved after all this, review the next cause.
    Caution

    Do not try to fix it by granting the service account administrator rights; give only the minimum rights needed.

    Do not leave the password in an event-log capture or in an inquiry post.

    Frequently asked questions

    • 7038 appears even though I did not change the password. The same record is logged when the account has been disabled, locked or expired, or renamed. Check the error sentence in the event body first.
    • How are 7038 and 7041 different? Both record a service logon failure. 7041 is sometimes logged together for a logon-type problem such as the “Log on as a service” right, so if you see both for the same service, check the account's rights as well.
