    EVENT ID 1002

    Application Hang Event 1002: Program Not Responding

    1002 is logged when a program stops responding for a period of time and Windows marks it as hung. Unlike Application Error 1000 the process was not ended by an exception.

    Check which task the hang started in and whether the app recovered. If only one app repeats, look at its settings, plug-ins and overlays first; if several apps hang in the same time window, compare graphics driver, storage and memory usage.

    When it appears

    • “Not responding” shown in the window title
    • A game, File Explorer or document app freezes
    • It recovers after a while or is force-closed

    Likely causes

    • The app waiting on an internal task or plug-in
    • Slow response from graphics, storage or network
    • Overlay or security-software conflicts

    What to check, in order

    1. Record the name of the hung app and the hang type.
    2. Compare whether it reproduces only in the same app.
    3. Turn off overlays and plug-ins, and retest from a clean boot.
    4. Check Disk, Display and Application Error events from the same time.
    Caution

    Do not conclude RAM or storage failure from 1002 alone. The app that hung and the conditions are better clues.

    Frequently asked questions

    • Does 1002 mean the RAM is faulty? No. App-internal waiting, storage delay, graphics driver problems and plug-in conflicts can all cause it. First check whether it repeats randomly across several apps.
    • How do I tell 1000 and 1002 apart? 1000 is an app ended by an unhandled exception; 1002 is a continuing not-responding state. For 1000 check the exception code and module; for 1002 check when the hang began, the task and how often it repeats.
