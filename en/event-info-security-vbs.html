    Virtualization-Based Security (VBS), Credential Guard and TPM Records Explained

    A PC with Memory integrity (VBS/HVCI), Windows Hello, a TPM or Credential Guard turned on writes an information record at every boot to say that these security features started. Seeing many of them is evidence that things are working normally.

    Seeing Hyper-V-Hypervisor 1 at every boot means the hypervisor started normally, and it appears if you use Memory integrity (VBS) or WSL2/virtual machine features. It can appear because of VBS even if you never use a virtual machine.

    Entries whose value is written as 0 (for example LsaSrv 6156 and Wininit 14) mean the conditions for that feature are not met or it is not used; they are not errors. The values worth checking in this group are listed under “When to worry” below.

    The records explained on this page

    Source and IDMeaningWhat to check
    Hyper-V-Hypervisor 1Records that the hypervisor (the Hyper-V layer) started normally. It is left at every boot if you use Memory integrity (VBS) or WSL2/virtual machine features.If you want to turn virtualization features off, check Windows Features and the Memory integrity setting.
    Hyper-V-Hypervisor 2Records the hypervisor scheduler type (SchedulerType).Use as a reference when investigating virtual machine performance problems.
    Hyper-V-Hypervisor 129Records the result of the hypervisor initializing I/O remapping (IOMMU): whether the hardware is present and used, and the Problems value. A Problems value of 0x0 means no problem.If Problems is not 0, check the IOMMU and virtualization settings in the BIOS.
    Hyper-V-Hypervisor 156Records that the hypervisor applied the mitigation settings for a CPU vulnerability affecting virtual machines (CVE-2018-3646).If you worry about performance loss, check it together with whether virtualization-based security features are used.
    Hyper-V-Hypervisor 165Records that the hypervisor applied the mitigation settings for CPU vulnerabilities affecting virtual machines (the MDS family of CVEs).If you worry about performance loss, check it together with whether virtualization-based security features are used.
    IsolatedUserMode 1Records that a Secure Trustlet (for example NgcIso.exe, related to Windows Hello) started in the isolated security area. A status of STATUS_SUCCESS means success.Check the trustlet and the status only if it is not STATUS_SUCCESS.
    IsolatedUserMode 2Records that a Secure Trustlet ended.Even many repeats are normal; it is left at every sign-in and shutdown.
    IsolatedUserMode 3Records that the Secure Kernel (virtualization-based security) started. If flags contains HvciEnabled, Memory integrity (HVCI) is on.Use the change in these flags as a reference when you turn off Memory integrity because of an incompatible driver.
    IsolatedUserMode 5Records that a Secure Trustlet started (including the default entry whose image name is NULL).Check only if it is not STATUS_SUCCESS.
    Kernel-Boot 153Records that virtualization-based security (VBS) is enabled and the reason (such as a registry configuration).It has nothing to do with Disk 153 or nvlddmkm 153 — check that the source is Kernel-Boot.
    Wininit 12Records that LSASS.exe started as a protected process.Use as a reference when a security program conflict is suspected.
    Wininit 14Records the Credential Guard configuration values (registry setting, test configuration, automatic enablement). A value of 0 means the feature is not used.If you intend to use Credential Guard, check the values.
    Wininit 18Records that VBS key isolation started and began protecting keys isolated in VSM.It does not appear in an environment where virtualization-based security is off.
    Wininit 19Records the result (HRESULT) of creating the virtualization-based security timer. Success means no problem.Check only if the HRESULT is not a success.
    LsaSrv 6156Records the result of deciding at boot whether to enable Credential Guard automatically (the hardware requirements for virtualization-based security, domain membership and licensing). A value of 0 is not an error.If you intend to use Credential Guard, check each value.
    HAL 16Records that IOMMU error reporting was initialized.Use as a reference when investigating device DMA errors.
    TPM-WMI 1025Records that the TPM (Trusted Platform Module) was provisioned successfully and is ready to use.Check the state in tpm.msc only if there are TPM-related errors.
    TPM-WMI 1046Records that the Measured Boot log files were cleaned up (deleted).Check that the deleted file path is the MeasuredBoot folder.
    TPM-WMI 1282Records that the TBS (TPM Base Services) device identifier was generated.Check the state only if there are TPM-related errors.
    TPM 18A record that causes TPM provisioning and state checks to run.Check the state in tpm.msc only if there are TPM-related errors.
    Directory-Services-SAM 16962Records that remote calls to the SAM (the account database) are being restricted to the default security descriptor.Use as a reference when reviewing security policy.
    Directory-Services-SAM 16977Records the minimum password length setting values (MinimumPasswordLength and so on).Use as a reference when reviewing password policy.
    Directory-Services-SAM 16983Records that periodic summary events began to be written for legacy-style password change calls from remote clients.Use as a reference when reviewing security policy.

    When to worry

    • If the Problems value in Hyper-V-Hypervisor 129 is not 0x0, check the IOMMU and virtualization settings in the BIOS.
    • Check the trustlet (for example NgcIso.exe, related to Windows Hello) only when the status in IsolatedUserMode 1 and 5 is not STATUS_SUCCESS.
    • If flags in IsolatedUserMode 3 contain HvciEnabled, Memory integrity is on. If you turned Memory integrity off because of an incompatible driver, these flags change.
    • Check Wininit 19, 23 and 25 only when the HRESULT is not a success (0), and Wininit 24 only when Win32Error is not 0.
    • Check the state in tpm.msc only when there are separate TPM errors (Warning or Error level). Do not reset the TPM before you have secured your BitLocker recovery key.
    • The Directory-Services-SAM records are Windows' default security hardening and auditing behavior. You do not need to look at them unless you are reviewing password policy.
    Caution

    Do not conclude a failed part or a security incident from one information-level record. Use it as a clue only when Error/Warning records from the same time and a real symptom (drops, reboots, slowness) accompany it.

    Frequently asked questions

    • I do not use Hyper-V, but Hyper-V-Hypervisor records appear. If a feature that uses the hypervisor, such as Memory integrity (VBS), WSL2 or Sandbox, is on, the record is left at every boot even if you never use a virtual machine directly. If you want to turn it off, check Windows Features and the Memory integrity setting.
    • LsaSrv 6156 or Wininit 14 shows 0. Is that OK? Yes. A value of 0 means the conditions for automatically enabling Credential Guard (the hardware requirements for virtualization-based security, domain membership, licensing) are not met or it is not used. Check the values only if you intend to use Credential Guard.
    • Kernel-Boot 153 appears. Is it a disk error? No. A 153 whose source is Kernel-Boot is a boot security record saying that virtualization-based security is enabled. It has nothing to do with Disk 153 (I/O retries) or nvlddmkm 153 (graphics).
