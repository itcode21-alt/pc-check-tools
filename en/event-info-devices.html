    10 INFORMATION-LEVEL EVENTS

    DriverFrameworks, volsnap 33, FilterManager, TPM-WMI and Sandboxie Records Explained

    Device drivers, file-system filters and backup (VSS) components also leave information records when they connect or load. You use them only as clues to which drivers sit in the path when there is a real device error or disk delay.

    FilterManager 6 records that a file-system filter driver loaded and registered. Programs such as antivirus, cloud sync (CldFlt) and sandboxes (SbieDrv) leave as many of them at boot as there are drivers. DeviceName tells you which drivers sit in the disk I/O path.

    DriverFrameworks-UserMode 10000, 10002 and 10100 are written when the user-mode driver of a device such as USB, audio or HID starts or updates its state. If the device does not actually drop, they are normal connection records.

    The records explained on this page

    Source and IDMeaningWhat to check
    DriverFrameworks-UserMode 10000A state record of the UMDF driver host connecting to a device. If there is no real device error it can be read as a normal boot/connect log.Check the device InstanceId and DriverName in the XML.
    DriverFrameworks-UserMode 10002An informational record of the user-mode device driver's framework communication/initialization state. Use it as a candidate cause only when a specific device reconnects or stops working.Note the device name, state and error code in the General tab and XML, and compare with 10110/10111 and Device Manager from the same time.
    DriverFrameworks-UserMode 10100An informational record written when the user-mode driver framework starts a device driver or updates its state. When a device malfunction accompanies it, check the device name and the state code in the XML.Check DeviceName, InstanceId, Status and DriverName in the XML.
    volsnap 33An informational event recording the state of volume shadow copies and VSS storage areas. If backups and restore points do not fail, its appearance alone does not mean a storage fault.Check the volume shown in the event and the result of the VSS operation.
    FilterManager 1Records that a file-system filter driver was unloaded normally (the driver name is shown in DeviceName).Check in DeviceName which filter driver it is (antivirus, cloud sync, sandbox and so on).
    FilterManager 6Records that a file-system filter driver loaded and registered with the Filter Manager. DeviceName tells you which drivers sit in the disk I/O path.Check whether DeviceName contains an unfamiliar driver.
    SbieDrv 1101A record of the Sandboxie driver (SbieDrv). On the PC that produced it, only data remained, without the message text.If you do not use Sandboxie, check whether to remove it, and look together with the SbieDrv load record in FilterManager 6.
    TPM-WMI 1038Records that the TPM WMI management component queried or updated the security chip state.Check the actual state with tpm.msc and Get-Tpm.
    TPM-WMI 1041An informational event recording the result of a TPM WMI security chip management operation. The error state, command and target feature must be checked in the XML, and it alone is not urgent.Check Result, Status and Operation in the XML.
    Win32k 267Records that touch and touchpad hardware quality assurance (HQA) validation succeeded.Check it together with other errors only if there are input device problems.

    When to worry

    • Only when a device really drops or stops working, check DeviceName, InstanceId and Status in the XML, and compare with DriverFrameworks 10110/10111 from the same time and yellow errors in Device Manager.
    • volsnap 33 is an information event. If backups and restore points are not failing, do not delete restore points at random. Compare whether volsnap 36, Disk or Ntfs errors appear at the same time.
    • When there is disk delay or a blue screen, see whether DeviceName in FilterManager 6 contains an unfamiliar third-party filter driver; temporarily removing it to compare can be one of the candidates.
    • If you do not use Sandboxie (SbieDrv), check whether to remove it. Remove it to compare only when there are game or disk-delay symptoms.
    • For TPM-WMI 1038 and 1041, check tpm.msc and Result/Status in the XML only when BitLocker, Windows Hello or Secure Boot problems accompany them. Do not reset the TPM before you have secured the recovery key.
    Caution

    Do not conclude a failed part or a security incident from one information-level record. Use it as a clue only when Error/Warning records from the same time and a real symptom (drops, reboots, slowness) accompany it.

    Frequently asked questions

    • There are many FilterManager records. Is that why my disk is slow? The load records themselves are not a problem. But if there is disk delay or a blue screen, a third-party filter driver (antivirus, cloud sync, sandbox) can be a suspect, so check it in DeviceName and compare by temporarily removing it.
    • volsnap 33 appears. Is my storage faulty? No. It is an information event about the state of volume shadow copies and the VSS storage area. Suspect storage only when volsnap 36, Disk or Ntfs errors appear at the same time.
    • DriverFrameworks 10100 repeats. It may be normal initialization right after boot, resume from sleep or a device connection. Check the device name and the state code only when it repeats at the same time as a real device drop.
