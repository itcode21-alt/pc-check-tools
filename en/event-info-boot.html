    16 INFORMATION-LEVEL EVENTS

    Records Written at Every Boot — Kernel-Boot, Kernel-General, EventLog 6009

    Open the System log in Event Viewer and you will find a run of Information-level records right after boot. Most are normal records reporting the boot configuration and timing, and their presence alone does not mean anything is wrong with the PC.

    This group covers boot options, the boot times reported by the firmware, system time initialization and registry maintenance. They only mean something once you read the values, so you can normally ignore them.

    There are two cases where they become useful: when boot is slow and you want to see whether the firmware phase is long (Kernel-Boot 30), and when the boot time looks off (Kernel-Boot 238, Kernel-General 25).

    The records explained on this page

    Source and IDMeaningWhat to check
    Kernel-Boot 18Records the number of boot entries (boot options) configured on this system.If a multi-boot setup is not what you intended, check the number of boot entries.
    Kernel-Boot 25Records the boot menu policy value.Use as a reference when investigating boot menu behavior.
    Kernel-Boot 27Records the boot type (BootType) and load options (NOEXECUTE, FVEBOOT and so on).Use as a reference when investigating boot options.
    Kernel-Boot 30Records boot time metrics reported by the firmware (when OS image loading started, when boot services ended and so on).If boot is slow, compare the values to see whether the firmware phase is long.
    Kernel-Boot 32Records the time the boot manager waited for user input (BitlockerUserInputTime). 0 means it did not wait for input.If a BitLocker PIN prompt makes boot slow, check this value.
    Kernel-Boot 238Records the time-zone bias and firmware time reported by UEFI firmware.If the boot time looks off, check the BIOS clock and the motherboard battery (CMOS).
    Kernel-General 15Records that a registry hive was reorganized and its size reduced.Check the hive name and the change in size.
    Kernel-General 16Records that the access history of a registry hive was cleared.Even a large number of repeats is normal.
    Kernel-General 20Records that the leap second setting was updated.Use as a reference when investigating time synchronization problems.
    Kernel-General 24Records that time-zone information was updated.If the time is off, check the time-zone setting.
    Kernel-General 25Records the values the system time was initialized to at boot (RTC time, loader time, whether it succeeded).If Success is false or the RTC error code is not 0, check the motherboard battery and the BIOS clock.
    EventLog 6009An informational event that records the Windows version/build and the processor configuration (for example Multiprocessor Free) at boot.Use together with 6005 and 6013 when checking boot time and the Windows build.
    Subsys-SMSS 17Records that a platform binary (an executable supplied by the firmware) ran successfully.If a program installed by the firmware is suspected, check whether it ran.
    Wininit 23Records the result of initializing Boot App Anti-Rollback.Check only if the HRESULT is not a success.
    Wininit 24Records that the Boot App Anti-Rollback timer started (including start time, grace period and expiry time).Check only if Win32Error is not 0.
    Wininit 25Records that the previous Boot App Anti-Rollback timer was continued.Check only if the HRESULT is not a success.

    When to worry

    • If there are no Error or Warning records from the same time, you can ignore this group.
    • If the time looks off, read the Success value and the RTC error code in Kernel-General 25 and the firmware time in Kernel-Boot 238, then check the BIOS clock and the motherboard battery (CMOS).
    • If boot is slow, compare the firmware-phase time in Kernel-Boot 30 with other days, and if a BitLocker PIN is the reason, see whether Kernel-Boot 32 is not 0.
    • Wininit 23, 24 and 25 are records of the Boot App Anti-Rollback feature. Check them only when the HRESULT or Win32Error is not a success (0).
    Caution

    Do not conclude a failed part or a security incident from one information-level record. Use it as a clue only when Error/Warning records from the same time and a real symptom (drops, reboots, slowness) accompany it.

    Frequently asked questions

    • These records appear at every boot. Is my PC broken? No. Information-level records report a normal boot process and do not mean an error. Use them as a clue only when there are Error/Warning records from the same time and a real symptom.
    • Is Kernel-Boot 153 part of this group? No. Kernel-Boot 153 is a record that virtualization-based security is enabled, so it is explained in a separate group (the VBS and security records page). Its source differs from Disk 153 and the graphics driver's 153.
