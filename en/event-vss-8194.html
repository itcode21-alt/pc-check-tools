    EVENT ID 8194

    VSS Event 8194: IVssWriterCallback Access Denied

    8194 is a record that VSS failed with access denied while querying the callback interface a writer provides. It is usually a situation where the service account lacks COM access permission, and whether the backup actually failed has to be checked separately.

    Several backup vendors' documents report that this record is also left in environments where the backup completes normally, but you cannot assume it is harmless in every environment. Move on to the permission check when the backup result shows a failure or vssadmin list writers shows an error state.

    When it appears

    • It is left every time a backup or restore program runs
    • An error when running vssadmin list writers
    • VSS 8193 records are logged with it

    Likely causes

    • The service account (Network Service and so on) has no access permission to the COM component VSS requested
    • Security software or a policy limits the service's permissions
    • A service-permission configuration in a cluster environment

    What to check, in order

    1. Write down the error code in the event body (such as 0x80070005) and the component that was called. Start with what is easy to undo so you can narrow the range without risk.
    2. In an administrator command prompt, check with vssadmin list writers whether any writer is in an error state. Compare with the first check to narrow the cause candidates.
    3. Check whether the backup job really succeeded. If it still reproduces at this step, move on to the next item.
    4. Compare with VSS 8193 at the same time. See whether the symptoms differ before and after the change.
    5. Change COM permissions only after checking the backup software manufacturer's and Microsoft's guidance. If it is still unsolved after all this, review the next cause.
    Caution

    DCOM and COM security permissions are hard to undo once changed. If the backup completes normally, do not change permissions just because of the record.

    Make a restore point before changing permissions.

    Frequently asked questions

    • 8194 appears but the backup succeeds. Can I ignore it? If the backup completes normally and there are no other errors, it is often kept as something to observe. If a backup failure or a writer error state is present as well, find the cause.
    • Will changing DCOM permissions fix it? In an environment where lacking permission is the cause it may help, but it is hard to undo once changed. Proceed only after securing the manufacturer's and Microsoft's guidance and a restore point.
