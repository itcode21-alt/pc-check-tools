    EVENT ID 1001

    BugCheck Event 1001: Blue Screen Details in the Log

    BugCheck 1001 is the record Windows leaves in the System log right after a blue screen (stop error). The stop code, four parameters and the dump file path are recorded together, so it is the first source for the analysis.

    With the source BugCheck, event 1001 is written at the moment of the crash. Unlike Windows Error Reporting 1001 (a later report), it carries the stop code, the four parameters and the dump path itself.

    Look up the stop code in the General tab (for example 0x0000009c), or open the saved dump (C:\Windows\Minidump) in a crash-dump analysis tool to see which driver was involved.

    When it appears

    • On reboot right after a blue screen
    • After an unexpected system shutdown

    Likely causes

    • A kernel crash caused by a driver or hardware error
    • System halt due to unstable memory or power
    • Unstable overclock or XMP/EXPO settings

    What to check, in order

    1. Read the stop code (for example 0x0000009c) and the four parameters in the General tab.
    2. Compare WHEA-Logger and Kernel-Power events at the same time.
    3. Analyze the dump files in C:\Windows\Minidump with a dump analyzer.
    4. If the event has piled up several times, compare whether the stop code is the same each time — if the code differs every time, suspect memory (RAM) before one specific driver.
    Caution

    The record itself is not the cause; it only states that a crash happened and its details. Use the stop code to narrow the candidates.

    Frequently asked questions

    • How do BugCheck 1001 and Windows Error Reporting 1001 differ? They share the event ID but have different sources. BugCheck records the stop code and parameters at the moment of the crash; Windows Error Reporting only records afterwards that the error was reported. BugCheck is more direct for analysis.
    • No dump file was created. Can I still analyze with only this event? Yes. The stop code and parameters in the event body are enough to look up the candidate causes and a check order; if a dump exists, analyzing it identifies the faulty driver more precisely.
