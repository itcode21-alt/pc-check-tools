    EVENT ID 158

    Disk Event 158: Duplicate Disk Identifier

    Disk 158 is a warning that two or more disks use the same identifier or GUID. It can appear with cloned VHDs, storage exposed over several paths without MPIO, and some external-disk setups; by itself it does not mean a physical disk failure.

    First check UniqueId and the disk layout with Get-Disk to tell whether really different devices are duplicates or the same device is visible over several paths. Changing an identifier or initialising a disk risks data loss, so a backup and confirmation of the target are needed.

    When it appears

    • After a disk was added or cloned
    • Several external disks or VHDs are connected
    • Disk numbers or volume identification differ from what you expect

    Likely causes

    • A copied VHD keeps the same disk identifier
    • The same physical disk is exposed over several paths without MPIO
    • Identifier duplication during storage or virtual-disk cloning

    What to check, in order

    1. Check Number, FriendlyName and UniqueId in Get-Disk. Start with what is easy to undo so you can narrow the range without risk.
    2. If it is one device over several paths, check the MPIO and storage configuration. Compare with the first check to narrow the cause candidates.
    3. If it is a cloned VHD, tell the original from the copy and consider Set-VHD -Path <path> -ResetDiskIdentifier. If it still reproduces at this step, move on to the next item.
    4. For USB external disks, remove them safely and connect them one at a time to see which device triggers it. See whether the symptoms differ before and after the change.
    5. Before changing a duplicate identifier by hand, make a backup and be sure of the target disk. If it is still unsolved after all this, review the next cause.
    Caution

    158 does not necessarily mean a disk failure or poor performance. Tell the duplicate-identifier warning apart from a real I/O failure.

    Changing the identifier with diskpart or an initialisation command can lose data, so do not run it without confirming the target.

    Frequently asked questions

    • Do I need to replace the disk when 158 appears? No. A duplicate-identifier warning and a physical failure are separate things. Check whether real I/O errors or access failures appear together.
    • What should I do if it appears after cloning a VHD? Tell the original from the copy, then consider Set-VHD -Path <path> -ResetDiskIdentifier in a Hyper-V environment. Do not run diskpart or an initialisation command without confirming the target.
