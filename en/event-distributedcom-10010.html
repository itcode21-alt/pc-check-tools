    EVENT ID 10010

    DistributedCOM Event 10010: Server Did Not Register in Time

    10010 records that a DCOM server did not register within the time limit. It means something only when it appears at the same time as a real delay in sign-in or app launch; if it repeats only at boot without any malfunction, it is something to observe.

    The CLSID and AppID in the event description tell you which component it is. Looking at it together with Service Control Manager 7000, 7009 and 7011 at the same time helps you judge whether a slow service start is the cause.

    When it appears

    • A delay of about 10–15 seconds right after sign-in
    • A particular app, widget or service starts slowly
    • Repeats only at boot with no malfunction

    Likely causes

    • The linked service has not started yet
    • A delay in an app component or Windows app package
    • High storage or CPU load
    • A recent app update or a service configuration conflict

    What to check, in order

    1. Write down the CLSID, AppID and server name from the event. Start with what is easy to undo so you can narrow the range without risk.
    2. Compare with Service Control Manager 7000, 7009 and 7011 at the same time. Compare with the first check to narrow the cause candidates.
    3. Check whether there really is an app or feature that is delayed. If it still reproduces at this step, move on to the next item.
    4. Compare whether it reproduces after repairing or updating the app and in a clean boot. See whether the symptoms differ before and after the change.
    Caution

    Do not apply a fix that simply changes permissions, as you might for 10016, first. If there is no malfunction it may only need observing.

    Frequently asked questions

    • 10010 appears at every boot. Should I fix it? If there is no malfunction or delay you do not need to act urgently. Only if sign-in is slow for a few seconds along with it, narrow the cause down with a clean boot and similar steps.
    • Should I change DCOM permissions as with 10016? No. 10010 is a registration-timeout record, not a permission denial, so changing permissions is unrelated. Do not change DCOM permissions casually.
