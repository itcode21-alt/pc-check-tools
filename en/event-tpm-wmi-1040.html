    EVENT ID 1040

    TPM-WMI Event 1040: Device Attestation Pre-check Failed

    The wording looks serious, but this event is not an actual failure: it is the result of Windows diagnosing itself ahead of time by measuring the boot process (Measured Boot). Read together with the original log (TPM-WMI 1801 and so on), it is in most cases a sign that the Secure Boot certificates have not yet been updated, so the measured values differ from what was expected.

    If real features such as BitLocker and Windows Hello are working normally, there is no urgent action. The first step is to check whether a real function is actually failing.

    When it appears

    • Recorded around the same time as TPM-WMI 1801
    • While using features that need device attestation, such as BitLocker and Windows Hello
    • A result JSON file is created in the MeasuredBoot log folder

    Likely causes

    • The Secure Boot certificates are not up to date, so the boot measurements differ from what was expected
    • The BIOS/UEFI firmware is old and the Measured Boot chain does not match the expected values
    • A defect or initialization state problem in the TPM firmware itself

    What to check, in order

    1. Open the JSON file in the MeasuredBoot log folder named in the event and see which component failed. Start with what is easy to undo so you can narrow the range without risk.
    2. Check whether TPM-WMI 1801 (Secure Boot certificates not applied) appears around the same time. Compare with the first check to narrow the cause candidates.
    3. Update to the latest BIOS from the motherboard or laptop maker and check whether it still reproduces. If it repeats at this step, move on to the next item.
    4. Check whether there is a real failure in features such as BitLocker and Windows Hello. If they work normally, there is no urgent action.
    Caution

    The wording looks serious, but if BitLocker and Windows Hello have no real failure, do not reset or reinstall right away. Before resetting the TPM, always back up the BitLocker recovery key.

    Frequently asked questions

    • Does this event mean I can no longer use BitLocker or Windows Hello? Not immediately. BitLocker and Windows Hello that are already set up often keep working. Some enterprise and cloud sign-in scenarios that require attestation may be restricted, so first check whether a real function is failing.
    • How do I open the JSON file in the MeasuredBoot log? Open the C:\Windows\Logs\MeasuredBoot folder in File Explorer and open the file named in the event with Notepad or another text editor; you can read in text which component check failed.
