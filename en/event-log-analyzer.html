EVENT LOG ANALYZER

Windows Event Log Analyzer

Paste text or XML copied from Event Viewer, or PowerShell output, and the analyzer reads each record's Source and Event ID and lays out what it means and what to check first. It narrows down where to look from the combination of records, and when there are restart records it also shows the records in the 10 minutes before and after and the gaps between repeats. All processing happens in this browser; what you paste is not sent anywhere.

Load from a file (.txt .xml .csv, up to 2 MB):

This page accepts text and XML only. To analyze a .evtx file, use the Event Viewer tab of the diagnostic tool (Korean). The example is a made-up record for illustration.

What does each button copy or save?

  • Copy summary — copies the list of analyzed events as a few lines of text. Each line has the source name, event ID, how many times it appeared and the address of the explanation page. Use it to paste straight into a community question or a chat.
  • Copy as Markdown — copies the same content in table form. Pasted into places that support Markdown (GitHub, Discord, Notion) it shows as a table; where it is not supported the | characters appear as they are, so use “Copy summary” there.
  • Copy share link — copies a web address that reopens this result. Sending it to someone opens the same event summary. The address contains only the source, event ID and count, nothing is stored on a server, and because it has no times the distribution and before/after records are not shown.
  • Save CSV — downloads the per-event summary (source, ID, count, level, first/last record time, explanation page) to your PC as event-log-summary.csv, which opens in a spreadsheet. It contains times, so keep that in mind when sending it to others.
  • Print / save PDF — prints the current result (overall assessment, distribution, before/after records, event cards) or keeps it as a PDF. In the print dialog choose “Save as PDF” instead of a printer. It is exactly what you see on screen, so record times are included.

Which should I choose? Use “Copy summary” when asking for help, “Save CSV” to organize in a spreadsheet or keep a file, and “Print / save PDF” to keep the screen as it is. The summary, Markdown and share link do not include record times or event bodies. Every button works only inside this browser and sends nothing you entered to a server.

Formats you can paste

  • Event Viewer General tab text: double-click an event to open it and copy the body. The “Source”, “Event ID” and “Date” lines are read.
  • XML view on the Details tab: the <Provider Name>, <EventID> and <TimeCreated> values are read. You can paste the XML of several events one after another.
  • PowerShell Format-List output: the ProviderName, Id and TimeCreated lines are read. This is the easiest way to collect many records at once.
  • One-line table or CSV rows: only when none of the formats above is present, it looks for lines where a source name and an ID that this site knows appear together.

To collect only the errors and warnings of the last 3 days as text, open PowerShell, run the command below and copy the output. Usage is documented at Microsoft Learn: Get-WinEvent.

Get-WinEvent -FilterHashtable @{LogName='System'; Level=1,2,3; StartTime=(Get-Date).AddDays(-3)} -MaxEvents 100 | Format-List TimeCreated, ProviderName, Id

Level 1, 2 and 3 are Critical, Error and Warning. If there are too many records, lower the -MaxEvents value or narrow StartTime to the day the symptom happened.

Build a collection command for your symptom

Choose a symptom and a period and the page builds a PowerShell command that collects only the matching events. Paste the command into PowerShell, run it, and paste the output into the box above.

Custom date range (optional): choosing dates overrides the “Period” above.

How to use the command

  1. Copy the command: press “Copy command” above.
  2. Open PowerShell: right-click the Start button and choose Windows PowerShell (Terminal on Windows 11). Administrator rights are not needed. Check that PS appears at the start of the prompt; this command does not work in Command Prompt (cmd).
  3. Paste and run: right-click in the PowerShell window or press Ctrl+V to paste, then press Enter. After a few seconds the events are listed as TimeCreated, ProviderName and Id lines. If nothing appears, there were no such events in that period, so widen it.
  4. Copy the output: select the output by dragging with the mouse and copy it (in the classic console window, select and right-click; in Terminal press Ctrl+Shift+C). If there are more lines than fit on the screen, scroll up and select from the start to the end, or lower the “Count” above and run again.
  5. Analyze: paste what you copied into the box at the top of this page and press “Analyze”.

This command only reads the event log; it does not change settings or files. The output contains only the record time, the source name and the event ID, not the computer name or user name.

The System and Application logs can be read with normal PowerShell rights. If there is no result, the output is empty without an error. Widen the period or change the symptom. If there were several restarts, it is easier to read when you narrow the period to the day the symptom occurred.

How to read the result

  • Source and ID are a pair. The same number means something different when the source differs. Event 7001 means different things for Service Control Manager and Winlogon, 1001 for BugCheck, Windows Error Reporting and DHCP-Client, and 153 for Disk and nvlddmkm. So the tool does not guess at records with no source and shows only the candidates that use the same ID.
  • The level badge is the usual weight of that kind of event. The Critical, Error, Warning and Information badges say how seriously such an event is normally treated; they are not a verdict that your PC is at that level. Even for the same warning, a record seen once and one repeated dozens of times a day should be read differently.
  • “These patterns appear” narrows where to suspect first from the combination of events. It separates storage, WHEA hardware errors, graphics driver, blue screen, sleep/resume, device start problems, service failures, update/install failures, wireless/wired connection problems and sign-in failure paths. It does not confirm a cause.
  • The distribution over time appears when there are 5 or more records with times. Within 48 hours the bars are one hour each, otherwise one day each, and periods that include restart records are orange. If records cluster in one period it is a clue to recall what you were doing then.
  • Logs worth collecting points out clues missing from the pasted range, for example restarts with no blue screen or WHEA records, or records whose time or source could not be read.
  • Comparison with the previous analysis appears when you collect again with the same command after a fix and press “Analyze” once more. It separates events that disappeared, events still seen and new events. The previous result lives only in this tab's memory while the page is open and is not saved.
  • Narrowing the results appears when there are 4 or more distinct events. You can filter the cards below by level, by whether there is an explanation, by 3 or more repeats, and sort by importance, repeat count or recency; it changes only the screen, and your input is unchanged.
  • The format read and time recognition are shown in the status line at the top of the result. Check that it was read in the format you intended (XML, PowerShell, General tab) and how many records had a readable time. Without times, the before/after records and the distribution cannot be built.
  • Records before and after restarts appear only when Kernel-Power 41 or EventLog 6008 is present and times were pasted. A restart record only records the result “not shut down normally”, so what came before it is the clue that narrows the cause. A preceding record is not evidence of the cause, though.
  • Events without an explanation are shown separately as dashed cards. The tool does not pretend to explain every event: it points to a Microsoft Learn search and offers a request link (GitHub, public). Only the source and event ID are pre-filled in the request link. Explanations are in English for 56 common events and the informational-record groups; for others the Korean explanation is linked where one exists.

What this tool does not do

  • It does not conclude from one event that a power supply, memory or SSD is faulty. An event is a record of what Windows saw.
  • No AI writes text for it. It shows an explanation only when the event matches data registered on this site.
  • It neither reads nor stores values such as computer names, user names or IP addresses. The analysis uses only the source, the event ID and the record time.
  • For a combined analysis of symptoms, error codes and parts, or to load a .evtx file directly, use the diagnostic tool (Korean). This page is a light tool that quickly organizes pasted records by event.

Frequently asked questions

Is the text I paste sent to a server?

No. The analyzer runs only in your browser and does not send or store what you paste. It uses only the source, the event ID and the record time, and does not read computer names or user names.

Can it interpret an event from the ID alone?

The source is needed too. Event ID 7001 means different things for Service Control Manager and Winlogon, and 1001 means different things for BugCheck, Windows Error Reporting and DHCP-Client. With an ID alone it can only list the candidates that use that ID.

What about events without an explanation on this site?

They are shown separately with a Microsoft Learn search link. The tool does not invent meanings. English explanations currently exist for 56 common events and for the informational records grouped on five pages; for the others it points to the Korean explanation where one exists.

Can the result confirm a failed part?

No. An event records what Windows saw; it does not name the faulty part. Use the tool to decide which records to read first and in what order to check.
