    EVENT ID 7023

    Service Control Manager Event 7023: Service Terminated With an Error

    7023 records that a service ended after returning its own error code. The wording at the end of the description, read together with the service name, narrows the cause.

    If the same error repeats, searching for that wording together with the service name for a known fix is the efficient first step.

    On some PCs the description ends with a message such as “The system is shutting down” instead of a numeric code, and the 7023 sits a few seconds before the Kernel-Power 109 that announces the restart.

    When several services show it at once

    • The approach differs depending on whether 7023 comes from one service or from several at the same time.
    • From one service only: it is a configuration or file problem of the program that service belongs to.
    • From several at once: shared components or permission settings may have changed. Run a system file check first rather than restarting each service.

    When it appears

    • A feature fails to run
    • A service stops during boot

    Likely causes

    • Damaged service configuration or files
    • Permission or dependency problems

    What to check, in order

    1. Read the error wording in the description: because 7023 means the service ended with its own error, the text at the end is the clue. Write it down exactly, for example “Access is denied” or “The specified service is not installed”.
    2. Look up the wording together with the service's purpose: the same wording needs different action per service, so search the service name and the wording together and see which feature it belongs to.
    3. Check dependencies and the log-on account: look at the Dependencies and Log On tabs in services.msc. A permission-type message points to the log-on account; a start-failure message points to a prerequisite service.
    4. Check for damaged system files: if several services give 7023 together, suspect shared components. Run sfc /scannow from an administrator prompt first, and if it cannot repair, run DISM /Online /Cleanup-Image /RestoreHealth.
    Caution

    Restarting the service without the error text can hide the cause of recurrence.

    Frequently asked questions

    • Where do I find the error code? At the end of the event description, where the code the service returned is shown. Searching it with the service name narrows the cause.
    • Can I just restart the service without the error code? It may work temporarily, but you can miss why it recurs. Record the error code first, then restart.
    • In what order do I run sfc and DISM? Run sfc /scannow first. If it reports damage it could not repair, run DISM /Online /Cleanup-Image /RestoreHealth to repair the component store, then run sfc once more. Both need an administrator command prompt.
