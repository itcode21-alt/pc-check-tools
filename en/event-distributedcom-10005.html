    EVENT ID 10005

    DistributedCOM Event 10005: Service Start Error

    10005 records that DCOM tried to start a service it needs and ran into an error. The clue is not the record itself but the service name and error number written in the event description.

    A dependent service that has been stopped, or whose startup type was changed, is a common cause. Check the service and the services it depends on in services.msc, and compare with Service Control Manager 7000, 7001 and 7023 at the same time.

    When it appears

    • A particular feature fails to run
    • A service start error during sign-in or boot
    • Search, authentication or network features stop working together

    Likely causes

    • A dependent service was stopped or its startup type was changed
    • Damaged service files or app configuration
    • A service switched off by a security policy or a clean boot

    What to check, in order

    1. Write down the service name and the error number in the event description. Start with what is easy to undo so you can narrow the range without risk.
    2. Check the state of that service and its dependent services in services.msc. Compare with the first check to narrow the cause candidates.
    3. Compare the time with Service Control Manager 7000, 7001 and 7023. If it still reproduces at this step, move on to the next item.
    4. If it is a needed service, consider repairing the Windows component or reinstalling the app. See whether the symptoms differ before and after the change.
    Caution

    Do not switch every service to automatic start in one go or edit the registry.

    Frequently asked questions

    • Does changing all services to automatic fix it? It is not recommended. Check only the services you need; a bulk change can cause boot delays or conflicts.
    • Where do I find the error number? It is written in the event description together with the service name. Note the number and look up the explanation of the same Windows error code.
