    EVENT ID 55

    Kernel-Processor-Power Event 55: Reading the Processor Power Management Record

    Kernel-Processor-Power 55 is an informational event that records, at boot and for each logical processor, the idle states (C-states), the performance state method (such as CPPC), the base frequency and the maximum and minimum performance percentage. For example, a body starting with 'Processor 11 in group 0 exposes the following power management capabilities' is left once per processor.

    Even if the count looks like several hundred, it is normal because it is the number of logical processors times the number of boots. CPU slowdown or overheating should be judged not from this event but from other IDs of the same provider and from temperature and clock records.

    When it appears

    • At every boot, recorded all at once for as many logical processors as there are

    Likely causes

    • A normal boot record — the count is the number of logical processors × the number of boots

    What to check, in order

    1. Check that the count is not far from (number of logical processors × number of boots).
    2. If the number of idle states or the performance state method is not shown, check the CPU power management settings in the BIOS (C-state, CPPC).
    3. Check slowdown and overheating not with this event but with another ID of the same provider (for example 37) and temperature records.
    Caution

    It is not an error or a warning. Even if the count looks large, it is normal.

    Frequently asked questions

    • There are several hundred 55 events — is that a problem? No. It is left as many times as the number of logical processors × the number of boots. For example, a PC with 24 logical processors booted 10 times gives 240 records.
    • Should I look at this event when CPU performance drops? This event only tells you which power management capabilities the CPU provides. For slowdown, check the temperature and power limit records in HWiNFO together with other events of Kernel-Processor-Power.
