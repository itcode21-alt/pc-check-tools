    EVENT ID 7031

    Service Control Manager Event 7031: Service Terminated Unexpectedly

    7031 records that a service ended unexpectedly and Windows scheduled a recovery action such as a restart. Whether the count keeps growing is what decides if action is needed.

    A scheduled recovery means Windows is aware of the problem, so watch whether it repeats, but do not rush to touch system files.

    What 7031 does and does not tell you

    • 7031 tells you what stopped and how Windows will respond, but not why it stopped. Look for the cause in other records from the same time.
    • Application Error 1000 — keeps the faulting module name and exception code. It is the most direct clue.
    • Windows Error Reporting 1001 — if a crash report was created, the summary is here.
    • 7000/7023 for the same service — logged if it failed again after the restart.

    When it appears

    • An app or network feature suddenly stops

    Likely causes

    • A service crash
    • A module or driver error

    What to check, in order

    1. Check the service name and the count: in “This action was performed N time(s)” N shows how much it repeats. If N keeps growing it is a reproducible problem, not a transient error.
    2. Check whether Application Error 1000 is present: 7031 reports only the result, not the faulting module. The 1000 from the same time holds the module name and exception code, and the real investigation should start from that module.
    3. Check the recovery settings: in services.msc → the service's properties → Recovery tab, look at the first and second failure actions. Restart is configured there, which is why 7031 is logged; the setting itself is not the problem.
    4. Repair the program the faulting module belongs to: if the module is a program's file, repair or update that program; if it is a driver file, reinstall that driver from Device Manager.
    Caution

    Act when the repeat count increases.

    Frequently asked questions

    • Windows restarts it automatically — can I just wait? If a recovery action is scheduled you can wait a little. But if the count keeps rising, reinstalling the related program is safer.
    • How does it relate to Application Error 1000? They may be the same crash recorded from the service side and from the application side. Compare the times and the target program.
    • Which items in Application Error 1000 should I look at? The faulting module name and the exception code. If the module is a DLL of a program, investigate that program; if it is a driver file (.sys), investigate that device driver.
