    EVENT ID 15

    Disk Event 15: Device Not Ready for Access

    15 records that the specified disk device was not yet ready to be accessed. The first thing to compare is whether the time it appears coincides with a connection, a wake from sleep or a virtual-machine snapshot.

    A VMware (Broadcom) knowledge-base article says this event can be recorded right after a quiesce snapshot of a virtual machine and can be ignored. On a physical PC, one or two records with no symptoms are something to watch; if freezes or file errors repeat alongside it, move on to checking the storage device.

    When it appears

    • Right after connecting an external drive or USB storage, or waking from sleep
    • Right after a virtual-machine (quiesce) snapshot
    • Storage is recognised late during boot

    Likely causes

    • An access request arrived while the device was still initialising
    • A controller, driver or firmware problem
    • An unstable cable, port or power supply
    • A virtual-machine snapshot removed a temporary disk

    What to check, in order

    1. Check which disk number it is and whether it is external or internal.
    2. Check whether the time coincides with a connection, a wake from sleep or a snapshot.
    3. Compare with Disk 7, 11, 51 and 153 records from the same time.
    4. Change the cable and port, and compare the USB selective suspend setting.
    5. If it repeats on an internal device, check SMART and the controller driver.
    Caution

    If it repeats together with disk access errors, back up before you check anything.

    Do not change the device timeout value without knowing the cause.

    Frequently asked questions

    • 15 is recorded every time I plug in my external drive. Is that all right? It is common for an access request to arrive before the device is ready. If there are no real file-access errors, just observe; if there are, check the cable, the port and the USB power-saving setting.
    • It appears only in a virtual machine. VMware says it can be harmless right after a snapshot. If it repeats regardless of snapshots, or disk errors inside the guest appear with it, check the storage connection.
