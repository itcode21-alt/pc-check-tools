    EVENT ID 15

    HAL Event 15: IOMMU Error

    This record, whose source is HAL (Hardware Abstraction Layer), shows the sentence “The IOMMU has encountered an error” together with Device (device ID), FaultInformation (address of the fault) and FaultReason (fault reason code).

    The IOMMU is a hardware layer that watches that PCIe devices stay within the allowed range when they access system memory directly (DMA); when it detects a problem during that watching, the error is recorded.

    The event by itself does not mean a part has failed. If it was recorded a few times in a cluster over a few weeks and then never recurred, it was most likely a temporary issue with a particular driver version or the initialization timing.

    When it appears

    • While using virtualization (Hyper-V, WSL2 and so on) or GPU passthrough
    • After the connection state of a particular PCIe device (GPU, NVMe, USB controller and so on) changed
    • A pattern that repeats in a short period and then stops

    Likely causes

    • The motherboard BIOS/UEFI IOMMU (AMD-Vi, VT-d) settings are not up to date
    • A particular PCIe device's driver or firmware makes wrong DMA requests
    • Virtualization software (Hyper-V, VMware and so on) conflicts with the hardware IOMMU mapping
    • Poor physical contact in memory or a PCIe slot

    What to check, in order

    1. Check the motherboard maker's website for the latest BIOS update. Start with what is easy to undo so you can narrow the range without risk.
    2. Write down the Device and FaultInformation values in the event and check whether the same values repeat. Compare with the first check to narrow the cause candidates.
    3. If you recently added or replaced a PCIe device, reseat it in its slot. If it still reproduces at this step, move on to the next item.
    4. Temporarily turn off virtualization features such as Hyper-V and WSL2 and compare whether it still reproduces. Compare the symptoms before and after the change.
    5. If it repeats after a restart, move the device to another slot or remove it to identify the cause device. If it still repeats, consider the next cause.
    Caution

    Do not conclude from this one event that the motherboard or CPU has failed. If it does not recur, it was most likely a temporary driver or initialization issue. If power is lost during a BIOS update, the motherboard can be damaged, so keep a laptop plugged in to its charger.

    Frequently asked questions

    • Does an IOMMU error mean the motherboard or CPU is broken? It cannot be concluded. If it was recorded a few times in a cluster and then never recurred, it was most likely a temporary driver or initialization issue. Judge it together with how often it repeats.
    • Can this error appear even if I do not use virtualization (Hyper-V, WSL2)? Yes. The IOMMU is not a virtualization-only feature but a hardware layer that controls PCIe devices' DMA access, so it can be recorded because of a driver or firmware problem of a particular PCIe device even without virtualization.
