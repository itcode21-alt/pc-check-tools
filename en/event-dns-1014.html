    EVENT ID 1014

    DNS Client Events 1014: Name Resolution Timed Out

    1014 records that a DNS name-resolution request did not get an answer within the timeout. In Event Viewer the source may show as DNS Client Events or Microsoft-Windows-DNS-Client. It often appears with symptoms such as only some sites being slow, or a game launcher or Windows Update failing to find its server.

    This event alone cannot tell you that the internet line or the network card is faulty. Compare the QueryName (the domain looked up) and the time with the time the connection really failed, and compare the answers of the default DNS server with another DNS server to narrow the cause.

    Name-resolution delay is not the same as a dropped connection

    • 1014 means that turning a domain name into an IP address did not finish within the timeout. That is different from the line itself being down.
    • If a site does not open by its address but does open by IP, it is a typical name-resolution problem.
    • If the domain names in the records are concentrated on a particular service, suspect that service or the filter of a security program.

    When it appears

    • Websites open slowly
    • Right after switching Wi-Fi

    Likely causes

    • A DNS server delay or a temporary failure to answer
    • A DNS cache or routing problem on the router or the ISP line
    • The influence of a DNS filter in a VPN, proxy or security program
    • The wireless driver still preparing the connection right after wake from sleep

    What to check, in order

    1. Narrow the scope: is it only this PC? See whether other devices on the same router (a phone, for example) are also slow on the same site. If the other devices are slow too, it is a router or line problem and there is no need to touch the PC settings.
    2. Check whether the same domain is also slow on other devices on the same router. If it is slow on all devices, check the router, the line and the DNS service before the PC.
    3. Flush the DNS cache: run ipconfig /flushdns in an administrator command prompt, then compare the default DNS response time with nslookup example.com.
    4. Compare DNS server answers: in PowerShell run Resolve-DnsName example.com and Resolve-DnsName example.com -Server 1.1.1.1. If only one server is slow, suspect the DNS server or a difference in the router settings.
    5. Compare with a public DNS: temporarily change the DNS in the adapter settings to 1.1.1.1 or 8.8.8.8 and see whether it still reproduces. Note the original DNS address first, and on a company or school network check the administrator policy first.
    6. Check VPN and security-program filters: a web filter in a VPN or an internet security product can intercept name resolution and cause delays. Disconnect it briefly to see whether it still reproduces, and turn protection back on once solved.
    7. Compare related events: check DHCP-Client 1001, Tcpip 4199 and 4266 and WLAN-AutoConfig events at the same time. If you see a 169.254.x.x address or DHCP failures, check the IP and gateway before DNS.
    Caution

    If the internet is fine and it was a one-off, do not treat it as a hardware failure.

    Frequently asked questions

    • If only one site opens slowly, is this event the reason? A DNS resolution delay can affect only a particular domain. If other sites are fine and only one is slow, the server of that site itself may be the problem.
    • Does restarting the router fix it? If it is a temporary DNS cache or routing problem, a router restart often fixes it. If it repeats, change the DNS server address and compare.
