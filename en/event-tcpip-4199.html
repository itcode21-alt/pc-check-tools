    EVENT ID 4199

    Tcpip Event 4199: IP Address Conflict

    Tcpip 4199 records that Windows detected the same IP address being used twice on the network. As Microsoft describes, it can also appear as duplicate detection while receiving a DHCP address, so first write down the conflicting address shown on the General tab and the hardware address of the other party.

    If it happened once and the internet and the local network are fine, it may have been a temporary DHCP or wake-from-sleep situation. Only when there are repeated disconnections or IP conflict notifications should you check the router's lease list and the fixed-IP configuration together.

    When it appears

    • No internet after boot or wake from sleep
    • An IP address conflict notification or a dropped connection
    • Right after a DHCP renewal, a router restart or a VPN connection

    Likely causes

    • The router or DHCP server leases an address that is already in use
    • A fixed IP overlaps with a DHCP address
    • A duplicate address is detected while switching after wake from sleep, a VPN or a virtual adapter
    • A router firmware or network-device address-management problem

    What to check, in order

    1. From the General tab and the XML, write down the conflicting IP address, the other party's hardware address and the adapter name. Start with what is easy to undo so you can narrow the range without risk.
    2. Check whether DHCP is used and the current address with ipconfig /all, and check for a duplicate fixed IP. If “DHCP Enabled” is “Yes”, the address comes from the router; if “No”, it is a fixed IP. Compare with the first check to narrow the cause candidates.
    3. Compare the router's DHCP lease list with its fixed assignments. If it still reproduces at this step, move on to the next item.
    4. Compare whether it reproduces with the VPN and virtual adapters turned off, and on another router or cable. See whether the symptoms differ before and after the change.
    5. If it repeats, update the PC and router firmware and the network driver and review the DHCP lease information. If it is still unsolved after all this, review the next cause.
    Caution

    If it happened once or twice and there is no problem using the internet, it may be a temporary duplicate detection. Adjust the address allocation only when there are repeated disconnections.

    Before arbitrarily fixing the same IP or narrowing the DHCP range, check the configuration of the other devices on the current network.

    Frequently asked questions

    • Is 4199 evidence of hacking or malware? No. It is a network event that records detection of a duplicate IP address. It can also occur with router DHCP, a fixed IP, or a VPN or virtual adapter configuration, so do not conclude it is a security problem.
    • What should I check first when 4199 repeats? Write down the conflicting IP from the event, check whether it is DHCP or a fixed IP in ipconfig /all, and compare with the router's DHCP lease list. Checking whether it reproduces with the VPN off or on another router also narrows the range.
