    EVENT ID 140

    Ntfs Event 140: Transaction Log Flush Failed

    Ntfs 140 records that NTFS could not write data to the transaction log and warns the volume may be corrupted. Look at the storage I/O path and file-system state together.

    It can come with slow storage response, a lost connection or a power cut, so compare Disk events from the same time. Even if files open normally, a repeating 140 can show instability in the storage path: reduce writes and copy important data to another device before looking for the cause.

    When it appears

    • A freeze or delay while saving
    • During an external-disk or virtual-machine snapshot task
    • Together with Ntfs 55/50 or Disk errors

    Likely causes

    • Slow storage response or a lost connection
    • SATA, USB or storage-controller problems
    • A power cut or abnormal shutdown
    • Filter-driver or virtual-storage problems

    What to check, in order

    1. Back up important files first and note the event's VolumeId and DeviceName.
    2. Compare whether Disk 7, 11, 51, 98, 129 or 153 appear at the same time.
    3. Check SMART, cable, port and M.2 seating.
    4. After backing up, check the volume and device with fsutil dirty query and the maker's diagnostic tool.
    5. If it repeats, update the storage, controller and filter drivers and cross-test.
    Caution

    140 alone does not mean files are already damaged, but if it repeats, reduce writes and prioritize backup because of the risk of data loss.

    Frequently asked questions

    • Does 140 mean my files are already damaged? It warns of possible damage, but actual damage must be confirmed by checking files and the volume. If it repeats, back up first.
    • Which events should I look at with it? Check whether Disk 7, 11, 51, 98, 129, 153, Ntfs 55/50 and storahci/stornvme events appear at the same time.
