    EVENT ID 36874

    Schannel Event 36874: TLS Negotiation Failed

    36874 records that a TLS connection failed because the client and server could not find a common encryption method or protocol. First read the description to see which app failed talking to which server.

    An old program, or a proxy or security appliance that does not support current TLS, or a wrong system clock that breaks certificate validation, can leave a similar record. Simply enabling TLS 1.0/1.1 to lower security is not recommended.

    When it appears

    • Failure to connect to a particular website or update server
    • HTTPS communication errors in an old program
    • Right after a certificate or TLS setting change

    Likely causes

    • A mismatch of TLS versions or cipher suites between client and server
    • TLS compatibility problems of an old app, proxy or security appliance
    • A certificate chain or system-time error

    What to check, in order

    1. Check the Protocol, the error state and the calling process in the event.
    2. Compare with 36888 and any app or Windows Update failures from the same time.
    3. Check the system date and time, and the root certificate updates.
    4. Compare the TLS settings that the app, proxy and server support against the official documentation.
    Caution

    Do not enable TLS 1.0/1.1 unconditionally to lower security, and do not just hide the Schannel log.

    If you run the server, check both the client and server settings together.

    Frequently asked questions

    • How do I read 36874 and 36888 together? 36874 is a negotiation failure and 36888 records that the handshake ended with a fatal alert, so they often appear at the same time. Do not try to fix them separately; first find which app or server is behind it.
    • Does enabling TLS 1.0 fix it? It may connect temporarily, but it lowers security. Upgrading the server or app to current TLS is the proper way; if you truly need it, check the vendor's guidance and the risk first.
