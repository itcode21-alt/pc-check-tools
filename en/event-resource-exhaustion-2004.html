    EVENT ID 2004

    Resource-Exhaustion-Detector Event 2004: Low Virtual Memory

    2004 is a warning that Windows diagnosed the system's virtual memory and commit limit as running low. The event description can show the processes using the most commit at the time, so look at the commit size and the page file together, not only RAM usage.

    If the commit usage keeps rising the longer a particular program runs, you can suspect a leak in the app or a plug-in. If it occurs in several programs at the same time, first check the page file and the free space on the system drive.

    When it appears

    • A program suddenly closes or stops responding
    • Memory runs out after running a game, browser or virtual machine for a long time
    • Commit usage in Task Manager is close to the limit

    Likely causes

    • A virtual memory leak in a particular program or service
    • The page file is off or its size is limited too much
    • Running several large programs at once exceeded the commit limit
    • A RAM shortage together with increased page file use

    What to check, in order

    1. Write down the top memory-using processes and amounts at the time from the event description.
    2. Check the commit usage and the commit limit in Task Manager's Performance > Memory.
    3. Check whether the page file in Settings is automatically managed and the free space on the system drive.
    4. In Task Manager, compare whether the same program keeps increasing its commit each time it is run again.
    5. Split the reproduction by updating the program, removing plug-ins and restarting, and consider a memory diagnostic if it repeats in several apps. If it is still not resolved, consider the next cause.
    Caution

    2004 does not immediately mean bad RAM. Check the process the event points to and the commit size first.

    Continuing heavy work under a memory shortage can lose unsaved data, so save your work first.

    Frequently asked questions

    • Do I need to add RAM when 2004 appears? Not necessarily. A virtual memory leak in a particular program or a page file limit can be the cause. First check the commit usage of the process the event points to.
    • Which value should I look at in Task Manager? On the Performance tab, check the commit usage and commit limit in the Memory item. Looking only at the memory column on the Processes tab can miss the cause of virtual memory exhaustion.
