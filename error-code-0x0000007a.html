에러 코드 상세

0x0000007A · KERNEL_DATA_INPAGE_ERROR

커널 데이터를 디스크에서 읽어오는 도중 실패했을 때 나타나는 코드로, 저장장치나 메모리, 전원 문제가 복합적으로 얽혀 있을 수 있습니다.

이 코드를 어떻게 해석해야 하나요?

저장장치 계열 오류는 Windows가 필요한 데이터를 제때 읽지 못했거나 파일 시스템과 장치 연결에 문제가 생겼다는 단서입니다. 물리 장치 상태와 논리 파일 시스템을 분리해 봐야 합니다.

먼저 기록할 내용: 0x0000007A가 발생한 시각, 직전에 실행한 작업, 최근 설치한 드라이버·업데이트, 재부팅 뒤 같은 코드가 반복되는지를 적어 두세요.

가능성 높은 원인

  • 저장장치의 배드섹터나 물리적 결함
  • 램 모듈의 불안정
  • 전원 공급 불안정
  • 저장장치 케이블 접촉 불량
  • 갑작스러운 전원 종료로 인한 파일 시스템 손상

첫 점검 항목

  1. 디스크 검사 — 관리자 권한 명령 프롬프트에서 chkdsk C: /f /r로 배드섹터 여부를 점검하세요.
  2. 메모리 진단 — Windows 메모리 진단 도구로 램 상태를 점검하세요.
  3. 케이블 연결 확인 — 저장장치와 전원 케이블 연결 상태를 물리적으로 확인하세요.
  4. 전원 공급 확인 — 파워 서플라이 용량이 충분한지 확인하세요.
  5. 데이터 백업 — 중요 데이터는 미리 백업해 두세요.

확인 결과에 따른 다음 단계

  • chkdsk에서 배드섹터가 발견될 때 — 데이터 백업을 최우선으로 하고 디스크 교체를 검토하세요.
  • 메모리 진단에서 오류가 발견될 때 — 램 모듈을 하나씩 꽂아가며 어느 모듈이 문제인지 확인하세요.
  • 둘 다 정상인데 반복될 때 — 저장장치 컨트롤러 드라이버·펌웨어를 업데이트하고, BIOS에서 SATA 모드(AHCI/RAID)가 설치 당시와 같은지 확인하세요.

데이터와 시스템을 보호하는 주의사항

SMART 경고, 읽기 실패, Disk 7·129·153 반복이 있으면 복구 명령보다 중요한 파일 백업을 먼저 진행하세요.

앞 단계로 해결되지 않을 때

백업 후 케이블·포트·M.2 슬롯을 교차하고 제조사 진단과 펌웨어를 확인한 뒤 파일 시스템 검사를 계획하세요.

작업이 잘못됐을 때 되돌릴 수 없는 경우가 많으니, 복구나 초기화, 드라이버 제거에 앞서 중요 파일을 다른 물리 저장장치에 먼저 복사해 두세요.

자주 묻는 질문

  • SSD·NVMe를 바로 교체해야 하나요? 이 문제(0x0000007A)만으로 저장장치 고장을 단정하기는 어렵습니다. 슬롯 재장착과 펌웨어 업데이트를 먼저 확인한 뒤에도 반복되면 다른 슬롯이나 드라이브로 교차 테스트해보는 것이 안전합니다.
  • BIOS 설정도 영향을 주나요? 네, SATA 모드(AHCI/RAID)나 고속 부팅 설정이 인식 지연에 영향을 줄 수 있어 BIOS 설정을 함께 확인해야 합니다.
  • 재부팅해도 반복되면 데이터 복구는 가능한가요? 파일 시스템이 살아있다면 다른 PC에 연결해 데이터를 먼저 백업하세요. 디스크 자체가 인식조차 안 된다면 전문 복구업체 상담을 고려하세요.
