에러 코드 상세

0x00000154 · UNEXPECTED_STORE_EXCEPTION

커널 메모리 저장소 구성 요소가 예기치 않은 예외를 감지했을 때 나타나는 코드로, 저장장치 펌웨어나 컨트롤러 드라이버 문제와 관련이 깊습니다.

이 코드를 어떻게 해석해야 하나요?

부품 고장을 코드 하나로 단정 짓기보다는, 발생 시점과 최근 변경 사항, 반복 조건, 안전 모드 재현 여부를 함께 기록해 원인 범위를 좁혀가는 것이 정확합니다.

먼저 기록할 내용: 0x00000154가 발생한 시각, 직전에 실행한 작업, 최근 설치한 드라이버·업데이트, 재부팅 뒤 같은 코드가 반복되는지를 적어 두세요.

이 코드가 가리키는 것

이름의 store는 Windows가 메모리 압축과 페이지 관리에 사용하는 저장소 구성 요소를 뜻합니다. 디스크에서 읽은 데이터가 기대와 다르거나 메모리 내용이 어긋날 때 발생할 수 있어, 저장장치와 메모리를 모두 확인 대상으로 두는 것이 안전합니다.

첫 점검 항목

  1. 저장장치 상태(SMART) 확인 — CrystalDiskInfo 등으로 SSD·HDD의 건강 상태를 봅니다. 재할당된 섹터나 대기 중 섹터 수치가 올라가 있으면 저장장치 교체를 먼저 검토해야 합니다.
  2. 디스크 오류 검사 — 관리자 명령 프롬프트에서 chkdsk C: /f를 실행합니다. 재부팅 후 검사가 진행되며, 시간이 오래 걸릴 수 있으니 여유가 있을 때 실행하세요. 검사 전 중요한 파일은 다른 저장장치에 백업해 둡니다.
  3. SSD 펌웨어 업데이트 확인 — 제조사 전용 도구(삼성 매지션, WD 대시보드 등)로 펌웨어 최신 여부를 확인합니다. 특정 펌웨어의 결함이 이 코드로 이어진 사례가 있습니다.
  4. 메모리 진단 실행 — 저장장치에 이상이 없으면 mdsched.exe나 MemTest86으로 메모리를 검사합니다. 메모리 압축 과정에서 발생하는 경우도 있기 때문입니다.

확인 결과에 따른 다음 단계

  • SMART 경고가 발견될 때 — 데이터 백업을 최우선으로 하고 저장장치 교체를 검토하세요.
  • chkdsk로 해결될 때 — 재발 여부만 지켜보면 됩니다.
  • 펌웨어 업데이트로도 해결되지 않을 때 — 메모리 진단으로 넘어가세요.

데이터와 시스템을 보호하는 주의사항

정확한 원인을 파악하기 전에 초기화나 레지스트리 수정, 시스템 파일 수동 교체부터 시도하지 않는 것이 좋습니다.

앞 단계로 해결되지 않을 때

코드가 매번 동일하게 반복된다면 이벤트 로그와 장치 상태를 기록해두고, 코드가 바뀐다면 메모리·전원·온도처럼 시스템 전체의 안정성을 먼저 살펴보세요.

시스템 복구나 초기화, 드라이버 삭제처럼 원상복구가 힘든 작업을 시작하기 전에, 중요한 파일은 미리 외장 저장장치나 별도 위치에 백업해 두세요.

자주 묻는 질문

  • 블루스크린 코드가 한 번 떴는데 계속 지켜봐야 하나요? 이 문제(0x00000154)가 한 번만 발생했다면 즉시 부품을 교체하기보다 재현 여부와 최근 변경 사항을 먼저 기록해두는 것으로 충분합니다. 반복된다면 그때 하드웨어 점검 범위를 넓히세요.
  • 덤프 파일은 어디서 확인하나요? C:\Windows\Minidump 폴더에 저장되며, BlueScreenView 같은 도구로 열어 정지 코드와 관련 드라이버를 확인할 수 있습니다.
  • 메모리 압축 기능을 꺼야 하나요? 메모리 압축은 Windows 기본 기능이라 끄기 어려우니, 저장장치와 메모리 점검을 모두 마친 뒤 재현 여부를 지켜보는 것이 좋습니다.
