    저장공간

    NAS 파일을 삭제해도 용량이 안 줄어듦 원인과 점검 순서

    파일을 삭제하고 휴지통까지 비웠는데도 사용 중인 저장 공간이 줄어들지 않는 경우

    파일을 삭제하고 휴지통도 비웠는데 저장 공간 사용량이 그대로라면, 대부분 '스냅샷'이 원인입니다. 스냅샷은 특정 시점의 데이터 상태를 통째로 보관하는 기능이라, 스냅샷을 찍은 이후에 삭제한 파일이라도 스냅샷 안에는 그대로 남아있어 실제 디스크 공간을 계속 차지합니다.

    탐색기(파일 마우스 우클릭 삭제)에서 지운 것과 공유 폴더 자체의 네트워크 휴지통을 비우는 것은 별개인 경우도 있어, 이 둘을 구분해서 확인해야 합니다.

    이 가이드가 필요한 상황

    • 파일을 삭제하고 휴지통도 비웠는데 저장 공간 사용량이 줄지 않는다.
    • 스토리지 관리자의 사용량이 실제 남아있는 파일보다 훨씬 크게 표시된다.
    • Synology Drive를 쓰는데 오래된 파일 버전이 계속 쌓인다.

    먼저 확인할 항목

    1. 스냅샷 확인·정리 — DSM → 제어판 → 스냅샷 복제(또는 Snapshot Replication 패키지)에서 해당 공유 폴더에 걸린 스냅샷 목록을 확인하고, 필요 없는 오래된 스냅샷을 삭제하세요.
    2. 네트워크 휴지통 비우기 — DSM의 File Station에서 해당 공유 폴더로 이동해 숨김 폴더 #recycle을 확인하고 내용을 완전히 비우세요.
    3. Synology Drive 버전 관리 확인 — Synology Drive Admin Console에서 팀 폴더별 버전 관리 설정과 보관 기간을 확인하고, 필요 없다면 보관 기간을 줄이거나 기능을 끄세요.
    4. 용량 재계산 대기 — 대용량을 정리했다면 몇 시간 정도 기다린 뒤 스토리지 관리자에서 사용량을 다시 확인하세요.

    원인을 더 정확히 나누는 방법

    스냅샷을 지워도 되나요

    스냅샷은 실수로 삭제한 파일을 복구하는 안전장치이기도 합니다. 무작정 전부 지우기보다, 보관 정책(예: 최근 7일치만 유지)을 설정해 오래된 스냅샷만 자동으로 정리되도록 하는 것이 안전합니다.

    Synology Drive 휴지통은 계정별로 따로 있습니다

    Synology Drive를 여러 계정이 함께 쓰는 경우, 각 계정의 개인 휴지통은 따로 관리됩니다. 관리자 계정에서만 비웠다면 다른 계정의 휴지통에 파일이 남아있을 수 있습니다.

    확인 결과에 따른 다음 단계

    • 스냅샷 삭제로 용량이 회수될 때 — 스냅샷이 원인이었던 것이 확인된 것입니다. 앞으로는 보관 기간을 정책으로 설정해 스냅샷이 무한정 쌓이지 않도록 관리하세요.
    • 스냅샷도 없는데 용량이 그대로일 때 — Synology Drive 버전 관리나 다른 계정의 개인 휴지통을 확인하세요. 그래도 원인을 못 찾으면 스토리지 관리자에서 폴더별 사용량 분석 기능으로 실제로 용량을 차지하는 위치를 찾아보세요.

    자주 묻는 질문

    • 스냅샷이 뭔지 몰랐는데 어떻게 확인하나요? DSM → 제어판 → 스냅샷 복제(또는 패키지 센터에서 Snapshot Replication 설치 후)에서 공유 폴더별로 찍힌 스냅샷 목록을 볼 수 있습니다. 자동으로 주기적으로 찍히도록 설정돼 있는 경우가 많으니 먼저 확인해보세요.
    • 스냅샷을 다 지우면 데이터가 위험해지나요? 스냅샷은 백업이 아니라 같은 볼륨 내 복구용 스냅이라, 디스크 자체가 고장 나면 스냅샷도 함께 사라집니다. 중요한 데이터는 스냅샷과 별개로 외부 백업(다른 NAS, 클라우드 등)을 권장합니다.
