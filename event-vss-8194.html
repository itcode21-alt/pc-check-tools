EVENT ID 8194

VSS 이벤트 8194 IVssWriterCallback 액세스 거부 점검

VSS(볼륨 섀도 복사본 서비스)가 System Writer 같은 구성 요소를 조회하다 '액세스 거부(0x80070005)'로 실패했다는 기록입니다. 백업은 정상 완료되는데 이 기록만 남는 경우도 보고됩니다.

8194는 VSS가 writer가 제공하는 콜백 인터페이스를 조회하다 액세스 거부로 실패했다는 기록입니다. 대개 서비스 계정에 COM 접근 권한이 부족한 상황이며, 백업이 실제로 실패했는지와는 따로 확인해야 합니다.

여러 백업 제조사 문서에서 이 기록은 백업이 정상 완료되는 환경에서도 남는 것으로 보고되지만, 모든 환경에서 무해하다고 단정할 수는 없습니다. 백업 결과가 실패로 나오거나 vssadmin list writers에 오류 상태가 보일 때 권한 점검으로 넘어가세요.

발생 조건

  • 백업·복원 프로그램을 실행할 때마다 함께 남음
  • vssadmin list writers 실행 시 오류
  • VSS 8193 기록이 함께 남음

가능성 높은 원인

  • VSS가 요청한 COM 구성 요소에 서비스 계정(Network Service 등)의 접근 권한이 없음
  • 보안 소프트웨어나 정책이 서비스 권한을 제한
  • 클러스터 환경의 서비스 권한 구성

점검 순서

  1. 이벤트 본문의 오류 코드(0x80070005 등)와 호출 구성 요소 기록 — 되돌리기 쉬운 항목부터 확인해 위험 없이 범위를 줄입니다.
  2. 관리자 권한 명령 프롬프트에서 vssadmin list writers로 오류 상태의 writer가 있는지 확인 — 첫 확인 결과와 비교해 원인 후보를 좁힙니다.
  3. 백업 작업이 실제로 성공했는지 확인 — 이 단계에서도 재현되면 다음 항목으로 넘어가세요.
  4. 같은 시각의 VSS 8193과 비교 — 변경 전후로 증상이 달라지는지 비교해보세요.
  5. 백업 소프트웨어 제조사와 Microsoft 안내를 확인한 뒤에만 COM 권한을 변경 — 여기까지 확인해도 해결되지 않으면 다음 원인을 검토하세요.
주의사항

DCOM·COM 보안 권한은 한 번 바꾸면 되돌리기 어렵습니다. 백업이 정상 완료되고 있다면 기록만 보고 권한을 바꾸지 마세요.

권한을 바꾸기 전에 복원 지점을 만들어 두세요.

자주 묻는 질문

  • 8194가 뜨는데 백업은 성공해요. 무시해도 되나요? 백업이 정상 완료되고 다른 오류가 없다면 관찰 대상으로 두는 경우가 많습니다. 다만 백업 실패나 writer 오류 상태가 함께 있다면 원인을 확인하세요.
  • DCOM 권한을 바꾸면 해결되나요? 권한 부족이 원인인 환경에서는 효과가 있을 수 있지만, 한 번 바꾸면 되돌리기 어렵습니다. 제조사·Microsoft 안내와 복원 지점을 확보한 뒤에만 진행하세요.

공식 출처

  • Microsoft 지원: 백업 또는 vssadmin list 실행 시 '액세스 거부' 오류(KB2991246, 클러스터 환경 핫픽스)
